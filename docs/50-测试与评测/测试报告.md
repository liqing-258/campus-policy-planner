## 2.5 一个容易误读的口径：评测集跑在**2 份文件**上，不是演示库的 18 份

`tools/run_eval.py` 自己建临时库，只导入：

```python
DEMO_FILES = ["01-本科生奖学金评审办法（2026年版）.pdf", "02-学生事务办理指南.docx"]
```

所以评测集里的"应拒答（库内无）"是**相对于这 2 份**说的。典型例子 B-03
「图书馆的开馆时间是几点？」——在评测库里确实没有图书馆文件，应当拒答；
但**在演示库（18 份）里这是可答的**（《图书馆借阅与自习空间管理办法》第一章写着 8:00–22:00）。

这不是矛盾，是两套语料各自的正确答案。R5 收尾时我就误读了一次：拿演示库直调 B-03，
看到 `code=0` 以为门禁坏了；核对 `DEMO_FILES` 才发现两边语料不同。

> 之所以不去掉这个差异：评测集要的是"同一批题的稳定基线"，语料越小越稳定；
> 而"每份文件都能被问出来"是另一支门禁（`tools/kb_probe.py`，18 份），
> 两者分工在链 R §R.5.3b 里写过。

```bash
# 全量（Windows 本机约 322 秒，323 项）
.venv\Scripts\python.exe -m pytest

# 只跑 R9 新增（验证码 / 注册 / 看板）
.venv\Scripts\python.exe -m pytest tests/test_register_analytics.py

.venv\Scripts\python.exe -m pytest tests/test_workflows.py tests/test_injection.py ^
    tests/test_versions.py tests/test_feedback.py tests/test_stats.py tests/test_history.py

# R9 页面验收（需先起服务：.venv\Scripts\python.exe server.py --no-browser）
.venv\Scripts\python.exe .build\check_r9.py

# 接口数核对（必须与文档一致）
.venv\Scripts\python.exe tools\dump_routes.py

# 评测集
.venv\Scripts\python.exe tools\run_eval.py
```

> **一个环境坑**：本机 `pytest` 会话结束时清理 `%TEMP%` 里的旧临时目录，会被安全钩子拦截
> （>50 文件触发批量删除确认），表现为**汇总行消失、退出码 1**。
> 用 `--basetemp` 指定目录能绕开，但**必须每次换一个新目录**——
> 复用一个已存在的 basetemp 会让 pytest 在启动时先删它，同样被拦截，导致所有 fixture setup 报错。
