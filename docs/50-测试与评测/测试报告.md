## 4. M6 新增 77 项：每一项在解决什么

### 4.1 `test_workflows.py`（14 项）— 节点轨迹

| 用例 | 断言的行为 |
| --- | --- |
| `test_successful_ask_records_four_executed_nodes` | 一次问答只执行 `intent/retrieval/analysis/validation` 四节点 |
| `test_only_analysis_node_calls_the_model` | 四个节点里只有 analysis 调模型（`model_calls=1`，其余 0） |
| `test_intent_node_output_drives_next_actions` | 意图节点判 `needs_profile` 时才给"去匹配/去规划"两个动作 |
| `test_flow_question_gets_no_match_suggestion` | 纯流程类问题不硬凑推荐位 |
| `test_refusal_still_records_run` | 拒答也落轨迹（`status=succeeded` + `outcome=refused`） |
| `test_model_says_insufficient_records_validation_node` | 模型自述不足时，问题记在 validation 而不是"validation 崩了" |
| `test_degraded_run_marks_analysis_skipped` | 降级时 analysis 记 `skipped` 而非 `failed` |
| `test_invalid_model_output_records_failed_run` | 4002 也留一条 `failed` 轨迹 |
| `test_run_can_be_fetched_by_owner` / `test_other_users_run_is_forbidden` / `test_missing_run_returns_404_with_its_own_code` | 轨迹可查、越权 403、缺失 2009 |
| `test_message_carries_the_run_id` | 消息与轨迹能互查 |
| `test_recorder_marks_failed_node_and_reraises` | 节点异常记 failed **并**继续抛出（不吞异常） |
| `test_finish_is_idempotent` | 降级路径两次 `finish()` 不产生两条运行记录 |

### 4.2 `test_injection.py`（14 项）— 注入防护

8 种攻击形态参数化命中（`test_scan_covers_multiple_attack_shapes`）；
3 条正常政策文本**不误报**（`test_scan_does_not_flag_normal_policy_text`——
"逾期视为放弃，不再另行通知"这类句子必须沉默，否则告警失去意义）；
降权恒为 0.5；高相关注入片段**保留并标记**、低相关被阈值拦下；
`test_injection_cannot_forge_citations` 用 99 号引用证明"注入无法让模型编出出处"。

### 4.3 `test_versions.py`（14 项）— 版本冲突

规范化三年例（去括号/去年份/去版本词）、不同主题不合并、`year_of` 三种来源、
两版并列 + 365 天差 + "现行有效"标注、四种静默条件（不同主题/单文档/短标题/同年同日）、
双 active 时明说"标注本身存在冲突"、`test_ask_surfaces_both_versions` 验证问答链路真的带 `conflicts`。

### 4.4 `test_feedback.py`（9 项）— 答案反馈

创建、**覆盖不新增**（同一人重复评价只有一行）、缺 `reason_code` → 1001、
非法原因码拒绝、不能评提问本身（1003）、不能评他人（3002）、缺失 2009、
未登录 3001、消息列表回带反馈。

### 4.5 `test_stats.py`（8 项）— 任务统计

空账号返回完整形状（五态补 0，不留 `undefined`）、五态四优先级计数、
逾期排除 done/cancelled、**完成率排除 cancelled**（作废两条后完成率 60%→75%，
不排除会导致"努力做事反而变好"的荒谬读数）、计划分组、用户隔离、状态变更后立即反映。

### 4.6 `test_history.py`（6 项）— 多轮上下文

首轮无历史块、次轮带上一问、**Prompt 明写历史不可引用**、`use_history=false` 可关
（评测集不受污染）、长答案 240 字截断、会话隔离。

### 4.7 既有文件追加（11 项）

## 5. 红→绿证据（四次真实的红）

测试报告最容易写成"全绿"两个字，那样等于什么都没说。下面是三次**真实失败**的过程。

### 5.1 T-11：从"只有评测集证据"到"可断言"

M5 结项时 T-11 的证据只有评测集 F 类 4 条全拒答——那证明的是"注入样本被拒答"，
不是"注入被识别"。M6 先写 `test_injection.py`，首跑 **8 项红**（`app/injection.py` 还不存在），
实现三层后转绿。

期间修掉一条自己写的假断言：

```python
assert "injection" in c or True     # 恒真，等于没断言
```

改成真的去 `/retrieval/search` 的候选里找 `injection.patterns` 含 `override_instructions`。

### 5.2 T-12：从"根本没做"到"能断言 + 能复现"

`test_versions.py` 首跑 14 项红。实现 `app/versions.py` 后转绿，但**绿了仍然不算完**：
演示库里 4 份文件的 `academic_year`/`published_at`/`effective_status` 全是 NULL，
这种数据上"检测通过"证明不了界面能看到任何东西。

于是补了两件事：前端上传/编辑入口（`PATCH /documents/{id}`）、演示库补一份 2025 年版。
随后在真实演示库上验证：

```
=== 奖学金申请截止时间是什么时候
召回 6 条 · 冲突 1 组
  [1] （演示样例）01-本科生奖学金评审办法（演示样例）.pdf   cov=0.8571
  [2] 01-本科生奖学金评审办法（2025年版）                  cov=0.8571
  --- 冲突 topic=01本科生奖学金评审办法 · 相差 365 天
    · 2026 active     （演示样例）01-本科生奖学金评审办法（演示样例）.pdf
    · 2025 superseded 01-本科生奖学金评审办法（2025年版）
```

> 上面这段是 **M6 当时**在真实库上的输出：文件名还带「（演示样例）」与 `01-` 编号。
> R1 重建知识库后，同一组文件叫 `本科生奖学金评审办法（2026年版）` 与 `（2025年版）`，
> 冲突检测的结论（1 组冲突、相差 365 天、2026 现行 / 2025 已被取代）没有变。
> **保留旧输出而不是改写成新名字**：这是当时真实跑出来的证据，改写就等于伪造。

### 5.3 T-24：扫描测试抓到了写文档的人

写 `安全自查.md` 时，在"怎么查全历史"的命令示例里写了**完整**密钥。
`test_security_scan.py` 当场判红：

```
AssertionError: 疑似密钥入库：
  OpenAI/兼容 key @ docs\50-测试与评测\安全自查.md: sk-3c1061c34…
```

改成只写前 9 位后转绿。这条留在报告里，因为它说明**这道闸门对自己人也生效**——
比任何"密钥管理规范"都有说服力。

### 5.4 B-10：补全写了、代码跑了、一条都没补进来

R2 补做时给 `_complete_neighbours` 写的第一版是这样的：先把"所有过了覆盖率闸的候选"
放进排除表，再去取邻片。结果打印出来：

```
refused False  n 6  neighbours 0
```

`neighbours 0` 是那句最容易被忽略的红——**接口没报错、回答也没变差，只是新功能完全没生效**。
原因是要补的邻片本来就在"过了闸的候选"里（它覆盖率够、只是排第 11 没抢到前六），
被自己的排除表全挡掉了。改成只排除"已经进了证据窗口的 6 条"后：

```
refused False  n 8  neighbours 2
```

六条用例把这两种状态都钉住了：`test_top_window_really_misses_the_fee_chapter` 先证明
"窗口确实漏了"，`test_completion_brings_back_the_gated_neighbour` 再证明"补得回来"。
如果只写后者，将来排序一变、窗口本来就包含该章，用例会**假绿**。

## 7. 复现方式

```bash
# 全量（Windows 本机约 145 秒，262 项）
.venv\Scripts\python.exe -m pytest

# 只跑 M6 新增
.venv\Scripts\python.exe -m pytest tests/test_workflows.py tests/test_injection.py ^
    tests/test_versions.py tests/test_feedback.py tests/test_stats.py tests/test_history.py

# 接口数核对（必须与文档一致）
.venv\Scripts\python.exe tools\dump_routes.py

# 评测集
.venv\Scripts\python.exe tools\run_eval.py
```

> **一个环境坑**：本机 `pytest` 会话结束时清理 `%TEMP%` 里的旧临时目录，会被安全钩子拦截
> （>50 文件触发批量删除确认），表现为**汇总行消失、退出码 1**。
> 用 `--basetemp` 指定目录能绕开，但**必须每次换一个新目录**——
> 复用一个已存在的 basetemp 会让 pytest 在启动时先删它，同样被拦截，导致所有 fixture setup 报错。
