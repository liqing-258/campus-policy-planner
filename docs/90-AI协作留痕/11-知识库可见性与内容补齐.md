## O.3 AI 输出摘要（做了什么，以及为什么这么做）

### O.3.1 ① 先证明"接口有 18 条、页面是 0 条"

没有先改代码，先取证。带学生令牌请求列表接口：

```
GET /api/v1/documents?page=1&page_size=50
→ code 0, total 18, items 18
```

再看数据库：`documents` 20 行（其中 2 行是上一版留下的异常样本，`deleted_at` 非空），
`document_chunks` 74 行，`policy_rules` 20 行（10 条 `approved`）。
每份文件的 `parse_status` 都是 `indexed`，没有一份是 `empty`。

也就是说：**库是好的、接口是好的、索引是好的，只有页面是空的。**

### O.3.2 ② 根因：`onMounted` 只挂了深链处理，没挂列表加载

`frontend/src/views/LibraryView.vue` 的挂载行是：

```ts
onMounted(openFromQuery)
```

而 `openFromQuery` 的第一行是：

```ts
const target = String(route.query.doc ?? '')
if (!target) return
```

`?doc=` 是"从问答页点引用跳到知识库、自动展开某个文件"的深链参数。
正常进入 `/library` 时它不存在，函数立刻 `return`——
**`loadDocs()` 从头到尾没有被调用过一次**，于是 `docs=[]`、`total=0`，
模板渲染出"文件（0）"和"暂无文件"。

修法是让挂载动作**与深链解耦**，且不要重复请求：

```ts
onMounted(async () => {
  const target = String(route.query.doc ?? '')
  if (target) {
    await openFromQuery()   // 深链分支内部会调 loadDocs
    return
  }
  await loadDocs()
})
```

为什么不写成 `onMounted(() => { openFromQuery(); loadDocs() })`：
深链分支自己会调 `loadDocs`，那样会连发两次列表请求，
第二次还会把 `page` 重置，滚动定位就失效了。

### O.3.3 ③ "显示 0"和"内容薄"是两件事，修法也必须分开

- **显示 0**：一行前端代码的事，改完立刻可见；
- **内容薄**：18 份文件中，15 份在 `tools/make_demo_docs.py` 的 `POLICIES` 里，
  每份 2–3 页、约 500 字、4 个片段；`02-学生事务办理指南.docx` 是另一套
  `GUIDE_SECTIONS` 结构，6 个片段。

500 字是什么概念：一份《图书馆借阅与自习空间管理办法》只有"开放时间、借阅册数、
逾期费、座位预约、违规处理"五条。能回答"本科生能借几本"，但回答不了
"逾期费怎么算""校外怎么用数据库""毕业前要办什么"。

### O.3.4 ④ 扩写策略：追加章节，不动旧条款

改法不是重写,而是**在每份文件末尾追加 2–3 章**,原因有三条,都是硬约束:

1. **评测基线**：`eval/qa_set.jsonl` 的 24 条标准答案引用的是现有条款原文。
   就地改字，评测会从"答错"变成"标准答案本身就错了"，基线不可比。
2. **版本对照**：《奖学金评审办法》2025/2026 两版的差异是**五处实质条款**
   （绩点 3.0→2.8、排名 30%→35%、公示 3→5 天、截止 9/10→9/12、申请书 800→600 字），
   这是版本冲突演示的命门。这两份**一个字都没动**。
3. **可审阅**：追加内容集中在一张 `EXTRA_PAGES` 表里，
   评审想看"这次到底补了什么"，查这一张表即可，不用逐份 diff。

追加的章节按各文件原有条号往下排（学籍到第二十三条、处分到第十八条），
内容统一覆盖五类"用户真会问的东西"：

| 追加主题 | 例子 |
|---|---|
| 办理流程与时间节点 | 交换生 3 月/9 月批次、申请截止为发布后 10 个工作日 |
| 材料清单 | 推免要成绩单+六级+获奖证书+科研成果证明 |
| 费用与标准 | 住宿费四人间 1200/学年、水 3.5 元/吨、电 0.55 元/度 |
| 算例 | 逾期费 3 册×10 天×0.1 元 = 3 元；加权绩点 = 3.18 |
| 常见问题与咨询渠道 | 校园卡消磁免费换、网络报修 24 小时、分机号 |

### O.3.5 ⑤ 顺手修掉的三处同类隐患

都不是用户点名的问题，但都属于"会静默产生错误结果"的一类，碰到了就必须修：

1. **PDF 折行溢出**：生成器按"每 38 字折一行"手算 y 坐标，
   章节一多就会把行写到页面之外——**不报错，只是正文少一截**。
   这次加了硬断言：`y > 790` 直接 `SystemExit` 并指名哪一页该拆。
   （本次 18 份全部通过，未触发。）
2. **评测脚本写死旧文件名**：`tools/run_eval.py` 的 `DEMO_FILES` 还指着
   `01-本科生奖学金评审办法（演示样例）.pdf`——上一轮去掉"（演示样例）"时漏改的。
   跑评测直接 `FileNotFoundError`。除了改名，还让它报错时**列出 `demo/` 真实文件**。
3. **巡检没有"列表非空"这条断言**：见 O.4.2，这是本次最重要的教训。

## O.4 人工干预记录（六个现场）

### O.4.1 【空列表】接口 18 条，页面 0 条

**现象**：图 1。

**定位顺序**（每一步都在缩小范围，而不是猜）：
先 `curl /health` → 18/74 正常；再带令牌 `curl /documents` → total 18；
再查 SQLite → 20 行里 18 行有效；最后才读 `LibraryView.vue` 的 `onMounted`。

**关键判断**：页面左下角那句"服务正常 · 政策 18 份"是 `/health` 的结果。
它和表格里的"文件（0）"同时出现在一屏里，等于系统自己承认了矛盾。
**先信这句，就不用去怀疑数据库。**

### O.4.2 【测法】224 项测试 + 7 页巡检，为什么一个都没抓到

这是本次最该记下来的一条。

`tools/browser_check.py` 对每一页断言四件事：
不该出现的字样、`innerText` 长度 ≥ 200、无横向溢出、无 JS 报错。
知识库页"文件（0）"这一屏：

- 没有建设期字样 ✅
- 正文 839 字（含表头、说明、空态文案）✅ 远超 200
- 无溢出 ✅
- 无 JS 报错 ✅（`openFromQuery` 正常返回，没有异常）

**四条全过。** 因为"空表格"在结构上是一个完全正常的页面，
它只是没有数据——而原来的断言里**没有一条在数量上较真**。

后端的 224 项测试也测不到：它们打的是 `/api/v1/documents`，
那条路一直是好的。缺的是"页面挂载后会去拉数据"这个行为。

**改法**：给 `/library` 加一条专用断言，直接数行：

```python
if path == "/library":
    rows = c.eval("document.querySelectorAll('.table tbody tr').length")
    heading = c.eval("(document.querySelector('.list-head h3')||{}).textContent || ''")
    if not rows:
        failures.append(f"{label}：文件列表 0 行（标题「{heading}」）")
    elif rows < 5:
        failures.append(f"{label}：文件列表只有 {rows} 行，像是没加载完")
    else:
        notes.append(f"知识库列表 {rows} 行 / 标题「{heading.strip()}」")
```

修完的实测输出（真实运行）：

```
[巡检] 政策知识库  ok · 文字   839 · 卡片  1 · 溢出 0 · 底/卡/字 0.07/0.11/0.91
[巡检] 备注
   - 知识库列表 10 行 / 标题「文件（18）」
[巡检] 全部通过
```

> 教训：**"页面有内容"不等于"页面有数据"。**
> 断言要落在用户真正关心的量上——这里是"列了几行"，
> 不是"这一屏有多少个字"。

### O.4.3 【溢出】手算折行，超页不报错

`_make_pdf` 用固定行高往下写，从不检查是否写出页面。
本次每份文件从 2–3 页加到 4–6 页，正好是最容易踩这个坑的时候。

加断言后第一次运行就通过了，但这不代表原来没问题——
它代表**这次**没踩到。断言留着，是为了下次加章节时立刻失败，
而不是等用户在界面上发现"第十七条怎么没了"。

### O.4.4 【旧文件名】评测脚本还指着"（演示样例）"

```
FileNotFoundError: demo\01-本科生奖学金评审办法（演示样例）.pdf
```

上一轮批量去掉"（演示样例）"时，`tools/` 下的引用扫过一遍，
但 `run_eval.py` 的 `DEMO_FILES` 藏在文件头部常量里，漏了。

这类问题的共同点：**改名是一次性的，引用是分散的**。
所以这次除了改对名字，还让脚本在文件不存在时打印 `demo/` 的真实清单：

```python
available = sorted(p.name for p in (ROOT / "demo").iterdir() if p.is_file())
raise SystemExit(f"评测要用的示例文件不存在：{name}\ndemo/ 现有：{available}")
```

### O.4.5 【检索】扩写把一条本来答得上的问题挤出了前六

这是本轮唯一一次"改好反而变差"的现场，必须记。

**现象**：扩写前问"图书逾期费怎么算"，能答；扩写后问同一句，仍能答。
但问"图书馆的书逾期了怎么收费"（上一轮记入已知限制 B-10 的原句），
**依旧拒答**。查下来原因变了：

- 扩写前：《图书馆》只有 4 个片段，"第二章 借阅规则"（含逾期费条款）排得进前六；
- 扩写后：7 个片段，新增的"电子资源""座位管理""常见问题"三章都提到`图书馆`,
  BM25 里"图书馆"是高频词，命中它多的片段分数高。
  含逾期费的"第二章"只提到"借阅图书"，覆盖率 0.4；
  其他片段覆盖率 0.6 甚至 0.8。排序规则是**先覆盖率、再分数**，
  于是第二章掉到第 11 位，前六里没有它，模型看到六段都不讲钱，就拒答了。

**处理**：没有为了这一句去改排序或阈值。理由是：
`eval/qa_set.jsonl` 的 D 类（近义干扰）专门在压这一类改动，
而 B-10 本来就是"保守拒答"的已知限制，改排序的回归面远大于收益。
改为**如实缩小限制范围**：问"逾期费怎么算"能答（见 O.5.4），
只有把"逾期费"说成"收费"这种口语化动词时才会漏。

**判断依据（实测）**：

```
问：图书逾期费怎么算
答：逾期费按每册每天 0.1 元计算，单册逾期费上限为 20 元 [2][1]。
    计算方式为：逾期册数 × 逾期天数 × 每天 0.1 元。
    例如借阅 3 册、逾期 10 天，逾期费为 3 × 10 × 0.1 = 3 元 [1]。
    单册逾期费上限为 20 元，即单册逾期超过 200 天的按 20 元计收 [1]。

问：图书馆的书逾期了怎么收费      → code 4001（模型判定证据不足）
```

同一份文件、同一段条文，换个说法一答一拒。
这不是知识库缺内容，是**检索的召回口径**问题，属于已知限制的新边界。

### O.4.6 【数据】18 份里哪几份必须"原地更新"

`tools/refresh_demo_library.py` 的分支逻辑是：
**有已复核规则的文件只洗文本、不重解析**，没有规则的才删了重建。
规则通过 `chunk_id` 外键绑在片段上，重解析会换 id，规则不是失效而是指向空行。

本次的实际分布：

```
[reb] 本科生奖学金评审办法（2025年版） → 4 片段
[upd] 本科生奖学金评审办法（2026年版）（保留 10 条规则，清洗 0 个片段）
[reb] 学籍管理规定 → 9 片段
...
```

2026 版走的是"原地更新"分支，而它的文件内容本次**一个字都没改**，
所以"清洗 0 个片段"是正确结果，不是漏做。
如果哪天它真的清洗了片段，说明文件被动过，需要回头核对 10 条规则的引文是否还成立。

### O.5.4 真实问答（四条，全部引用到新增章节）

## O.8 结论

这次的两个问题，一个在**渲染层**，一个在**语料层**，唯一的共同点是
都被"看起来正常的输出"盖住了：

- 页面返回 200、字数 839、无报错、无溢出——**四条巡检断言全绿，但表格是空的**；
- 文件都在库里、状态都 `indexed`、接口 total=18——**数据全对，但每份只有半页纸**。

所以这一轮真正沉淀下来的不是那行 `onMounted`，而是两条判据：

1. **断言要落在数量上**。"有内容"必须量成"有几行"，
   否则空态页面能骗过所有基于长度与溢出的检查。
2. **语料的"够用"要用提问来验**。18 份文件、74 个片段听起来不少，
   但四个真实问题（逾期费、推免权重、四六级缺考、处分解除）
   在扩写前一个都答不出来——**片段数不是指标，答得出才是**。

扩写后，这四个问题都能答，并且答案里带着可以点开核对原文的引用编号。
这才是"政策知识库"该有的样子：不是把文件堆进去，而是让每一条规定
都能被一句人话问出来、被一段原文答回去。
