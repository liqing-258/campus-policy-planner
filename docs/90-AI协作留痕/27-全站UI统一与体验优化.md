# 链 AE · 全站 UI 统一与体验优化（R18）

> 功能轮 R18（2026-11-15）。对「知校」做一轮纯前端的 UI/UX 优化：工作台快捷操作区、
> 匹配页画像分组、知识库概览统计、问答工作流步骤条，及全站交互体验核对。

## AE.1 目标

| 表面上看 | 实际牵连 |
| --- | --- |
| 统一全站视觉规范 | 现有 R10/R11 已建好浅底青碧 design tokens + 对比度验算，色值已在需求方向上 |
| 工作台加快捷操作区 | 现状有欢迎 + 统计 + 日程 + 更新 + 推荐 + 六列表，缺"从哪开始"的入口 |
| 匹配页画像分组 | 九字段平铺一格，需求要按"学籍/学业/排名/其他"归类 |
| 知识库顶部概览 | 现状只有表格，缺"文件/解析/片段/待处理"四个总览数 |
| 问答工作流步骤条 | 现状是 details 折叠，展开才见节点，需求要"一眼看全" |

## AE.2 用户 Prompt 与理解

用户原话（R18 完整需求，十三节 + 十二条约束 + 收尾）。我的理解落在三条硬线：

1. **"不要为了追求视觉效果而随意更换技术栈或重新设计整个前端工程"** + **"优先复用现有组件"**
   —— 现状的 design tokens、卡片、按钮、标签、空态已经齐备，本轮**不换色、不重构**，
   只补"布局与信息组织"的缺口。
2. **"颜色不能成为唯一的状态识别方式，还应搭配文字标签或图标"** —— 现状的状态标签
   （`.tag.met/unknown/not_met`）本来就是"色 + 文字"双通道，已满足；本轮不改。
3. **"不得删除现有功能和用户已经能够使用的操作"** + **"不得使用静态假数据"** —— 知识库
   概览四个数、匹配进度、工作台入口，全部来自真实接口，前端不自造数字。

## AE.3 方案取舍

| 取舍点 | 选了什么 | 为什么 |
| --- | --- | --- |
| 色彩规范 | **保留现有色值，不改** | 现有 `#0a7d6f`/`#f4f8f7`/`#fff`/`#dbe7e3` 已在需求方向（≈ #087E73/#EAF5F2/#fff/#DDEBE7），且经过 R10/R11 对比度实算；换色要重跑 21 项验算，风险远大于收益（约束 10 优先保留已有可靠实现） |
| 工作台快捷操作区 | 四个带图标卡片（复用导航图标字符） | 需求点名"醒目的快捷入口"，且不与既有统计/列表重复 |
| 匹配画像分组 | `Field` 加 `group`，四组渲染 | 纯前端展示层改动，字段白名单与提交逻辑零变更 |
| 匹配填写进度 | 已填非空字段数 / 总数 | 前端算，不新增字段、不动画像白名单 |
| 知识库概览 | 拉一次 `/documents?page_size=100` 现算 | 四个数都来自真实接口，前端不拍脑袋；演示库 18 份远小于 100 上限 |
| 问答步骤条 | details 里加横向步骤条（圆点 + 标签） | 保留 details 展开看耗时/摘要，不删诊断能力；skipped 保持灰，不伪装成完成 |

## AE.4 现场记录（本轮踩到的）

1. **`.stat` 没有 `plain` 语义类**：概览"待处理"想用中性灰，写成 `class="plain"`，但
   styles.css 的 `.stat` 只有 accent/ok/warn/danger/info 五态（`::before` 色条默认就是灰）。
   改成不传 class，靠默认色条。
2. **画像分组的标签缩进**：把平铺 `profile-grid` 包进 `v-for="g in fieldsByGroup"` 后，
   原 `<label>` 循环结尾的 `</div>` 从"一个"变成"两个"（profile-grid 结束 + field-group
   结束），漏补会让后续 DOM 结构错位——逐段 grep 核对才抓回来。
3. **问答步骤条不能替代 details 里的摘要**：需求要"一眼看全"，但节点 `summary`（一句
   说明每个节点做了什么）只在 `title` 悬停里，展开后仍是原来的 `trace-line`。这是**加一层**
   而不是**替换一层**——删掉 details 的耗时/摘要等于删诊断能力。

## AE.7 已知不做 / 限制

- 问答回答的"核心结论/政策要求/办理流程/注意事项/依据"五段式分区**未做**：现有回答是
  模型输出的纯文本 + 引用列表，做分区要么改后端 Prompt 契约、要么前端按语义切分——
  前者要动 N-01 契约校验、后者会破坏"引用逐条可核对"（切分后 [n] 编号对不上原文）。
  这是约束 10「冲突保留已有实现」的直接落点。
- 知识库详情"独立抽屉"未做：现有"行内展开"已稳定，改成抽屉要重构列表与详情的状态管理，
  收益是视觉、风险是破坏深链定位（`?doc=` 展开 + 滚动到行）。
- 数据中心"热门政策查询排行/高频事务类型"等新业务分析未加：这些需要新接口（按文档引用
  次数、按事务类型聚合），约束 7 要求"需新接口应先说明范围"，本轮纯前端不动后端。

## AE.9 结论

这一轮最硬的一条判断是**"统一"不等于"重做"**：R10/R11 已经把浅底青碧 + design tokens +
对比度验算这套底子打好，需求里的色彩规范方向与现状一致，所以本轮**一处色值都没动**，只补
四个信息布局缺口——工作台"从哪开始"的入口、匹配页"九格归四组"、知识库"四个总览数"、
问答"处理过程一眼看全"。所有新数字都来自真实接口（概览四个数、填写进度、快捷入口），
零静态假数据、零后端改动，这正好卡在约束 4「优先复用」与约束 12「刷新可恢复」上。
