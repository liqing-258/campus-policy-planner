# Prompt 留痕模板

> 用法：每个核心功能建一份文件，按条目追加。**随做随记，不事后补写。**
> 赛事要求：至少 3 个核心功能的完整 Prompt 链，含你的提问、AI 的修改建议、你如何引导修复 Bug。

---

## 条目模板

```markdown
### YYYY-MM-DD ｜ 阶段 ｜ 一句话目标

**1. 目标**
这次要解决什么。用可验证的一句话写。

**2. 我发给 AI 的完整 Prompt**
（原文照抄，不删减、不美化。多轮对话按时间顺序排列，标注 [第1轮] [第2轮]…）

**3. AI 的关键输出摘要**
它给了什么方案/代码。只摘要点，不整段复制。

**4. 我的判断与修改**
- 采纳了什么，为什么；
- 否决了什么，为什么；
- 我手动改了哪些地方。

**5. 改动的文件**
`app/xxx.py`、`docs/xxx.md`

**6. 测试命令与真实结果**
```bash
pytest backend/tests/test_xxx.py -v
# 输出（粘贴真实结果，不通过也照实写）
```

**7. 遇到的问题与修复过程**
现象 → 定位 → 我如何引导 AI → 最终修复。

**8. 对应 commit**
`a1b2c3d feat(xxx): ...`
```

---

## 写作纪律

| 允许 | 禁止 |
| --- | --- |
| 照实记录失败与返工 | 把失败轮次删掉只留成功 |
| 摘要 AI 输出 | 编造没发生过的对话 |
| 标注"此处我改了 AI 的方案" | 把 AI 原方案说成自己写的 |
| 记录 AI 给出错误方案后我如何纠正 | 编造"AI 一次就对" |
| commit 哈希如实填 | 事后批量补写 pretend 记录 |

> 评审看的是**驾驭 AI 的过程**，不是"AI 多听话"。一次被纠正的错误方案，比十次一次成功更有说服力。
