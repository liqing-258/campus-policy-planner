## H.4 人工干预记录（AI 出错、被纠正的地方）

这一节是本项目"如何引导 AI 修复 Bug"的直接证据。**每条都是真实发生过的**，保留了错误现场。

### H.4.1 AI 自己写出了语法错误的 import 行

`app/auth.py` 第一版里出现了这样一行：

```python
from shared.codes import FORBIDDEN, ROLES if False else FORBIDDEN  # noqa: F401
```

这是无效 Python——`import` 语句里不能跟条件表达式。成因是 AI 在写 import 时"顺手"想表达"这两个常量可能重复、只取一个"，结果把意图写成了代码。发现方式是写完后立即读回文件检查。修复：删掉该行，改为只从 `shared.enums` 取 `ROLE_ADMIN, ROLES`（`FORBIDDEN` 常量在 `shared.codes` 里本就用于别处，本文件不需要）。

**教训**：AI 生成的代码"看起来对"不等于能 import。每个 `.py` 文件写完必须 `python -c "import 模块"` 或跑一次测试。

### H.4.2 异常类继承导致所有错误码都变成 1001

`app/errors.py` 第一版：

```python
class ApiError(Exception):
    code: int = INVALID_PARAM
    ...
class InvalidPagination(ApiError):
    pass          # ← 没有声明 code
```

子类不声明 `code` 时，`InvalidPagination` 会继承 `1001`，**分页参数错误会被报成"参数校验失败"**——表面能跑，语义错了。发现方式：读回文件，看到 `pass` 的那几个类，立刻意识到错误码表形同虚设。修复：每个子类显式 `code = codes.XXX`。

**如果只跑一次冒烟测试是发现不了的**——因为 HTTP 400 看起来"也没错"。这正是自动化断言（`test_invalid_pagination_is_1002`）存在的理由。

### H.4.3 Flask 的 404 处理器把契约处理器顶掉了

第一版在 `app/__init__.py` 里又注册了一次：

```python
@app.errorhandler(404)
def _not_found(exc):
    return fail(INVALID_PARAM, "接口不存在", 404)
```

Flask 按"最具体优先"选择处理器，这个更具体的 404 会覆盖 `contract.py` 里 `HTTPException` 的统一处理，导致同一个 404 在两个文件里有两套实现。修复：删掉它，只保留 contract 里一处。

**判断依据**：契约规范写的是"外壳唯一实现"，那就不允许存在第二个出口。

### H.4.4 响应键序会被 Flask 按字母排掉

这是最容易漏的：Flask 默认 `app.json.sort_keys = True`，会把外壳输出成
`{"code","data","message","request_id","timestamp"}`——**`data` 跑到了 `message` 前面**。

契约规范写死了顺序 `code → message → data → request_id → timestamp`。肉眼几乎察觉不到（JSON 对象本无序），但前端若按位置解析或做字符串快照测试就会炸。修复：

```python
app.json.ensure_ascii = False   # 中文不转义
app.json.sort_keys = False      # 保持插入顺序
```

并加断言 `list(body.keys()) == ENVELOPE_KEYS`。这条现在由 `test_envelope_key_order_and_types` 长期看护。

### H.4.5 前端 `127.0.0.1` 打不开，`localhost` 能开

现象：`curl http://127.0.0.1:5173/` 返回 000，`curl http://localhost:5173/` 返回 200。

原因：Vite 默认 `host: 'localhost'`，Windows 上 `localhost` 优先解析到 `::1`（IPv6），只绑了 IPv6。评审若照 README 输入 `127.0.0.1` 就是一片空白。

修复：`server.host = true`（同时监听 `0.0.0.0` 与 `::`）。顺带修掉第二个坑：5173 被占用时 Vite 会**静默换到 5174**，而 README 写的是 5173 —— 加 `strictPort: true` 让它直接失败而不是换端口。

**这类坑的特点是"作者本机永远不会遇到"**，因为作者用的是 `localhost`。只有按文档逐条照做才会暴露。

### H.4.6 TypeScript 相对路径写错一级

`src/router.ts` 里写 `import { getToken } from '../api/client'`，但 `router.ts` 就在 `src/` 下，应为 `./api/client`。`vue-tsc` 直接报 `TS2307: Cannot find module`。

值得记录的是：**这个错误是靠 `npm run build` 抓到的，`npm run dev` 不会报**——Vite dev 模式下模块解析更宽松，坏 import 可能直到运行时才白屏。所以 M2 就把 `build` 纳入门禁，而不是等 M6 才发现。

### H.4.7 `import fitz` 已被弃用

PyMuPDF 2.x 里 `fitz` 只是兼容别名，导入时会打 `FutureWarning: The fitz API is deprecated`。M3 的解析器统一改为 `import pymupdf`。

## H.7 反思（如果重做，会改什么）

1. **先写 `errors.py` 的测试，再写 `errors.py`**。H.4.2 这种"所有 code 变 1001"的错误，一条断言就能拦住，而我当时是先写完再回读发现的。
2. **`.env` 的补齐应该做成脚本**，而不是临时一段 Python。M3 要加 4 个新配置项，同样的活还要再干一次——现在补进 `tools/selfcheck.py` 的检查项里了。
3. **端口类问题应该在建工程第一天就用"两个地址都测"**（`127.0.0.1` 与 `localhost`）。这类问题只有复现者会遇到，作者自测发现不了。
4. **`app/config.py` 里 `Settings` 的 overrides 后置归一化**写对了，但第一版差点漏掉——如果 `overrides` 里的 `database_url` 不做二次归一化，测试就会连到开发库上、把真数据删掉。这条已写成注释，防止后人"顺手优化"掉。
