## W.3 AI 的关键输出与我的取舍

### W.3.1 Logo：三层意象，一个组件

图形取意「进校门 → 翻开文件 → 读明白」：门楣弧 + 两根门柱 + 摊开的册子（含书脊）+ 顶部一点。
48×48 `viewBox`，纯 `path`/`circle`，无位图、无字体依赖，任意尺寸都锐利。

三处尺寸**共用同一个组件**，只传 `size`：

| 场合 | 尺寸 | 说明 |
| --- | --- | --- |
| 顶栏 `.brand` | 30px | 与 14.5px / 11px 两行文字并排 |
| 登录小窗 `.head` | 44px | 与 15px / 11.5px 两行文字并排 |
| 落地页 `.brand-row` | 86px | 与 `clamp(64px,12vw,108px)` 的大标题并排 |

**踩到的坑：SVG `<defs>` 的 id 是全局的。** 三枚 logo 都写 `id="lg"` 时，后挂载的会覆盖前面的，
表现是"某个尺寸的 logo 突然变成纯色"。用 `useId()` 生成唯一 id（实测 `logo-grad-v-3`）。

`useId` 是 Vue 3.5 才有的，而 `package.json` 写 `^3.4.0`、实装 3.5.45——
**`vue-tsc --noEmit` 退出 0 不能证明它在运行时存在**（类型来自实装的 3.5.x，运行时在旧环境可能是 3.4）。
所以代码里保留 `typeof useId === 'function'` 的回退分支。

### W.3.2 浅底：三处结构性返工

这一节是本轮花时间最多的地方，返工三次，每次都是**不同性质**的错。

**返工一："往白里加白"。**

深色主题里 `rgba(255,255,255,0.05)` 的意思是"比背景亮一点"——输入框底、分段控件底、行悬停态全靠它。
到白底上它等于**什么都没画**。可怕的地方在于：元素还在、尺寸也对、`opacity` 也是 1，
**只是看不见**，看图会以为是"风格变简约了"。

全仓 `grep -rn "rgba(255, 255, 255"` 找到 **18 处**（`AuthPanel` / `styles.css` / `WelcomeView`），逐处处理：

| 原写法 | 改为 | 用于 |
| --- | --- | --- |
| `rgba(255,255,255,.03)` | `--c-elev-1: rgba(18,48,43,.045)` | 表格行悬停 |
| `rgba(255,255,255,.05)` | `--c-elev-2: rgba(18,48,43,.075)` | 分段控件底、输入框底 |
| `rgba(255,255,255,.08)` | `--c-elev-3: rgba(18,48,43,.115)` | 选中态、强调面 |

用深绿灰 `rgba(18,48,43,·)` 而不是纯黑，是为了让"浅底"带一点青碧的调子，不是死白。

**判据一句话：深色里的"加白"到浅色里必须变成"加黑"。**

**返工二：主色分工反了。**

深色主题下我（R9）写过一条硬规则：`--c-primary` 只用于文字，铺底用 `--c-primary-strong`。
到浅底上这条规则**方向对了、取值反了**：

| | 深色（V2.5） | 浅色（V2.6） |
| --- | --- | --- |
| 当文字 | 亮青碧 `#2fc7b4`（于深底 8.1:1） | 深青碧 `#0a7d6f`（于白底 5.03:1） |
| 当底色 | 深青碧 `#0b7f74` | 更深 `#076b5e`（压白字 6.41:1） |

浅底上"当文字"必须比"当底色"**更深**才读得清，恰好与深底相反。直接把深色主题的两个值搬过来，
结果是 `--c-primary` 当文字只有 3.42:1（不合格），当底色压白字 2.x:1（更糟）。

**返工三：对比度是算出来的，不是看出来的。**

写了三版试算脚本（`.build/contrast.js` / `contrast2.js` / `contrast3.js`），
对 `surface` / `bg` / `surface-2` 三种底逐色验算。第一版 14 项里 **8 项 FAIL**：

| 色 | 初值 | 初值对比度 | 校准后 | 校准后对比度 |
| --- | --- | --- | --- | --- |
| `--c-dim` | #6b7f79 | 3.17 ❌ | #5f736d | 4.53 ✅ |
| `--c-primary` | #12867a | 3.42 ❌ | #0a7d6f | 5.03 ✅ |
| `--c-accent` | #b8842a | 2.97 ❌ | #9c6410 | 6.10 ✅ |
| 白字 / `primary-hover` | #0a9484 | 4.25 ❌ | #0a8375 | 4.65 ✅ |
| `--c-met` | #1a8c56 | 4.36 ❌ | #19804e | 4.95 ✅ |

校准后 **21 项全部 ≥ 4.5**，最低 `dim/surface-2 = 4.53`，最高 `text/surface = 14.16`。
这些数字写进了设计说明书 §8.4，因为"看着够清楚"这种判断没法复核，数字可以。

**一个反向判断：边框不该按 3:1 要求。** 脚本里我把 `border/surface`（1.27）也标了 FAIL，
想了两分钟才明白是自己用错了标准：WCAG 的 3:1 是针对"**必要的**非文字控件边界"的启发式，
浅色主题里装饰性的描边本来就该淡。硬套 3:1 只会逼出一圈黑框。
这条判断写进了代码注释，免得下一轮有人"修"回去。

### W.3.3 分类色：对比度够，不等于能分开

词云是小字号，靠色相区分。原来七个分类色里 `#1f7a4d`（绿）与 `#4a6f8a`（蓝灰）
**对比度都合格**（分别 5.1 / 4.6），但两者**相对亮度差只有 0.0009**——缩到 12px 就分不出是两种颜色。

这类问题只验对比度是查不出来的，得另算一遍两两亮度差。第七色换成 `#8a3f8f`（紫）后，
最小亮度差升到 **0.0034**，白底 **6.59:1**。

### W.3.4 页面过渡：三个决定都不是"套个 Transition"

```html
<router-view v-else v-slot="{ Component }">
  <Transition name="page" mode="out-in">
    <component :is="Component" :key="route.path" />
  </Transition>
</router-view>
```

| 决定 | 取值 | 不这么做会怎样 |
| --- | --- | --- |
| **只包 `content` 里的页面组件，不包 `main`** | — | 侧栏与顶栏是常驻外壳，包进去每切一次整片闪 |
| **`mode="out-in"`** | — | 不设时新旧两页**同时存在**，能看到两段标题并排 |
| 时长 | 离场 150ms / 入场 210ms | `out-in` 下总时长**相加**，单程必须压短，否则一次切页 0.6 秒 |
| 位移 | 入场 `+6px`、离场 `-4px` | 内容区多是长页面，位移大了像"页面滚了一下" |
| 减弱动效 | 只留 0.12s 淡入淡出、**不做位移** | 位移是最容易引起前庭不适的一项 |

### W.3.5 粒子：canvas 而不是 DOM，且要能"证明它在动"

漂浮微粒 + 近距离连线（132px 内），指针附近有排斥（110px）。

| 决定 | 做法 | 理由 |
| --- | --- | --- |
| canvas 还是 DOM | **canvas** | 60 个会动的 DOM 节点每个都要布局+合成；canvas 每帧只改两个浮点数 |
| 点数 | 按面积缩放（1440×900 基准 62 点），夹 18–124 | 固定点数在 4K 上稀、在 1280 上糊 |
| 高分屏 | `dpr = min(devicePixelRatio, 2)`，`el.width` 与 `style` 尺寸**两个都设**，再 `ctx.setTransform` | 只设一个会模糊或错位；不夹到 2 则 3x 屏帧率掉一半 |
| 排斥 | `p.vx *= 0.996` 阻尼 | 少了这行，粒子被指针推开后越积越快，像被"吹飞" |
| 边界 | **环绕**（出左从右进） | 反弹会在边缘堆成一条线，很扎眼 |
| 交互 | 容器 `pointer-events: none` | 粒子层在最上层铺满视口，不设的话整页点不动 |
| 后台 | `visibilitychange` 时**主动 cancel** | rAF 在后台只降频到 ~1Hz，不会真停，仍在耗电 |
| 减弱动效 | **不创建 canvas** | 静态粒子云看起来像屏幕上的脏点，不是"简化版动效" |

### 验收脚本自身的三次误报

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| `KeyError: 'navOnText'` | 断言里取了一个我没放进返回对象的字段——**脚本的 bug，不是页面的** | 补字段（`navOnText` → 直接取 `text`） |
| 「过渡带 opacity」FAIL：`opacity=1` | 点完**立刻**采样，元素还挂着 `page-leave-from`，样式尚未走到 from 值 | 改用 rAF 连采 430ms，判"任一帧 opacity < 0.85 且位移 ≥ 2px" |
| 旧断言查 `.logo` 会 FAIL | R10 已把「知」字方块换成 `LogoMark`，**不是回归，是选择器过期** | 改查 `.logo-mark`，并**反向断言**旧 `.logo` 已不存在 |

第 2 条最值得记：**"动画没写"和"采样窗口错了"在数据上长得一模一样。**
判据必须表述成"过程中出现过中间态"，而不是"某一时刻的值是多少"。

第 3 条是本项目的通病：**改组件后，旧脚本的选择器会静默过期。**
处理方式是"改成新选择器 + 反向断言旧的已不存在"——只改前者，会漏掉"两套并存"的情况。
