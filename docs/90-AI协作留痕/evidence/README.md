# evidence · AI 对话证据归档目录

本目录存放**会话截图与录屏原始文件**，配合 `../00-AI对话历史总档.md` 的台账使用。

## 为什么需要这个目录

Markdown 快照能证明"我写了什么判断"，但**不能证明"这段对话真实发生过"**。赛事接受"截图或录屏"作为导出替代方案，因此这里放的就是那部分证据。

## 命名规范

```
AI-<链编号>-<序号>-<YYYYMMDD-HHMM>.png
```

示例：

| 文件名 | 含义 |
| --- | --- |
| `AI-D-01-20261107-1742.png` | 链 D（文档质量缺陷）第 1 张，11-07 17:42 |
| `AI-E-03-20261107-1801.png` | 链 E（Git 推送故障）第 3 张，11-07 18:01 |
| `AI-F1-02-20261110-2130.png` | 功能链 F-1（文档入库）第 2 张 |

录屏文件命名：`AI-<链编号>-REC-<YYYYMMDD>.mp4`。

## 每条链最少需要的截图

| 序号 | 必须拍到 |
| --- | --- |
| 01 | 我输入 Prompt 的完整内容（输入框可见） |
| 02 | AI 给出的方案或代码（能看出这是它的原输出） |
| 03 | 我发现问题后的追问 / 纠正 |
| 04 | 修复后的验证结果（脚本输出、测试通过、页面正常） |

> 只有 01、02 而没有 03、04 的链，无法证明"你驾驭了 AI"，只能证明"AI 给了东西"。

## 硬性要求

1. **截图前遮挡**：API Key / GitHub PAT / 手机号 / 真实姓名学号 / 他人隐私。
2. **不得裁掉自己的提问**：只截 AI 输出的截图一律作废。
3. **不得修改图像内容**（裁剪、遮挡之外不做任何处理）。
4. 截图放入本目录后，必须在总档 §3 台账把对应链的"截图"列由 `⬜` 改为 `✅`，并单独提交 `docs(ai-log)`。
