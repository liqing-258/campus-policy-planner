## M.1 目标（一句话）

让这个系统**在别人的电脑上、不装任何环境、双击就能用**，并且**界面上看不出它是一个课程项目**。

拆成三件必须落地的事：

1. **前端产品化**：删掉全部建设期信息（里程碑进度、接口条数、测试项数、`M3`–`M7` 角标），
   布局按已上线项目 `120.27.211.217`（本人"智能教室设备管理系统"）的"顶栏 + 分组侧栏 + 内容栅格"重做；
2. **单进程可交付**：Flask 直接托管构建产物，一个端口跑完整系统；再把整个后端打成免安装 exe；
3. **门禁可复现**：干净树 10 分钟内跑通，exe 在陌生目录能自举，界面用**真实渲染**而不是读源码来验。

一条隐含要求（后来变成最难的一条）：**这三件事的验证方式，必须是"真的跑一遍"，而不是"检查一下代码"**。
M7 所有的坑都出在这条上。

### M.3.2 后端：路径分离、静态托管、首次自举

新增 3 个能力、1 条硬约束：

```text
app/paths.py        resource_root()  ← 只读（_MEIPASS）
                    writable_root()  ← 可写（exe 同级）
app/bootstrap.py    ensure_schema() / ensure_users() / ensure_documents()
app/__init__.py     "/" 与 "/<path:filename>" 托管 SPA；api/* 显式 abort(404)
server.py           --no-browser / --bootstrap / --reset / --selftest
```

`--selftest` 是这轮最有用的小工具：起服务 → 打 6 项 HTTP 断言 → 打印 `[OK]/[FAIL]` 表格 → 用退出码表示结果。
它是 exe 自检与复现门禁**共用的判据**，避免了"两个脚本各自判断一遍、口径还不一样"。

### M.3.3 打包：单文件 exe + 三个检查脚本

```text
tools/build_exe.py     pkg_modules("app") 扫目录生成 --hidden-import
                       --onefile --console --add-data "frontend/dist;frontend/dist"
                       --add-data "demo;demo"
                      写 4 个 bat（GBK + CRLF）+ 使用说明.txt
tools/verify_exe.py    场景 A 裸 exe / 场景 B exe+交付库；跑完比对 dist/ 未被污染
tools/browser_check.py 无头 Edge + CDP：7 页真实渲染、断言 BANNED 零命中、量亮度
tools/repro_check.py   git archive HEAD → 干净树 → 10 步计时 → 对照 600 s 门禁
```

`build_exe.py` 里有一句刻意的设计：**hidden-import 由脚本扫目录生成，不手写清单**。
理由是 `create_app()` 里蓝图是函数内 `import`，手写清单一定会漂；而漏一个的表现是
"构建成功、双击报 `ModuleNotFoundError`"——最难查的一类失败。

## M.4 人工干预记录（AI 出错、被纠正的地方）

### M.4.1 `class="btn ghost"` 里根本没有 `ghost` 这个类

`AskView.vue` 里"清空对话"按钮写的是 `class="btn ghost"`。`styles.css` 里定义的是 `.btn-ghost`。
后果不是报错，而是**这个次要按钮渲染成了主色实心按钮**——比"清空对话"四个字更像"提交"，
在页面上是视觉误导。

`vue-tsc` 不查 CSS 类名，`vite build` 也不管，测试更不会管。**只有渲染出来看才发现。**
这也是 M7 坚持写 `browser_check.py` 的直接原因：类型检查通过 ≠ 界面正确。

修法：改类名，并且在 `styles.css` 里补了 `.btn-ghost` 的 hover 态。

### M.4.2 登录页顶部多出一条应用顶栏，品牌写了两遍

`App.vue` 无条件套外壳，于是 `/login` 被渲染成"顶栏 + 侧栏 + 登录表单"，
而登录页自己又有一块品牌区——**同一个产品名在屏幕上出现两次**，还多出一个"数据范围 · 本人"，
可那时用户根本没登录。

修法：`App.vue` 加

```ts
const isPublic = computed(() => Boolean(route.meta.public))
```

公共路由走 `<router-view v-if="isPublic" />` 独立成页，不套外壳。
这是"先在渲染里看见，再回代码里找原因"的典型：代码读起来完全合理，只有截图才暴露。

### M.4.3 答案里的 `**粗体**` 原样显示成星号

模型按 Prompt 要求输出 `**关键**` 加粗，但前端是纯 `{{ answer }}` 插值，于是页面上出现 `**`；
同时换行被 HTML 折叠，六段式答案糊成一大段。

修法两步，顺序很重要：

1. **先 `escapeHtml()`，再**把 `**x**` 换成 `<strong>x</strong>`，然后才 `v-html`。
   反过来（先转 `<strong>` 再转义）等于把 `<strong>` 也转义掉，或者更糟——把模型输出里的
   `<script>` 当标签执行。模型的输出是不可信数据，这条红线不能因为"只是加粗"就破例。
2. `.answer-text { white-space: pre-wrap; }` 保住换行。

（顺手发现 `white-space` 属性被写了两遍，是第一次替换留下的残渣，已清理。）

### M.4.4 `taskkill` 在中文 Windows 输出 GBK，把验证脚本的 reader 线程打崩了

`verify_exe.py` 第一版对 `subprocess.run(..., text=True)` 读 kill 的输出，
结果抛 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb4 in position 0`。

**这个错的表现极有欺骗性**：脚本崩了，人会以为 exe 有问题；但 exe 其实是好的，
崩的是"清理进程"这一步——因为中文 Windows 的 `taskkill` 输出"成功: 已终止进程"是 GBK，
而 `text=True` 按 UTF-8 解。

修法：

- kill 那条命令**不用** `text=True`，只取退出码；
- 子进程环境加 `PYTHONIOENCODING=utf-8`，让被检程序自己的输出是 UTF-8；
- 日志读取走 `decode()`：先 UTF-8，失败退 GBK。

### M.4.5 巡检把管理员页当学生页测 —— **是测法错，不是 bug**

`browser_check.py` 第一版按导航顺序逐页测，测到 `/rules` 时导航超时。
第一反应是"路由坏了"，查下去发现：学生访问 `/rules` 被守卫挡回工作台，
所以 `wait_for_url` 永远等不到 `/rules`。

**这是 RBAC 在正常工作。** 正确的处置不是去改守卫，而是改测法：拆出 `ADMIN_PAGES`，
换 `admin` 登录后再测。

这条单独记一笔，是因为"把正确行为当成 bug 去修"是本项目里最贵的一类错误——
M6 已经因为"把 `skipped` 当成缺陷"付过一次代价（见 `08-M6体验与质量.md` L.4.7）。

### M.4.6 第二次跑巡检在 `/login` 就超时：`user-data-dir` 里还留着上一轮的令牌

同一个 `--user-data-dir` 复用，localStorage 里有上一轮的有效 JWT，
于是导航到 `/login` 立刻被守卫跳回工作台，`wait_for_url(["/login"])` 永不满足。

修法：每次先 `goto(base + "/")`，再 `localStorage.clear()`，再开始登录流程。
**这属于测试夹具的卫生问题**，但它的表现是"页面打不开"，很容易被误判成前端崩溃。

### M.4.7 `test_root_route_is_human_readable` 挂了——因为它断言的是旧契约

根路径以前返回一段 JSON 说明（"这是个 API，前端在 5173"），M7 改成托管 SPA 之后，
`resp.get_json()` 返回 `None`，于是 `assert resp.get_json()["api"]` 抛 `TypeError`。

修法不是改回 JSON，而是**承认根路径现在有两种合法形态**：

```python
def test_root_route_serves_the_built_frontend_or_a_json_hint(client):
    resp = client.get("/")
    assert resp.status_code == 200
    if resp.is_json:
        assert resp.get_json()["api"] == "/api/v1"   # 没构建产物
    else:
        assert b'<div id="app">' in resp.data        # 有构建产物
```

并补一条新用例钉死一个更容易出错的行为：

```python
def test_unknown_api_path_is_json_404_not_the_spa(client):
    resp = client.get("/api/v1/no-such-endpoint")
    assert resp.status_code == 404
    assert resp.is_json          # 不能被 SPA 兜底吞成 index.html
```

**为什么这条重要**：如果 `/api/*` 的 404 返回 HTML 首页，前端 `res.json()` 会抛"解析失败"，
把人引向"后端崩了"而不是"路径拼错了"。一个本该 5 秒定位的错误会变成 5 分钟。

### M.4.8 WAL 让"看文件大小"变成假线索

裸 exe 首跑后，脚本去检查 `data/app.db` 是否"有内容"——文件只有 4 KB，
看起来像"库根本没建"。实际数据在 `app.db-wal`（816 KB），因为 SQLite 开了 WAL。

修法：判断库有没有内容**必须开连接 `count(*)`**，不能看文件大小。
这一条写进了 `09-M7` 的教训清单，也写进了 `运行说明.md` §5.5：
"一关程序数据就没了"那个现象，十有八九不是数据丢了，而是在看一个空壳 db。

### M.4.9 `--onefile` 会把数据库写进临时目录——而开发时完全看不出来

这是本轮**唯一一条"能在交付时悄悄毁掉项目"**的问题，且是设计期发现的，不是运行时踩的。

`--onefile` 每次启动把自身解压到 `%TEMP%\_MEIPASS`，**退出即删**。
如果数据库路径按 `Path(__file__).parent.parent` 推导，打包后它指向那个临时目录：

- 开发时（源码运行）这个路径恰好等于项目根 → **一切正常，看不出问题**；
- 打包后 → 用户第一次用正常，关掉窗口再打开，上传的文件、确认的计划、完成的任务**全没了**。

修法是新增 `app/paths.py` 把两个概念拆开，并让 `.env`、`app.db`、`uploads/` 全部走 `writable_root()`：

```python
def resource_root() -> Path:   # 只读：打包后 = _MEIPASS
def writable_root() -> Path:   # 可写：打包后 = exe 所在目录
```

验证方式也换了：**不在 `dist/` 里跑 exe**，整份拷到系统临时目录再跑，
跑完比对 `dist/` 前后逐项字节一致。在交付目录里跑一次，测试数据就混进"要发给老师的那一份"了。

## M.5 被否掉的方案（失败轮次不删）

### M.5.1 用 CSS 变量做主题切换，顺手提供"浅色模式" —— **否掉**

做过一版，发现要么维护两套令牌（深/浅各一份），要么每个组件都得写两遍 `var(--c-x)`。
真实需求只有一个：**界面看起来像个产品**。深色是参照 `120.27.211.217` 定的，
浅色模式没有任何人要求，加了只是给自己多一条可能出 bug 的路径（M4.1 那种浅底浅字在浅色主题下更难查）。
**砍掉。**

### M.5.2 保留"里程碑进度"卡，做成"可折叠的关于本系统" —— **否掉**

理由很直接：用户的原话是"**不能再显示任何有关里程碑建设任务的窗口**"。
把它折叠起来仍然是"显示"，只是默认收着。而且折叠的东西最容易被评审点开——
点开看到"当前进度 M6"，比直接显示更尴尬。
真正需要的"关于"信息（版本号、库规模）已经由 `/health` + 侧栏页脚承担了。

### M.5.3 exe 打 `--onedir` 而不是 `--onefile` —— **否掉**

`--onedir` 启动快（不用解压）、体积也小一点，但要交出去的是一个**目录树**
（`_internal` 里几百个文件），拷的时候少一个文件就报错，而且"双击哪个"这件事本身就要解释。
`--onefile` 的代价（102.8 MB、每次启动解压 3–8 s）比"拷贝出错"便宜。
代价如实登记在 `已知限制.md` C-10，没有藏。

## M.7 遗留问题（如实登记）

0. **M6 结项时列的 5 条"M7 优先"（部署加固 / 评测集扩到 60 条 / 漏抽差异报表 / 依赖 lock / 分页），

   11 天赛期里两者只能选一件。计划表原样保留在 `已知限制.md` §7 并逐条标注"未做"——
   **改计划比没做更糟。**
1. **技术文档是 13 页，而且这次是数出来的。** 第一版只能按字数估（约 17 页），
   这不算证据。为此写了 `tools/md_to_pdf.py`：A4 打印样式 HTML → 无头 Edge `Page.printToPDF`
   → PyMuPDF 数页，落地 `docs/70-提交版/技术文档（提交版·30页）.pdf`，**实测 13 页**（上限 30，余量 17）。
   改完 md 后把 PDF **逐页渲成 PNG 自己看了一遍**（`pymupdf` 105 dpi，13 张），
   看出 3 个只有肉眼能发现的问题，全部已修：

   | 问题 | 后果 | 修法 |
   | --- | --- | --- |
   | 段落内的 `<br />` 先拼接后被 `html.escape` 转义 | PDF 里出现字面量 `<br />` | 用 `\x00` 占位，转义后再换回 |
   | 代码块 `overflow: hidden` + 长注释 | **注释被裁掉**——这是文字丢失，不是难看 | `pre code { white-space: pre-wrap; word-break: break-all }` |
   | §9 写了 `pytest -q` | 与 `pytest.ini` 的 `addopts=-q` 叠成 `-qq`，汇总行被吞 | 改回 `pytest`，并把"为什么不能加 -q"写成脚注 |

   第一条和第三条都属于"我自己写的文档违反了我自己记过的规矩"（`<br />` 是转义顺序，`-q` 是 §5.4 的坑）。
   **不看渲染结果就发现不了**——这与整个 M7 的判断一致：能跑 ≠ 对，写完 ≠ 写对。
   仍未做：**没有用 Word/WPS 打开过**，字体回退与分页器差异只能靠那一步确认。
2. **演示视频还没录。** 脚本（8 分镜 / 每段口播 / 备用问题 / 禁止事项）已落盘，
   但赛事要的是视频文件本身。判据里"视频含 2 分钟 AI 协作"这一条**只有录完才算数**。
3. **exe 只验了 Windows x64。** PyInstaller 不能交叉编译，赛期没有第二台机器验证，所以不声称跨平台（C-12）。
4. **没有代码签名。** 首次双击会被 SmartScreen 拦一下（C-11）。个人开发者证书要钱，赛期来不及。

   代价如实登记（C-10）。
6. **只做了单机单进程。** 没有 HTTPS、没有反向代理、没有多实例；登录限流仍是进程内计数（C-2 / C-3）。
7. **界面只验了 Chromium 内核**（无头 Edge）。Firefox / Safari 未测——CSS 用的是标准属性，
   但"未测"就是"未测"，不写成兼容。

## M.10 这一轮最该记住的一句话

**"构建成功"和"能跑"之间，隔着一次真实启动；"界面写完了"和"界面是对的"之间，隔着一次真实渲染。**

PyInstaller 打印 `Build complete` 只代表压缩时没抛异常；`vue-tsc` 通过只代表类型没矛盾。
M7 里 9 处缺陷有 6 处是"代码读起来没问题、跑起来不对"：
按钮变实心（类名拼错）、品牌写两遍（少了 `v-if`）、星号原样显示（少了转义）、
数据落临时目录（路径算错）、WAL 让 db 看起来是空的、`taskkill` 的 GBK 把脚本打崩。
**这些都不是靠读代码能发现的，只能靠跑。**
