# 链 AJ · 登录落地页与进入路径（R23）

> 留痕编号：AJ ｜ 对应轮次：R23 ｜ 日期：2026-11-16
> 一句话：**落地页恒显，"进系统"是第二个动作**——令牌还在不等于可以替用户决定他看哪一屏。

---

## AJ.1 原始 Prompt（摘录）

> 优化一下登录逻辑，现在你每次给我的登录网址双击后跳转到的是学生端的工作台界面，
> 而理想状态是点击登录网址后跳转到的是 @image#1 这个界面，请你对这个问题进行优化。
> 请你严格按照我的要求执行任务，完成后更新需要迭代的文档，更新GitHub仓库。

截图那一屏是**落地页**：系统名「知校」+ 一句话 + 「开启系统」按钮 + 底部知识库规模
（`18 份政策 · 134 个可检索片段`），**没有登录框**。

## AJ.2 判断：不是路由守卫的问题，是落地页自己把自己弹走

第一反应是路由守卫把带 token 的人拦走了。但守卫里 `if (to.meta.public) return true` 在最前，
`/login` 是 public，守卫没拦。真正的原因在 `WelcomeView.onMounted`：

```ts
if (await auth.restore()) {
  router.replace(redirectTarget.value)   // ← 令牌还在就立刻走人
  return
}
```

**这行的本意是"已登录的人不必再看登录页"，但它把"看首屏"和"进系统"焊成了一个动作**：
只要本地令牌有效，落地页永远只存在一瞬间。用户双击网址 → 直接落在工作台，
截图那一屏根本没机会出现。

另外 `/login` 上还挂着 `props: { autoOpen: true }` —— 即便不被弹走，也会立刻弹登录框，
同样看不到首屏。所以两个问题叠着：**没机会看** + **看了也是弹框**。

## AJ.3 改法：restore 只答"我是谁"，去留交给「开启系统」

| 位置 | 改动 |
| --- | --- |
| `WelcomeView.onMounted` | 删掉 `router.replace`；`restore()` 的结果存进 `authed`，只用来决定按钮行为 |
| 「开启系统」按钮 | 已登录 → `router.replace(redirect)`（一键进系统）；未登录 → 拉开登录小窗 |
| 按钮下方小字 | 已登录时显示「已登录 · 换个账号登录」，专门开登录小窗 |
| `/login` 路由 | 不再 `autoOpen: true`；`?open=1` 才开窗（`redirect` 参数照旧） |

**为什么已登录时直接进系统而不是弹登录框**：令牌还有效就没有理由让人再输一遍口令；
要换账号有专门的入口。这样"看首屏"与"进系统"是两个动作，而不是同一个动作的两种结果。

## AJ.4 影响面：五个验收脚本的登录步骤

`browser_check` / `admin_ui_check` / `match_form_check` / `ask_flow_check` / `followup_click_check`
都写 `goto('/login')` 然后等用户名输入框——默认不开窗之后它们会等不到。全部改成
`goto('/login?open=1')`：**脚本要的是表单，用户要的是首屏，两者不冲突**。

一处现场：新门禁第一遍报 `JS 异常 1 条`，内容是 `GET /auth/me` 的 401。
那是**预期语义**（令牌过期 → 后端回 401 → 前端当未登录），不是异常——
浏览器把网络 401 也记成一条 console LOG。判据改为滤掉 `401/UNAUTHORIZED` 的 LOG，
`Runtime.exceptionThrown` 与 `console.error` 照旧判失败。

## AJ.6 没做的事

1. **没改登录接口、没改令牌机制**：`/auth/login`、JWT、`zxx_user` 缓存、退出登录全部原样；
2. **没改 `/` 的行为**：已登录进工作台是日常路径，不能让它每次先跳落地页再绕回来；
3. **没做"记住上次账号"**：那是新功能，不是这次的诉求；
4. **没动问答链路**（`followup_click_check` 的失败留着，见上）。
