## N.3 AI 输出摘要（做了什么，以及为什么这么做）

### N.3.1 ① 表单：先判断"这个控件该不该存在"

**用户的判断是对的，但原因和"颜色"无关。** 那个上下箭头不是 CSS 画的，
是浏览器给 `<input type="number">` 配的**系统原生 spinner**——它的配色跟随操作系统，
页面 CSS 只能改它的容器，改不了箭头本身。所以"把箭头调成深色"这条路从一开始就不存在。

于是问题变成：**这个控件需要存在吗？** 年级 1–8、绩点 0–5，键盘输入两三个字符就完事，
步进按钮在这个场景里没有任何价值。结论是**让它结构上消失**：

```vue
<!-- 不是 type="number"，原生 spinner 压根不会生成 -->
<input
  v-else-if="f.type === 'number'"
  :value="profile[f.key]"
  type="text"
  inputmode="decimal"
  autocomplete="off"
  :placeholder="f.hint"
  :aria-invalid="invalidFields.includes(f.label)"
  :class="{ bad: invalidFields.includes(f.label) }"
  @input="onNumberInput(f, $event)"
  @blur="normalizeNumber(f)"
/>
```

`type="text"` 也不是个省心的选择——它什么都收。所以字符过滤必须自己做，
而且要**在敲进来的瞬间做**，不能等提交：

```ts
function onNumberInput(f: Field, event: Event) {
  const el = event.target as HTMLInputElement
  const raw = el.value
  let next = raw.replace(/[^\d.]/g, '')      // 负号、字母、空格、+ 全在这一行没了
  const dot = next.indexOf('.')
  if (dot >= 0) {
    next = next.slice(0, dot + 1) + next.slice(dot + 1).replace(/\./g, '')  // 第二个小数点也删
  }
  // 只在真的改了字符时才回写 DOM：否则会把光标弹到末尾，
  // 在中间插一位数字时光标乱跳。
  if (next !== raw) el.value = next
  profile.value[f.key] = next
}
```

**越界值故意不夹到边界。** 这里做了一次取舍，写在了代码注释里：

```ts
/**
 * 失焦时只统一"写法"，不动数值：`007` → `7`、`3.20` → `3.2`、`.5` → `0.5`。
 *
 * 越界值**故意不拉回边界**——把 99 悄悄改成 8 等于替用户编了一个年级，
 * 用户还以为自己填的就是 8。越界就原样留着，由下面那行红字指出来。
 */
```

配套的三道防线：

| 防线 | 位置 | 挡住什么 |
| --- | --- | --- |
| 输入过滤 | `@input` → `onNumberInput` | 负号、字母、`1e9`、第二个小数点 |
| 越界提示 | `computed invalidFields` | 99 年级、-1 绩点：红字列出 + **禁用提交按钮** |
| 提交前兜底 | `buildProfile()` | 粘贴、自动填充、脚本赋值绕过模板的情况 |

学生类型改 7 项中文下拉（全部虚构校园口径）：
全日制在校本科生 / 专科生 / 硕士研究生 / 博士研究生 / 非全日制研究生 / 交换生 / 旁听生。

### N.3.2 ② 问答页：三行网格，不是"flex 列 + 粘底"

"输入框固定在页面最下方"听起来是 `position: sticky` 或 `flex-direction: column` 的活。
**但这一页不能这么写**，因为它有一个右侧历史栏：flex 列会让输入框横跨整页宽度，
伸到历史栏下面去，看起来像"浮在右边"而不是"接在对话下面"。

改成三行网格，每块显式指定行列：

```css
.chat {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 244px;
  grid-template-rows: auto minmax(0, 1fr) auto;   /* 标题 / 内容 / 输入 */
  height: calc(100vh - 56px - var(--space-4));
  margin-bottom: calc(var(--space-8) * -1);
}
.chat-main { grid-column: 1;      grid-row: 2; min-height: 0; overflow-y: auto; }
.chat-side { grid-column: 2;      grid-row: 2 / 4; overflow-y: auto; }
.composer  { grid-column: 1;      grid-row: 3; }
```

`minmax(0, 1fr)` 里的那个 `0` 是关键：默认 `1fr` 的最小值是 `auto`，
内容一长就把行撑高、整页跟着变高，输入框又被顶下去。写成 `minmax(0, 1fr)` 才真的"内部滚、外壳不动"。

建议问题做成**两态**，因为用户的两条要求其实是两个场景：

```ts
const suggestOpen = computed(() => {
  if (!suggestItems.value.length) return false
  if (focusOpen.value) return true          // 还没问过 → 只有聚焦才出现
  return Boolean(answer.value || refusal.value || degraded.value || citationRejected.value)
})                                          // 已经答过一轮 → 常驻
```

「答案」二字：改标题只是第一步，真正麻烦的是**它藏在别的地方**（见 N.4.9）。

政策文件链接给的是站内深链，并在页面上写清理由——用户说了"一定不要有任何违规行为"，
最守规矩的做法不是去找一个"看起来像官网"的地址贴上去，而是**根本不编造外部域名**：

```vue
<router-link class="src-link" :to="{ path: '/library', query: { doc: s.id } }">
  在知识库中打开 →
</router-link>
<p class="muted tiny">
  链接指向本站知识库中的文件（均为虚构示例，不指向任何真实机构）。
  系统不提供、也不编造外部网站地址。
</p>
```

### N.3.3 ③ 追问：从这一轮的结果里长出来

「下一步」原来是系统列的"你可以去做的事"（去建计划、去看规则），
用户要的是"我还能接着问什么"。差别在于**主语**：前者是系统，后者是用户。

于是把 `next_actions` 降级成一行小字「相关操作」，真正的追问区改成由本轮结果计算：

```ts
const followUps = computed<string[]>(() => {
  if (!hasResult.value) return []
  const label = matterLabel.value
  const doc = sources.value[0]?.title
  const vague = /^其他/.test(label)       // 「其他事项」是占位说法，见 N.4.4
  const out: string[] = []
  if (relatedConflict.value) out.push(`新旧两版《${relatedConflict.value.topic}》规定不一致时，以哪一版为准？`)
  if (refusal.value) out.push(...refusal.value.suggestions)
  else if (vague && doc) { /* 主语换成文件名 */ }
  else { /* 用 label 造句 + 引一份具体文件 */ }
  return Array.from(new Set(out.filter((s) => s.trim().length > 0))).slice(0, 3)
})
```

### N.3.4 ④ 最近提问：常驻面板 → 右上角按钮 + 抽屉

改三件事：

1. **位置**：从内容区中部挪到标题行右侧，做成 `btn-ghost btn-sm` 带条数角标；
2. **默认态**：默认展开（用户要"右侧是我提问过的问题"，所以第一次进来必须看得见），

## N.4 人工干预记录（十个真实现场，含我自己的返工）

### N.4.1 【崩溃级】修 bug 修出一个更严重的 bug

**现象**：第一版修改用了 `type="number"` + `v-model` + `@input` 清洗。
在浏览器里用脚本把年级设成 `-4`，页面**整块白掉**——不是报错提示，
是 `.profile-grid`（整个画像表单）从 DOM 里消失。

```text
BEFORE: <label class="field"><span>学生类型</span><select ...>
AFTER : grid 还在: False
        所有 input: []
CONSOLE TypeError: D.replace is not a function
        at T (index-eYxX1H1I.js:30:67594)
        at onInput (index-eYxX1H1I.js:30:72093)
CONSOLE TypeError: P.value[J.key].trim is not a function
        at ... (Array.filter) at ia.fn
CONSOLE TypeError: P.value[J.key].trim is not a function
        at N (index-eYxX1H1I.js:30:67758) at onBlur
```

**定位**：三条 TypeError 全部指向"对一个 number 调用字符串方法"。
去 `@vue/runtime-dom` 源码里确认了根因：

```js
// node_modules/@vue/runtime-dom/dist/runtime-dom.cjs.js:1582
const castToNumber = number || vnode.props && vnode.props.type === "number";
```

也就是说：`v-model` 绑在 `type="number"` 上时，**Vue 必然把值转成 number**，
而 `profile` 在 TS 里声明的是全 string 对象。

这里必须纠正一个容易犯的误判：**这不是"只有脚本赋值才踩得中"的边角**。
`castToNumber` 对键盘输入同样生效——用户打一个 `4`，写回的就是 number `4`。
换句话说，**任何人往这个框里打第一个数字，整页就会白**。

**为什么 224 项测试 + 7 页巡检都没抓到**：pytest 测的是接口（画像通过 JSON 直接传），
`browser_check.py` 测的是"页面能不能渲染、有没有溢出、深色主题亮度对不对"，
**没有一项是"往这个框里打一个字"**。三套验证都在自己的层里是绿的，
中间那条"人和控件之间"的缝没人管。

**修法**：不是给 `.trim()` 加类型判断，而是**不让值变成 number**——
摘掉 `v-model`，改用 `:value` + 手写 `@input`，输入框改 `type="text"`：

```ts
/** 读画像字段，永远拿到字符串。这层兜底留着防回归。 */
function textOf(key: keyof typeof profile.value): string {
  const v = profile.value[key] as string | number | null | undefined
  return typeof v === 'string' ? v : String(v ?? '')
}
```

**效果**：往三个数值框（年级 / 绩点 / 已修学分）里塞 `-4`，页面不崩、负号被抹掉；
排名百分比走同一条代码路径，脚本没有逐个覆盖——这一点如实写在断言清单里，不假装四个都测了。
`match_form_check.py` 的"不崩溃 / 负号被抹掉 / 越界不改数值"三组断言从红转绿。

> 这是本链唯一的"AI 自己制造的缺陷"。它的价值在于：**第一版方案看起来完全合理**
> （`type="number"` + `min/max` + `@input`，教科书式写法），
> 只有在真的往框里打一个数字时才会暴露。**方案的正确性不能靠"读起来对"来判断。**

### N.4.2 【32px】输入框"看起来贴底了"，其实差 32px

**现象**：改成三行网格后，肉眼觉得已经贴底，断言报 `距底 32px`。

**定位**：`.content` 有 `padding: 16px 24px 32px`。聊天页算高度时只扣了顶栏 56px 和上内边距，
下内边距没算进去：

```css
/* height 扣掉顶栏与上内边距，再用负 margin 抵消下内边距，总高正好一屏 */
height: calc(100vh - 56px - var(--space-4));
margin-bottom: calc(var(--space-8) * -1);
```

**效果**：距底 0px（断言阈值 12px，留 10px 呼吸）。

### N.4.3 【测法错，不是代码错】无头浏览器里的 `focus()` 不派发 focus 事件

**现象**："聚焦后才显示三条建议"这条断言反复失败，但代码逻辑检查了五六遍都是对的。

**定位**：无头窗口没有系统焦点时，`document.hasFocus()` 是 `false`，
此时 `element.focus()` **只设置 `activeElement`，不派发 `focus` 事件**——
Vue 的 `@focus` 根本没被触发。这是浏览器的行为，不是我的代码的问题。

```python
c.send("Emulation.setFocusEmulationEnabled", {"enabled": True})   # 打开焦点模拟
```

**判定**：这是本项目的**第二次**"测法错、不是代码错"（第一次在 M7 的 M.4.5）。
两次的共同点是：**断言先红，但红的原因在验证手段里，不在被验证的对象里**。
区别方法只有一个——去读被验证对象的实现，而不是猜。

### N.4.4 【跑题】「其他事项」造出了废话，知识库级清单被当成本轮结论

两个独立问题，症状都是"追问不对应"：

**其一**：意图分类没认出具体名目时给的 label 是「其他事项」，
拿它造句得到「其他事项需要准备哪些材料？」——读着像废话，点下去也答不出东西。
修法：主语换成引用到的文件名（`《图书馆借阅与自习空间管理办法》里还有哪些……`）。

**其二**：版本冲突是**知识库级**的清单（库里有哪几组同主题多版本），后端一次全给。
原先直接挂在本轮结果下面，于是问「图书馆能借几本」，解答下面顶着一张
"奖学金 2025/2026 两版"的黄色警告。修法：

```ts
const shownConflicts = computed(() => conflicts.value.filter((c) =>
  sources.value.some((s) => s.title.includes(c.topic) || c.topic.includes(s.title))))
```

**这个过滤同时关掉了两处噪音**：追问区不再跳去奖学金，那块黄色横幅也不再误报。

### N.4.5 【重复】点历史再问一次，右侧多出一行一模一样的记录

**现象**：截图里右侧「我提问过的问题」出现两条完全相同的标题。

**定位**：`ask()` **从不传 `conversation_id`**，后端于是每问一次就新建一条会话。
点历史 → 填入 → 再发送，必然多一条同题记录。用户会以为点按钮点出了 bug。

**修法**：只在"问题文本没被改过"时才续进原会话——

```ts
/**
 * 只在问题文本没被改过时才续：用户把它改成另一件事，就该是新的一个问题。
 * （后端带 conversation_id 会把上文拼进 prompt，改过的问题续进去会串味）
 */
const reuse = conversationId.value && payload === conversationTitle.value
const body: Record<string, unknown> = { question: payload }
if (reuse) body.conversation_id = conversationId.value
```

### N.4.6 【数据】刷新脚本首跑：18 份新文件，一份都没匹配上旧的

**现象**：dry-run 输出 `added=18 · dropped=5`，意思是要把旧文档全软删、新文档全新增——
等于 5 份旧文档的历史和关联全断。

**定位**：旧文档的 `title` 是当年手填的 `01-本科生奖学金评审办法（2025年版）`，
`normalize_title` 只做归一化、**不剥编号**；而新文件的 title 已经被
`bootstrap._title_of` 去掉了编号。两边永远对不上。

**修法**：`key_of()` 里多剥一次，只删 1–2 位且后面紧跟非数字的编号
（这样 `2024年…` 这种年份不会被误伤）：

```python
topic = re.sub(r"^\d{1,2}(?=\D)", "", normalize_title(title))
```

**效果**：`added=15 · updated=3 · dropped=2`，只软删了那两个异常样本。

### N.4.7 【外键】删文档前得先删片段与规则

```text
sqlalchemy.exc.IntegrityError: FOREIGN KEY constraint failed
[SQL: DELETE FROM documents WHERE documents.id = ?]
```

`document_chunks.document_id` 是外键，SQLite 开了约束。顺序必须是
`PolicyRule → DocumentChunk → Document`。

但更要紧的判断在**分支策略**上：有已复核规则的文件**不能删了重建**——
规则通过 `chunk_id` 外键绑在片段上，重解析会换 `chunk_id`，规则不是"失效"，
是直接指向不存在的行。所以：

| 文件状态 | 处置 |
| --- | --- |
| 有已复核规则（10 条规则涉及的 3 份） | **原地换文本**：改 title/文件名/哈希、覆盖物理文件、清洗片段里的"（演示样例）" |
| 无规则（其余 15 份） | 删了重建，保证片段与新文件逐字一致 |

**效果**：10 条已复核规则、`match_sessions` / `action_plans` / `tasks` 的溯源链全部保留。

## N.8 结论

**门禁通过**：五条要求全部落地，且每一条都有可执行断言；224 项后端测试、7 页巡检、
23 条问答断言、20 条表单断言全绿。

本链最重要的一个认知变化：

> **"验证过了"和"用过了"是两件事。**
>
> 这个系统在上一轮结束时是"224 项测试全绿 + 7 页巡检全过"，
> 但**没有任何一项验证是"往那个输入框里打一个数字"**。
> pytest 在测接口，巡检在测渲染，中间那条"人和控件之间"的缝，
> 直到用户截了一张"上下箭头颜色不对"的图，才被照出来——
> 而顺着这条线查下去，发现的是"打一个字整页白"。
>
> 所以从这一轮起，界面类缺陷的验收标准改成一条：
> **必须有一个脚本，用真实浏览器、从真实用户路径、产生真实输入**。
> 三条巡检脚本（`match_form_check` / `ask_flow_check` / `browser_check`）
> 分工就是按这条来的：一个管"控件收不收脏值"，一个管"流程对不对"，
> 一个管"每一页长得像不像产品"。
