### L.3.2 三条设计决定

1. **`status` 与 `outcome` 必须分开**。`status`（succeeded/degraded/failed）说"跑完没有"，
   `outcome`（answered/refused/citation_rejected/degraded/failed）说"跑完是什么结果"。
   一次正确的拒答是 `status=succeeded + outcome=refused`——只有一个字段时，
   它要么被冤枉成失败，要么看不出到底发生了什么。
2. **轨迹必须在抛业务异常之前 commit**。4001/4003/4006 都抛 `ApiError`，
   错误处理器只 `return fail(...)`，不 commit；若轨迹跟着业务数据一起回滚，
   "为什么这次拒答"就永远查不到。
3. **注入降权而不丢弃**。高相关片段（0.9 × 0.5 = 0.45）仍在阈值 0.35 之上，
   既不隐藏政策原文，又让拦截可见。真正兜底是引用白名单，不是正则。

## L.4 人工干预记录（AI 出错、被纠正的地方）

### L.4.1 同一个 flush 坑，第二次踩

```
sqlite3.IntegrityError: FOREIGN KEY constraint failed
[SQL: INSERT INTO messages (... workflow_run_id ...)]
```

`messages.workflow_run_id` 是表级外键，而 `Message` 与 `WorkflowRun` **没有 ORM relationship**，
SQLAlchemy 的 flush 排序不保证父行先写。M5 在 `matching.py` 踩过一次，M6 在 `qa.py` 又踩一次，
症状是 8 条 test_qa 全红、接口 500。修法：`recorder.finish()` 之后、`_save_messages()` 之前
显式 `db.session.flush()`，正常与降级两条路径都加。

**教训不是"记住这个坑"，而是"没有 relationship 的父子表，插入顺序永远要自己保证"。**

### L.4.2 `from app import workflows` 拿到的是模块，不是蓝图

```python
from app import workflows          # 函数体内，此时 app.workflows 是模块
workflows.WorkflowRecorder(...)    # AttributeError
```

因为 `app/__init__.py` 里注册蓝图时用 `workflows_mod` 别名，`app.workflows` 属性指向模块本身。
改成 `from app.workflows import WorkflowRecorder, serialize_run`。这类错误 `mypy` 能抓，但我们没有 mypy。

### L.4.3 `finish()` 被调用两次 → 一次问答两条运行记录

降级路径先 `finish()` 拿 `run_id` 写进消息、commit 后抛异常，外层 `except` 又 `persist` 一次。
`test_finish_is_idempotent` 是后补的——**先写的实现没意识到这条路会走两次**。
修法：`self.run` 缓存 + 早返回。

### L.4.4 我自己写的装饰性断言

```python
assert "injection" in c or True    # 恒真
```

写的时候想"确认一下有标记"，实际写成了永远通过。改成真的去 `/retrieval/search`
的候选里查 `injection.patterns` 含 `override_instructions`。
**假绿比红更危险**：它会让下一次重构失去保护。

### L.4.5 截断测试测不出来：200 字没到 240 字阈值

`"这一条说明写得很长，" * 20` 只有 200 字，断言"被截断"却永远成立（因为没截断也没超限）。
改成 `* 30`（300 字）。这条值得记：**边界测试的样本必须跨过边界**。

### L.4.6 `target_group` 过滤写成了"过滤后非空"

初版逻辑：过滤后没有规则 → 返回 2008。看起来对，但通用规则（`target_group` 为空，
如"须为在籍本科生"）永远被保留，于是**任何奖项名**都能匹配到 1 条通用规则并返回"符合 1 条"。

`test_unknown_target_group_says_what_is_available` 返回 `code=0` 才发现。
修法：必须存在**至少一条明确标注该奖项**的规则（`specific` 非空），否则 2008 并回传
`available_groups`。理由写进注释：

> 通用规则不能替某个奖项背书。返回"1 符合"会让申请人以为自己的奖项稳了——比报错更危险。

### L.4.7 绿了也不算完（一）：`test_versions.py` 全绿，但演示库一句话都说不出来

14 项测试通过后，我去演示库上试，发现 `academic_year`/`published_at`/`effective_status`
**三列全是 NULL**——M3 建表时就有这三列、上传接口也支持写入，但**前端从来没有入口**。

在这样的数据上"检测通过"，只能说明函数在测试造的数据上工作，
证明不了"管理员按界面操作后能看到冲突"。于是把"补后端接口 + 补前端入口 + 补演示数据"
一并做掉，才有 L.6.3 那段真实的冲突输出。

**这是本轮最重要的一条经验：单测绿 ≠ 功能可用。判断标准是"能不能在演示库里走一遍"。**

### L.4.8 绿了也不算完（二）：`PATCH /documents/{id}` 根本不存在

接着上一条，要把已有文件标成"2026 版"，发现没有任何接口能改元数据——
只能删了重传，而重传会换 `document_id`，挂在旧 id 上的已复核规则全部作废。

这是**清单外的第 31 条接口**。加它不是"顺手多做"，而是 T-12 可用的必要条件：
否则演示数据只能靠 SQL 塞，而那正是 `app/versions.py` 注释里批评过的做法。

### L.4.9 三、四次 `assert old in s` 失败：文件已经被改过了

用 `python - <<'PYEOF'` 批量改文档时，脚本里的 `assert old in s` 报错，
第一次以为是写法问题，重跑还是错——因为**上一次运行已经把内容替换掉了**。
改法：先 `grep -n` 看真实内容，再改；不要盲目重跑脚本。

### L.4.10 `pytest` 汇总行消失，我差点误判成"测试没过"

两次全量运行都只看到满屏点号、没有 `N passed`，退出码 1。查清是两个不同的原因：

1. **`-q` 叠了两次**：`pytest.ini` 里已有 `addopts = -q`，我再加 `-q` 变成 `-qq`，
   **汇总行被抑制**。这是我读错，不是测试失败。
2. **`%TEMP%` 清理被安全钩子拦截**：会话结束删旧临时目录（>50 文件）触发批量删除确认，
   进程被杀，退出码 1，汇总行随缓冲区一起丢失。
   用 `-u` 关缓冲 + `--basetemp` 指定目录解决——但**basemp 必须每次换新目录**，
   复用一个已存在的目录会让 pytest 启动时先删它，同样被拦，于是所有 fixture setup 报错。

这条不写"环境问题"四个字了事，因为**误读退出码会让整份测试报告失真**。

### L.4.11 扫描测试抓到了写文档的人

写 `docs/50-测试与评测/安全自查.md` 时，在"怎么查全历史"的命令示例里写了完整密钥。
`test_security_scan.py` 当场判红（`OpenAI/兼容 key @ docs\50-测试与评测\安全自查.md`）。

改成只写前 9 位。这条留在报告里，因为它是这道闸门唯一一次真实命中——
**它抓的是写文档的人，不是坏人。**

### L.4.12 重新生成演示文件导致三个二进制文件"被修改"

`tools/make_demo_docs.py` 重跑后，`demo/01`、`demo/02`、`demo/03` 的字节数完全一致但 Git 显示修改
（PDF/DOCX 的创建时间戳变了）。直接 `git checkout --` 还原，只保留新增的 2025 年版。
**演示资产没必要为元数据抖动留三次提交。**

## L.5 被否掉的方案（失败轮次不删）

### L.5.1 把没执行的 `matching`/`planning` 补成"已完成" —— **否掉**

六格进度条全绿很好看。但一次问答确实只走四节点，补绿等于每个数字都是假的。
代价是评审第一眼会问"两格怎么是灰的"——答案在其提示里：本次请求不涉及匹配。

### L.5.2 注入片段直接丢弃 —— **否掉**

丢弃最省事，但高相关片段里往往混着政策原文（"逾期视为放弃"就在同一段）。
丢弃等于把"这条政策写了什么"一起藏起来。降权到 0.45 仍高于阈值 0.35，
既保留原文又让拦截可见。

### L.5.3 继续加固注入正则 —— **否掉**

可以覆盖拼音、拆字、Base64，但每加一条都在推高误报。而**误报一次用户就开始忽略这个告警**，
比不提示更糟。方向改为引用白名单（结构性保证），正则只做"提高成本"。

### L.5.4 用语义聚类判"同一政策的两个版本" —— **否掉**

奖学金办法与勤工助学办法都含"家庭经济困难"，语义聚类必误报。取最保守规则：
规范化标题完全相同 + 年份或日期不同。代价是漏报改名版本，已登记为 A-2 限制。

### L.5.5 用 SQL 直接塞演示数据 —— **否掉**

能最快让界面出现冲突面板。但那样"演示能复现"就又变成假的了——
证明不了上传、解析、索引、元数据这条真实路径可用。改用 `tools/seed_demo_versions.py`
走应用内的真实接口（见 L.4.8）。
