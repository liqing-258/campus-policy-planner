## U.3 AI 输出摘要（做了什么，以及为什么这么做）

### U.3.1 先把九条归成四类，别一条一条改

逐条改的结果是九处互不相干的补丁。先归类才发现只有四种动作：

| 类 | 条 | 动作 | 落在哪 |
| --- | --- | --- | --- |
| **少显示** | 3、4、5、7 | 删掉或折叠 | `AskView.vue` / `MatchView.vue` 模板 |
| **输入行为** | 1、2 | 改事件与提交时机 | `AskView.vue` 的 `onEnterSend` / `useSuggestion` |
| **加控制** | 6 | 加一个多选筛选 | `MatchView.vue` 的 `shownStatuses` |
| **保状态 / 联动** | 8、9 | 新建 store + 动态边界 | `stores/match.ts` / `MatchView.vue` |

第 8 条不是"少显示"也不是"加控制"，它是**上一轮已经修过一次的同一类缺陷**：
R3 修过问答页的"切页丢对话"，当时的结论写在 `stores/qa.ts` 的文件头里。
这次把一个新页面接到同一套做法上——**复用判断，不复用代码**：
`qa` 存的是"这个标签页刚才在聊什么"，`match` 存的是"我正在填的表"，
后者含绩点与家庭经济困难认定，敏感级别更高，所以两处都选 `sessionStorage`、
都不选 `localStorage`，但理由不是一条。

### U.3.2 "去掉 [n]"不能删后端：引注是校验的产物

最省事的做法是在后端 prompt 里写"不要输出 [n]"。**没这么做**，因为：

`[n]` 是引用校验的输入。`app/qa.py` 会把模型输出里的编号与本次检索到的片段对照，
越界的编号要被剔除（`citation_warnings`），整篇编号全对不上时整条解答会被拦下（4003）。
让模型不写编号，等于把这条校验一起关掉——**为了界面干净，把"能不能核验"这件事废了**。

所以剥离放在**渲染层**：

```ts
// AskView.vue
function stripCitationMarks(text: string): string {
  return text.replace(/[ \t]*(?:\[\d{1,3}\])+/g, '')
}
```

三条约束，都是为了不误伤：

- **只剥纯数字的方括号**：`[附件1]`、`[注]` 是有意义的正文；
- **连续几个一起剥**：`[1][2]` 是常态；
- **只吃同一行内的空格**：正文是 `white-space: pre-wrap`，`\s*` 会把换行一起吃掉，
  整段会挤成一坨。

落库的消息**保留**编号。将来若要恢复"点 [1] 跳到片段"，不用重跑一遍问答。

同一轮的连带影响：页面顶部与欢迎区都写着"解答里的每个 [n] 都对应一条真实片段"。
正文没有编号了，这句话就成了错的——见 §U.4.5。

### U.3.3 藏起来 ≠ 删掉：引用片段与政策原文

第 3 条说"引用片段可以隐去"，第 7 条说"无需显示其他文字"。两条都照做，但**没删**：

| 位置 | 改法 | 为什么不删 |
| --- | --- | --- |
| 解答的「引用片段」 | 标题带条数 + 「展开」开关，默认收起 | 这一页承诺"每句话都能核对" |
| 匹配条目的出处 | `<details>政策原文</details>`，默认收起 | 匹配的全部价值就是可追溯到条款 |
| 「你的值 / 政策要求」 | **真删了** | 与 `rationale` 重复：「年级 4 满足要求不低于 2」已经带数值 |
| 规则编号 `R-3` | **真删了** | 内部编号，对填表的人没有意义 |

判断依据是**它是不是"另一份说法"**：重复的信息删掉，唯一的证据折叠。
两者在界面上都"看不见"，但一个是删、一个是藏，将来的代价完全不同。

### U.3.4 筛选做成"计数即开关"

第 6 条要"筛选三类中的任意一类或多类"。最直观的做法是在结论下面加一行三个 chip。
**没这么做**：那三个数字（符合 5 / 不符合 0 / 无法判定 0）本来就在最显眼的位置，
再加一组一模一样的按钮，等于把同一件事说两遍。

所以把计数本身做成 `<button>`：

```html
<button
  v-for="s in ALL_STATUSES"
  :class="['count', MATCH_TONE[s], { off: !shownStatuses.includes(s) }]"
  :aria-pressed="shownStatuses.includes(s)"
  @click="toggleStatus(s)"
>{{ MATCH_LABEL[s] }} {{ result.summary[s] }}</button>
```

三个细节：

- **多选**，不是单选；全选等于不筛。跑完一次匹配重置为全选——
  用户刚点完「开始匹配」，要看的是全貌，不是上次剩下的一半。
- **筛掉的类标 `off`**（35% 透明度 + 删除线 + 虚线边框），和"这一类本来就是 0"
  区分开：后者的数字是 0，前者的数字还在、只是没显示。
- **筛选不影响 `summary`**：计数是"这次匹配的事实"，筛掉某一类不该让它变成 0。

### U.3.5 年级上限是动态边界，与其它数值字段两种策略

第 9 条有两个要求，一个是边界（专科 1–3、本科 1–4），一个是**夹取**
（输 9 得 3、输 0 得 1）。

夹取和现有代码是**冲突**的。`normalizeNumber` 原来的注释写着：

> 越界值**故意不拉回边界**——把 99 悄悄改成 8 等于替用户编了一个年级，
> 用户还以为自己填的就是 8。

用户现在要求夹取。照做，但**只对年级做**，理由不是"用户说了算"，是两类字段性质不同：

| 字段 | 越界的含义 | 处理 |
| --- | --- | --- |
| 年级 | **这个值不存在**（专科没有第 5 年） | 夹到边界，因为合法域由学生类型决定 |
| 绩点 / 排名 / 学分 | **可能算错了**（绩点填 9） | 原样留着 + 红字，不替用户改 |

年级的上限只对用户明确点名的两类设限：

```ts
export const GRADE_MAX_BY_TYPE: Record<string, number> = {
  全日制在校专科生: 3,
  全日制在校本科生: 4,
}
```

硕士 / 博士 / 非全日制 / 交换生 / 旁听生仍是 1–8——**不是忘了，是没有口径**。
凭猜给一个上限，等于替用户定义学制。这一条写进 §U.6。

下拉用的是原生 `<datalist>`，不是自绘面板：自绘要自己管焦点、键盘导航、点外部关闭，
三处各有各的 bug，而这里只需要 1..N 这几个数字。`datalist` 天生"点开有候选、
也可以不理它直接打字"，正好是用户要的交互。

输入过滤在 `onNumberInput` 里加了一个 `integer` 分支：年级连小数点都不留
（`2.5 年级`没有含义），`+ / -` 这类符号本来就被 `[^\d]` 抹掉。

### U.3.6 复用 qa store 的同一把尺子

第 8 条的修法是新建 `frontend/src/stores/match.ts`，把
`documentId / targetGroup / profile / result` 从组件的 `ref` 搬进 Pinia，落 `sessionStorage`。

四条取舍写在文件头，其中两条值得单独说：

- **`result` 也存**。只存输入不存结论的话，用户回来看到"九项都填着、结论区空着"，
  还得再点一次「开始匹配」。而匹配是确定性的（不调模型），同样的输入必然同样的输出，
  让他再点一次只是重复劳动。
- **不防抖，写即落盘**。数据量小（画像几百字节，结论几 KB），没有 `qa` 那种
  "每追加一条就 stringify 整个会话"的放大效应；而防抖留的窗口期正好覆盖
  "输完最后一个字、立刻点侧栏切页"——**那正是这个缺陷被报上来的场景**。

## U.4 人工干预（失败现场，按发生顺序）

### U.4.1 验收脚本把"历史轮次"当成了"当前轮"

第一次跑验收，问答页前四条全过，第五条报"引用片段不存在"。
截图里明明有 `引用片段（5）`——那是上一轮跑出来的**历史**。

原因：`document.querySelector('.answer-text')` 会匹配到任何一轮的解答，
历史轮次（`.turn-bot.past .answer-text`）一直在 DOM 里。于是：

1. `wait_for` 立刻返回"答完了"（其实是上一轮那条）；
2. 当前轮还在生成，`.sec-head` 当然不存在。

修法两条一起用：
- 进页面先点「新对话」清掉历史；
- 断言一律用 `.turn-bot:not(.past) .answer-text`、`.cite-list:not(.compact)`
  （历史轮那份带 `compact`）。

**这类错误的共性是"选择器只描述了是什么，没描述是哪一份"**。
一个页面上同时存在"当前的"和"历史的"同名元素时，任何 `querySelector` 都在赌顺序。

### U.4.2 同步读 DOM，误报"夹取没生效"

第二轮：`专科生输 9 被夹到 3` 与 `输 0 被夹到 1` 两条报失败，读到的值是 `9` 和 `0`。

夹取改的是 `profile.grade`（Vue 的响应式状态），它要等下一次渲染才写回 `input.value`。
测试脚本在**同一个同步块**里 `el.value = '9'` → dispatch input → dispatch blur → `return el.value`，
读到的自然还是刚塞进去的 `9`。

修法是 blur 之后等 350ms 再读 DOM。**这不是产品缺陷，是断言写早了**。
但它值得记：Vue 的 DOM 永远落后于状态一个 tick，任何"操作完立刻读 DOM"的断言都不可信。

### U.4.3 store 的 `restore()` 整体替换 `profile`——整页刷新必现

第三轮只剩一条失败：整页刷新后画像回来了，但 `hasResult: false`。
查下去发现是两个问题叠在一起，第一个是真 bug。

`MatchView` 里写的是 `const profile = match.profile`（拿引用，模板直接写这个对象），
而 store 的 `restore()` 里写的是：

```ts
this.profile = base        // 整体替换
```

替换之后 state 指向新对象，组件手里的 `profile` 还指着**旧的那个**。
于是 `restore()` 明明成功、界面还是一排"未填写"。

**为什么"切页回来"看起来是好的**：上一轮 `restore()` 已经把值写进了旧对象，
组件重新创建时取到的正好是那个"有值的旧对象"。两次错误刚好互相抵消。
**只有整页刷新（文档重建）才暴露**——那才是第一次 `restore()`。

修法是 `Object.assign(this.profile, base)`：原地改，引用不变。
`clearAll()` 里同一个写法一起改了。

这件事的教训比 bug 本身重要：**"切页测试通过"不等于"持久化正确"**。
持久化要验两条路径——SPA 切页（内存还在）和整页刷新（内存没了）。
只验前者，验的是内存，不是存储。

### U.4.4 "换文件就清结论"的 watch 把"恢复"当成"换文件"

同一个失败的另一半：`watch(documentId, ...)` 的职责是"用户换了政策文件 → 清掉上一次结论"。
但恢复会把 `documentId` 从空串改成上次选的那份，这次变化被当成"用户换了文件"，
把刚恢复出来的 `result` 一起清掉。

修法是把 `match.restore()` 从 `onMounted` 提到 setup 顶部**同步执行**，
放在 `watch(documentId)` 注册之前。这样 watch 注册时 `documentId` 已经是最终值，不会误触发。

**一个 watch 如果同时要响应"用户操作"和"状态恢复"，它迟早会把两者搞混。**
顺序能解决的，就不要加标志位。

### U.4.5 改完功能忘改文案，是截图看出来的

功能全绿之后看验收截图，发现页面顶部还写着：

> 解答里的每个 [n] 都对应知识库中一条真实片段，点开可以核对原文

正文已经没有 `[n]` 了。欢迎区的第一条同样过时（"每个 [n] 对应一条真实片段"）。
文件头的验收能力清单第 1 条也还写着"正文 + 每条结论后面的 [n]"。

三处都是"改了行为没改描述"。这类错的麻烦在于**它不会报错**：
功能全对、测试全绿、界面上一句假话挂着，谁读到都会困惑。

修完之后给验收脚本补了一条断言：页面顶部说明的文本里不得出现 `[n]`。
**能写成断言的文案，就别靠人眼看。**

### U.4.6 `pytest` 231 errors：`--basetemp` 复用了旧目录

功能改完跑后端回归，结果是 `73 passed, 231 errors`，每个 error 都指向 fixture 的
`AssertionError`。单跑 `tests/test_workflows.py` 却 15 项全过。

原因是 `--basetemp=.build/pt_run` **用的是 R7 用过的同一个目录**。
pytest 会先清空已存在的 basetemp，而本机的安全删除钩子会把这次批量删除拦下来——
于是上一轮的 `test_*.db` 残留，`db.create_all()` 撞上已存在的表，fixture 全线失败。

换成 `.build/pt_run5`（全新目录名）后：**304 passed, 1 warning in 234.98s**。

结论：`--basetemp` 的目录名要带轮次或用时间戳，**不要跨轮复用**。
这是"环境限制伪装成代码回归"的典型——如果当时直接去看代码，会查一整晚。

## U.6 已知不做（以及为什么）

1. **不做"点 [n] 跳到对应片段"**。现在正文直接不带编号，最省事。
   真要做得先解决"一屏里有多个引用列表时跳到哪一个"，那是另一个交互设计。
   落库的消息保留着编号，将来做这个功能不用重跑问答。
2. **研/博/交换生/旁听生的年级上限仍是 1–8**。用户只给了专科（1–3）与本科（1–4）
   两类口径，其余凭猜写一个上限等于替用户定义学制。要加只是一行常量。
3. **筛选不跨会话保存**。切页回来仍是全选——筛选是"这一次怎么看"，不是"我的偏好"。
   真要记住，应该记在这台设备上（`localStorage`），那是另一条需求。
4. **匹配结论的 `details` 不做"全部展开"**。条目最多二十来条，逐个展开够用；
   加一个"展开全部"会让页面在默认状态下和没折叠一样。
5. **不做"建议栏已关闭"的持久化**。关掉的是"这一次"，下一次提问它会回来——
   这是刻意的，见 §U.3.1 与验收里的「关过一次后…又重新出现」。

## U.8 结论（一条认知变化）

九条需求里有六条在说"别给我看这个"。**照做很容易，做对不容易**：
删掉的和折叠的在界面上一样"看不见"，但删掉的东西将来要重新造，折叠的只要点一下。

所以这一轮真正的判断是**每一处删之前问一句"它是不是唯一的一份"**：
「你的值 / 政策要求」与 `rationale` 重复 → 删；
政策原文、引用片段是唯一的证据 → 折叠；
规则编号是内部术语 → 删。

另一条：**"切页测试通过"验的是内存，不是存储**。
持久化必须验两条路径，整页刷新那条才是真的。
这个缺陷在切页路径上被两次错误互相抵消，藏了整整三轮。
