## V.3 AI 的关键输出与我的取舍

### V.3.1 注册：三个约束逼出来的一个设计

需求要「姓名 + 学号 + 数字验证码」三栏。三个约束卡在这里：

| 约束 | 解法 | 代价 |
| --- | --- | --- |
| `users` 表没有 `student_no` 列，且项目用 `create_all()` 建表（老库不会自动改结构） | **学号即 `username`** | 学号不能改；改学号等于改账号 |
| 登录必须有密码，但需求没给密码栏 | 密码选填，留空用**学号后 6 位**，并在成功页把初始密码原样打出来 | 弱口令，登记为已知限制 |
| 「该学号已注册」不能被当成学号枚举接口 | **先验验证码再查库** | 打错验证码就白查一次 |

第三条最容易被写反。写反的后果不是"功能不对"，而是**这个接口变成了一个不用过验证码的学号查询器**：
攻击者拿随便一张过期码去试 `student_no`，只要返回"已注册"就知道这个学号存在。
用例 `test_duplicate_check_cannot_bypass_captcha` 就是锁这一条的。

验证码还有一条：**错了也销毁**。留着重试等于把 4 位数字的穷举成本从 1 次降到 N 次。
代价是打错要换图——注册页可以接受（点图即换）。前端因此做了个反直觉的决定：

```ts
// 注册失败也必须换码：服务端是**先校验后查重**，验过一次这张码就作废了
void refreshCaptcha()
```

第一版是"只在 `code === 1006` 时换图"，靠 `message` 正则猜错误码。后来想清楚：
任何注册失败都走完了验证码校验，这张码必然作废。不需要猜，一律换。

### V.3.2 主色调：为什么按钮不能用 `--c-primary` 铺底

换肤时最容易出错的是"主色好看就直接铺底"。实测对比度：

| 组合 | 对比度 | 结论 |
| --- | --- | --- |
| 正文 `#e7f1ee` 于 `#08110f` | ≈15:1 | 可以 |
| 次级文字 `#90a8a3` 于 `#08110f` | ≈6.4:1 | 可以 |
| **白字于 `--c-primary` `#2fc7b4`** | **≈2.1:1** | **不合格** |
| 白字于 `--c-primary-strong` `#0b7f74` | ≈4.9:1 | 可以 |

所以定了条规矩写进 `styles.css` 文件头：**`--c-primary` 只用于文字/描边/进度条，不铺大面积底色**。
旧版 `.btn` 直接铺 primary，这次全部改到 `--c-primary-strong`；导航选中态用 `brand` 渐变 + 左侧 2px 亮线，
不完全依赖颜色深浅。`App.vue` 的 logo 方块、`AskView` 的发送按钮与用户气泡也一样改了。

### V.3.3 工作台轮播：`scrollTop` 的小数被静默吞掉

需求是"自动上下滚动 + 悬停暂停 + 点击跳转"。第一版用 `requestAnimationFrame` 推进 `scrollTop`，
每帧位移 `speed * delta / 1000` ≈ 0.27px（16px/s @60fps）。

**现象**：验收脚本报 `scrollTop 1.0 → 1.0`，两秒内一像素没动。
但插桩后发现 setter **每秒被调用 60 次**——循环在跑，值却没变。

**真因**：`scrollTop` 在某些元素上不保留小数（布局单位 1/64px，写 0.27 读回来是 0）。
每帧都是"0 + 0.27 → 舍入 → 0"，永远在原地。改成自己累积余量：

```ts
carry += (props.speed * delta) / 1000
if (carry < 1) return
const step = Math.floor(carry)
carry -= step
view.scrollTop = Math.min(max, view.scrollTop + step)
```

**这条教训比修法本身重要**：`scrollTop` 在很长一段时间里读回来是整数，
写小数值"不报错、不生效"。凡是"循环在跑但状态不变"的现象，先怀疑**写入被精度截断**。

另一处：**不能复制节点做无缝 marquee**。复制会让读屏把每条念两遍，点击也分不清是哪一条。
所以滚到底停 1.1 秒再跳回顶部，视觉上像"换了一屏"。

### V.3.4 数据中心：口径必须写死，不能靠"看着差不多"

四个数字各自的算法都写进 `app/analytics.py` 的 docstring：

| 指标 | 算法 | 为什么 |
| --- | --- | --- |
| 平均符合率 | `Σ符合 ÷ Σ(符合+不符合+无法判定)` | 无法判定也是"评估过的一条"，不能踢出分母 |
| 画像完整度 | 已填字段 ÷ 9 | 只认非空；"任意"这类选项算已填 |
| 疑问条数 | `messages` 中 `role=user` 的行数 | 一条提问一行，追问也各自算 |
| `met_rate` 空库 | 返回 `null` 而不是 `0` | 0 会被读成"一个都没符合" |

`null` 那条是踩过的：前端拿到 0 会渲染成 `0%`，而实际是"没有数据"。两者含义完全相反。

### V.3.5 两处"数据看着像 bug，其实是事实"

**① 学生类型出来八瓣饼图。** 初次实测是：

```
[本科 12, 专科 5, 全日制在校本科生（具有本校正式学籍）4, full_time_undergraduate 4, ...]
```

`profile_json` 存的是**前端当时提交的原值**，历史上选项换过几版。直接 `group by` 得到一张八瓣、
每瓣 1 条的饼图，读不出任何趋势。加 `_normalize_student_type()` 归到四类后是
`[本科生 20, 专科生 5, 其他 2]`，原值另存 `raw_student_types` 供核对。

归并**只按关键词，不猜语义**：专科/本科/研究生三个词都认不出就归"其他"。

**② 词云里一半是半截词。** 初次 36 个词里有 `对绩`、`几本`、`几点`、`多久`、`时候`、`两版`、`年版`。
两处修：`STOPWORDS` 补十余个；加 `if count < 2: continue`——只出现一次的词字号小到看不清、
悬停只能回"出现 1 次"，纯噪声，这条同时天然挡掉被 jieba 切到一次的半截词。修后 28 词。

### V.3.6 词云压字：估算盒偏小，实测才对得出来

第一版词云是"纯螺旋 + 固定步长"，没有碰撞检测。理由写在注释里是"二三十个词，螺旋够分开"——
**这个理由是错的**。

程序化检测（取每个 `<text>` 的真实 `getBoundingClientRect` 两两求交）报出 4 对重叠：
`奖学金/借阅`、`本科生/图书`、`评审/逾期费`、`申请/四六级`。
原因：中文字宽约等于字号，「奖学金」在 28px 时占 112px，而螺旋一圈只拉开 30px，必然压字。

修法三步：① 加"估算外接盒 + 沿螺旋递增半径探测落点"的碰撞规避；
② 系数从"中文 1.02 倍字号"提到 **1.06**，四边各留 4px（第一版估小了，实测仍剩 1 对）；
③ 画布从 620×300 放大到 **640×360**（两个最大字号档的词在 300 高里放不下）。

结果：重叠 0 对，无出界。

**为什么坚持程序化检测**：截图里 26 个词，「奖学金」压住「借阅」看起来像"挨得近"。
肉眼判"好像没重叠"在 26 个词里必然漏掉一两对。这条断言已固化进验收脚本
（`词云无重叠` / `词云文字未出画布`）。

### V.3.7 `background-clip: text` 把整个标题画没了

落地页「知校」二字最初用渐变字：

```css
color: var(--c-text);
background: linear-gradient(168deg, #e7f1ee 6%, #2fc7b4 62%, #0e9488 100%);
-webkit-background-clip: text;
-webkit-text-fill-color: transparent;
```

**现象**：截图里标题位置一片空白，但 DOM 里 `innerText === '知校'`、
`getBoundingClientRect()` 是 236×113、`opacity` 是 1——**元素在、文本在，一个像素都不画**。

这类问题在真机上不一定复现（取决于 GPU 与合成层），但风险不对称：
对一个"进站第一眼就要看见系统名"的元素，掉字是灾难性的。
改为实色 `#e9f6f3` + 两层青色 `text-shadow` 模拟走向，任何环境都渲染得出来。

**判断规则**：`background-clip: text` 属于"**奖励不大、失败很惨**"的写法。
用于装饰性的小标签可以，用于关键标题不值得。

### 验收脚本自身的三次误报

这三条值得单独记，因为**它们看起来都像产品 bug**：

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| `/welcome` 导航失败，停在 `/` | 浏览器里留着上次的 token，`WelcomeView` 的 `onMounted` 判定"已登录就跳走"（**这是正确行为**） | 脚本改为先去 `/` 清登录态，再进 `/welcome` |
| "四个列表都套了滚动容器" → 只有 3 个 | 「我的待办」真的是 0 条（该学生名下无在办任务），空态不套容器是对的 | 断言改成"**有数据的列表**都套了容器" |
| 数据中心全空 | 后端跑的是**旧进程**，`analytics` 蓝图后加的、没注册 | 重启服务；接口直接 curl 确认 |

第三条尤其要注意：**静态文件是每次请求读盘的，所以前端改了不用重启；但 Python 蓝图是启动时注册的，后端改了必须重启。**
只看"页面能打开"会误判成前端问题。
