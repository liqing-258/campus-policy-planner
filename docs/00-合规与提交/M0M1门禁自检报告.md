## 4. 自检中发现并修复的 6 处缺陷

**这一节是本报告最重要的部分。** 门禁的价值不在"打勾通过"，而在"发现不通过"。

| # | 缺陷 | 怎么发现的 | 影响 | 修复 |
| --- | --- | --- | --- | --- |
| D-1 | PRD 标题写"P0 九项"，实际 10 条 | 逐行正则提取 `\| F-0x \|` 计数 | 口径自相矛盾 | 标题改"十项（F-01～F-10）"，保留历史说明 |
| D-2 | **F-01（登录与角色）、F-05（知识库浏览）没有任何验收标准** | 取 P0 集合与用户故事关联集合求差集 | 门禁 M1-4 实质不通过；这两项若不做测试，越权漏洞无人发现 | 补 **US-09**（越权返回 404 而非 403，避免泄露资源存在性）、**US-10**（软删除不破坏历史引用） |
| D-3 | 用户故事关联列用 `F-02/03/04` 简写 | 机器解析时把 `/03` 当作无效字符，误报缺口 | "可判定"无法机械校验，评审也无法快速核对 | 改为 `F-02/F-03/F-04` 全编号写法 |
| D-4 | **数据模型写"共 12 张表"，实际 13 张** | 统计 `### 3.x` 分节与 PK 数量 | 说明书、README、04 报告共 9 处同错；"9 实体 + 4 新增"却写"共 12"，自相矛盾 | 全局更正为 **13**（9+4=13），9 处同步 |
| D-5 | `match_sessions`、`workflow_runs` **没有索引** | 逐表检查"索引："行 | 违反门禁 M1-6；按 `user_id` 查历史会全表扫 | 分别补 `idx_ms_user_doc`/`idx_ms_created`、`idx_wf_user_created`/`idx_wf_status` |
| D-6 | `qa_feedback` 与 `audit_logs` 挤在一个小节，无独立字段表、无主键、索引合写 | 逐表检查 | 建表时无法直接映射 ORM 模型 | 拆为 §3.12 / §3.13，各补字段表、PK、索引与约束说明 |

## 7. 复验脚本（任何人在任何时间可重跑）

```bash
# M1-1 提交粒度
git log --oneline | wc -l
git log --shortstat --format='%h %s' | grep 'files changed'

# M1-3 敏感信息
git grep -nE 'ghp_[A-Za-z0-9]{20,}' -- .
git ls-files --error-unmatch .env    # 应报错（未跟踪）

# M1-4 P0 覆盖（Python，逐行解析）
python - <<'PY'
import io,re
s=io.open('docs/10-需求分析/PRD.md',encoding='utf-8').read()
p0=set(re.findall(r'\| (F-0\d|F-10) \|',s.split('### 2.2')[0]))
us=s.split('## 3. 用户故事与验收标准')[1].split('## 4.')[0]
covered=set(re.findall(r'F-\d{2}',us))
print('P0',len(p0),'覆盖',len(covered&p0),'缺口',sorted(p0-covered))
PY

# M1-5 接口数一致
grep -cE '^\| [0-9]+ \| (GET|POST|PATCH|DELETE) \|' docs/30-接口契约/接口清单.md
awk '/^## 6\./,/^## 7\./' docs/20-系统设计/系统设计说明书.md | grep -cE '^\| (GET|POST|PATCH|DELETE) \| /'

# M1-6 每表 PK + 索引
grep -c '^### 3\.' docs/20-系统设计/数据模型.md      # 13
grep -c '| PK |' docs/20-系统设计/数据模型.md         # 13
grep -c '^索引：' docs/20-系统设计/数据模型.md        # 13

# M1-7 技术栈一致性
grep -rn 'FastAPI\|React 18' docs/ README.md | grep -v 'ADR\|作废\|为什么\|V1.1 主要变更'
```
