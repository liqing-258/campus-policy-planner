## 1. 项目现状

「知校」是一个面向高校学生的**校园政策理解与事务规划系统**：把校内政策文件解析成可检索片段与可复核条件，
在此之上提供智能问答、资格匹配、事务规划、校园日历与管理员数据中心。

| 项 | 状态 |
| --- | --- |
| 技术栈 | Python 3.13 + Flask + SQLAlchemy + SQLite；前端 Vue 3 + TypeScript + Vite |
| 规模 | 后端 37 个 `.py`（`app/` 33 个模块）；前端 12 个视图 |
| 接口 | **57 条**（`tools/dump_routes.py` 现算） |
| 数据表 | **17 张**（业务 12 张 + 会话/审计等） |
| 政策库 | **18 份在用政策**（另有 3 份软删除验收件、2 份空文本演示件） |
| 政策条件 | 63 条规则，其中**已复核 9 条**可用于资格匹配 |
| 自动化测试 | **493 项**，31 个文件，`EXIT=0` |
| 交付形态 | 单文件 exe（109 MB，内嵌后端 + 前端产物 + 演示库） |

**本轮（R24）没有新增任何业务功能**，全部工作集中在：修掉一个真实缺陷、把三块"只能靠眼看"的东西变成可复现门禁、
补齐交付材料、并把版本冻结。

## 3. 本轮修复内容

### 3.1 P1：浏览器追问"点下去没反应"的真正原因

**现象**：`tools/followup_click_check.py` 三轮追问全部超时（1/3 → 实际每轮都空等 120 秒），
而同一句话走接口 6 秒就能答完。

**定位过程**（沿调用链读代码，不是猜）：

1. 接口直调正常 → 排除后端、模型、检索；
2. 读 `AskView.vue`：建议条按钮绑的是 `useSuggestion(s)`；
3. 读 `useSuggestion`：它只做三件事——`question.value = text`、`suggestClosed = true`、聚焦输入框。
   **不发送**；
4. 再往上查：这是 **R8 的明确要求**，用户原话"点击继续追问按钮时将该问题放置于对话框中，
   用户按下发送或是 enter 键才会发送"。代码注释里就写着"点建议只填入，不提交"。

**结论**：产品行为正确，**测试脚本假设了一个已经不存在的交互**。它写于 R8 之前，
之后一直按 `chip.click()` → 等 `.answer-text` 增加来断言，于是每轮必然空等满 120 秒。

**修复**（不是放宽等待、不是删断言）：

* 交互改成真实路径：**点选 → 断言只填入且未发送 → 点「发送」→ 等新解答**；
* 新增两条断言把这个契约**咬住**：一旦有人把"只填入"改回"直接发"，脚本立刻报错；
* 补 5 组边界场景：空白输入（按钮禁用）、快速连点三次（只产生一条）、整页刷新（对话仍在）、
  换角色（看不到上一个用户的对话）、管理员问答。

**结果**：**22/22 通过**（原 1/3）。

> 排查过程中另修掉两处**测试自身**的缺陷，一并登记：
> ① 断言在点击**同一帧**读 textarea，读到的是 Vue `v-model` 更新前的旧值 → 改为点击后单独等 DOM；
> ② `launch()` 复用浏览器 profile，上一轮的会话被 `sessionStorage` 恢复，于是"等到出现第一块解答"
> 在页面刚打开时就成立，读到的是空建议栏 → 改为先 `sessionStorage.clear()` 再进页面。
> 这两条与 R21 记过的"断言等到了页面上本来就有的东西"是同一类错误。

### 3.2 P2：后端测试退出码 1 的真实原因（R22 遗留）

**现象**：493 项全绿，但进程退出码是 1。

**定位**：这不是用例失败。默认 `--basetemp` 落在 `%TEMP%\pytest-*`，pytest 收尾时批量清理该目录，
被本机安全钩子拦下 → 退出码非零；同时汇总行有时被吞掉（本机 `addopts` 已含 `-q`）。

**验证**：把 basetemp 放进项目内重跑：

```
.venv\Scripts\python.exe -m pytest --basetemp=.build/pt-r24a -p no:cacheprovider
→ 493 passed, 1 warning in 408.21s  ·  EXIT=0
```

**结论**：**退出码 1 是环境行为，不是代码缺陷**。从此定口径：跑全量必须带 `--basetemp`（项目内、每轮换新名）。

### 3.3 本轮未修改任何业务代码

`app/*.py` 零改动、`frontend/src` 零改动、数据库结构零改动、接口仍 57 条、表仍 17 张。
R24 改动全部落在 `tools/`（验收工具）与 `docs/`。

## 5. 资格匹配模块最终验收

### 5.1 政策清单状态（本轮实测）

| 检查项 | 结果 |
| --- | --- |
| 有已复核条件、可用于匹配 | **3 份**：奖学金（2026 年版）、国家助学贷款与勤工助学、推荐免试遴选 |
| 待人工复核（`needs_review`） | 其余政策的条件均为待复核，**不出现在匹配页** |
| 不适用于资格匹配 | 由 `rule_type` 区分，只有 `eligibility` / `restriction` 参与 |
| 抽取失败 | 解析失败文件 `parse_status='empty'`，不进匹配列表 |
| 撤销复核后仍显示 | **不会**：判据是 `EXISTS(approved)` 子查询，撤销即移出（R21 已验证可逆） |

### 5.2 逐条验收（`tools/match_audit.py`，84 项断言）

对每份政策各提交三种画像，断言每一条已复核规则都被正确求值：

| 画像 | 断言 | 实测 |
| --- | --- | --- |
| `eligible`（绩点 4.0 / 排名 8% / 已认定困难 / 无处分） | **可比**条件必须全部 `met` | 奖学金 5/5、推免 2/2、助学贷款 1/1 —— 其中助学贷款的 R-1 是 `manual_review`（"家庭经济困难"要认定材料），判 `unknown` 才是对的，所以计的是"可比 1 条"而非"全部 2 条" |
| `ineligible`（绩点 2.0 / 排名 80% / 未认定 / 有处分） | 可比条件必须全部 `not_met`，且不得有一条 `met` | 全部 `not_met` |
| `sparse`（只填学生类型） | 不得给出任何结论；可比字段原因必须是 `missing_info` | 全 `unknown` |

同时校验：条目数 == 已复核条件数、三态取值合法、`unknown` 必带原因、`met` 必能回溯政策原文、
每条都带免责声明、`summary` 与实际计数一致。

**结论**：不存在"把无法判断的标成符合"，也不存在"把明显不符合的标成符合"；
匹配结果全部由 `app/matching.py` 的纯函数按算子计算，**不调用模型**，同输入同输出。

## 6. 管理员数据中心验收

### 6.1 数据准确性（接口 vs SQL，24 项断言全过）

| 指标 | 接口 | 独立 SQL | 口径 |
| --- | --- | --- | --- |
| 画像记录总数 | 49 | 49 | `count(match_sessions)` |
| 符合 / 不符合 / 无法判定 | 194 / 27 / 24 | 同 | `match_result_items.status` 分组；且与 `match_sessions.sum_*` 冗余列一致 |
| 平均符合率 | 0.792 | 194/245 | 符合 ÷ 判定总数 |
| 平均完整度 | 0.81 | 357 格 / (49×9) | 每份画像 9 个字段的填写率均值 |
| 近 7 天新增 | 49 | 49 | `created_at`（naive UTC）≥ 今天 −7 天 |
| 提问总数 | 108 | 108 | 非空用户消息数（限最近 2000 条）。**这个数会随浏览器门禁上涨**，见 §4.3 |
| 提问人数 | 2 | 2 | 会话所属用户去重 |
| 高峰时段 | 12 时 | 12 时 | 按 UTC+8 分桶后计数最大，并列取较小小时 |
| 词云 | 28 词 | — | **按 TF-IDF 权重降序**（不是词频降序） |

**两个口径值得写下来**：

1. **词云按权重排、不是按词频排**。「本科」出现 26 次却排在倒第四（十几份文件都有，IDF 低），
   「游泳馆」只出现 2 次却更靠前（只在食堂后勤指南里出现，区分度高）。词云字号跟着权重走。
2. **年级空值有两种写法**：`json_extract` 抽不到是 `NULL`，接口标成「未填写」。
   这是同一件事的两种写法，不是两种数据——核对时先对齐口径再比。

### 7.4 两条如实登记的限制（P2，不阻断交付）

1. **JWT 无状态、服务端无吊销表**：本项目没有 `/auth/logout` 接口，"退出登录"= 前端丢掉令牌。
   旧令牌在有效期内（`JWT_EXPIRE_MINUTES=720`，12 小时）仍可用。
   **影响**：仅当令牌被第三方拿到时才有意义；演示与比赛场景不构成阻断。
   **建议**：如需收紧，加一张 `revoked_tokens` 表（新表，不动既有表）并在 `login_required` 里校验 `jti`。
2. **演示库含测试会话**：见 §4.3，浏览器验收产生 6 条会话，未删除。

| 局域网 | `知校校园政策助手.exe --host 0.0.0.0 --no-browser`，别人访问 `http://<本机IP>:5000` | 需放行防火墙 5000 端口 |
| 公网 | 未做 | 未配置反向代理与 HTTPS，不建议直接暴露 |

**明确一点**：`127.0.0.1` 只对本机有效，评委在**另一台电脑**上打不开——要用局域网方式。

### 8.4 AI 服务配置

* 兼容 OpenAI 协议：`LLM_BASE_URL` + `LLM_API_KEY` + `LLM_MODEL` 三项，放 `.env` 在 exe 同级；
* **没有密钥不报错**：进入降级模式，只返回检索到的政策原文、不做归纳，界面顶部常驻说明；
* 换机器只需换 `.env` 三项，代码与数据库不用动；
* 真实密钥不入库、不进文档、不进交付包（已实测校验）。
