# 打包与分发（Windows 单文件 exe）

> 版本：v0.7.0 ｜ 更新：2026-11-12 ｜ 对应代码：`tools/build_exe.py`、`tools/verify_exe.py`、`packaging/entry_zx.py`、`app/paths.py`

这份文档回答三个问题：**为什么打包**、**打出来是什么**、**怎么证明它能用**。
所有体积、耗时、校验结果都是本机实测输出，不是估计。

---

## 1. 为什么要做成 exe

课程项目的交付对象是老师和同学，他们的电脑上不会有 Python 3.13、Node 22、也没有 `npm install` 过。
要求评审"先配环境再验收"等于把复现成本转嫁给验收方。

`dist/` 里的东西满足两条：

- **双击就能用**：`启动_知校.bat` → 3–5 秒后浏览器自动打开 `http://127.0.0.1:5000`
- **不写注册表、不装服务**：关掉窗口即停止，数据落在 exe 同级的 `data/`，删掉文件夹即卸载干净

源码方式仍然完整保留（`README.md` §快速开始）。exe 只是多给一条"零环境"的路径，不是替代品。

## 2. 交付目录结构

```
dist/
├── 知校校园政策助手.exe        103.0 MB  单文件，双击即用
├── data/
│   ├── app.db                 516 KB    演示库：18 份政策 / 122 片段 / 2 计划 / 11 任务
│   └── uploads/               20 个文件  政策原文（18 份在用 + 2 份软删除的异常样本）
├── 启动_知校.bat              起服务并自动打开浏览器
├── 启动_知校_不打开浏览器.bat  浏览器没弹出来时用，手动访问 127.0.0.1:5000
├── 重置演示数据.bat           旧库改名备份后重建一份干净演示数据
├── 查看_访问地址.bat          打印地址、账号、数据目录
└── 使用说明.txt               给拿到这个文件夹的人
```

结构参照已部署的「智能教室设备管控系统」（`D:\私人\学习\大三上\物联网应用软件开发\dist`）：
主 exe + `data/` + 若干中文 bat。bat 全部用 **GBK + CRLF** 写入，
因为中文 Windows 的 `cmd` 按 GBK 解释批处理文件，写成 UTF-8 会显示乱码。

## 3. 构建

```bash
cd frontend && npm run build          # 先出 dist，打包时被塞进 exe
cd .. && .venv\Scripts\python.exe tools\build_exe.py
```

实测输出：

```
[构建] PyInstaller 开始，首次约 2–4 分钟…
[构建] 完成，用时 41 s → D:\私人\学习\传智杯\dist\知校校园政策助手.exe
[构建] 体积 103.0 MB · sha256 25e84f0886b8e72c…
[交付] 已复制演示库 516 KB
[交付] 已复制上传件 20 个
[提示] 未复制 .env（避免把模型密钥打进可分发目录）。
```

> **sha256 每次构建都不一样**，这次是 `25e84f0886b8e72c…`（R3 重打包，含查询改写与会话持久化）。
>
> **R4 现役构建（2026-11-13 22:03）**：`d30cf5fbfee4c7ae…`，构建 43 s，体积仍 103.0 MB；三场景自检全过（A 自举 / B 带库 20 文档 122 片段 11 任务 / C 当服务 `/health` 18 份），交付目录前后逐项一致。上面那段 R3 输出按「历史实测不改写」保留原值。
>
> **R6 现役构建（2026-11-14 11:17，含 .env 向上查找与降级诊断）**：`f14bda81890d57a8…`，构建 **45 s**，体积仍 103.0 MB；交付库 20 文档 / **131 片段** / 11 任务，三场景自检全过（A 自举 / B 带库 18 份、登录与 401 正常 / C 当服务 5099，`/health` 18 份 131 片段、检索 `refused=False` 候选 9 条、补全 1 条），交付目录前后逐项一致。
> 这一版改了 `app/config.py`（`env_candidates()` 多路径 + `llm_config` 诊断）、`app/health.py`、`app/qa.py`、`frontend/src/App.vue`、`frontend/src/views/AskView.vue`、`frontend/src/api/client.ts`，并重建了前端产物。
> **关键行为变化**：exe 留在项目 `dist/` 时会**向上读取项目根的 `.env`**（`llm_mode=llm`，实测已复核），不再要求用户手动 `copy .env dist\.env`；而把 `dist/` 单独发给别人时仍会降级——那是设计，不是缺陷。
> 另：三个自检场景都跑在 `%TEMP%` 沙箱里（上一级没有 `server.py`），所以它们的日志写 `问答模式 degraded`，**这是预期**。
>
> **R5 收尾现役构建（2026-11-14 10:00，含降级指代兜底与两处初稿缺陷修正）**：`39be4c27576780c4…`，构建 35 s，体积仍 103.0 MB；交付库 20 文档 / **131 片段** / 11 任务，三场景自检全过（A 自举 / B 带库 18 份文档、登录与 401 拦截正常 / C 当服务 5099，`/health` 18 份 131 片段、检索 `refused=False` 候选 9 条、补全 1 条），交付目录前后逐项一致。这一版只改了 `app/rewrite.py`、`app/qa.py`、`app/anchors.py` 三个文件（B-11 降级兜底），前端无改动。
>
> **R5 构建（2026-11-14 01:22，含拒答进历史）**：`147ecc1c0cac2109…`，构建 42 s，体积 103.0 MB；交付库同上，三场景自检全过。
> 这一版之前先做了一次数据清理：`dedupe_conversations.py` 把探针留下的重复会话按标题去重（42 → 23 条），再 `VACUUM` 压缩（2164 → **1660 KB**）——交付库不该带着测试现场。R5 前跑过一次 `refresh_demo_library.py --prune-uploads`，清掉 68 个孤儿上传件（956 KB）——重建演示库会不断写新的物理文件，不清就会被打进交付包（§R.4.5）。
> PyInstaller 打进去的归档不是确定性产物，所以 sha 只能当"这一次验证的是哪个文件"的标记，
> 不能当稳定标识；要认产物，看体积（103.0 MB）+ 构建时间更实在。
> 更早的文档里若出现 `860672c3b53d131e…`（M7 那次），指的是当时那个包，不是笔误。

### 3.1 三条硬约束

| 约束 | 原因 | 做法 |
| --- | --- | --- |
| 资源与数据路径分开 | 单文件 exe 解压到 `%TEMP%\_MEIPASS`，退出即删。数据库若按 `__file__` 算，用户一关程序数据全没，而且**开发时完全看不出来** | `app/paths.py` 提供 `resource_root()`（`_MEIPASS`）与 `writable_root()`（exe 所在目录） |
| 构建全程只新建文件 | 本机沙箱对单轮批量删除有阈值，`--clean` 与"输出到已有目录"都会触发拦截 | 工作目录带时间戳（`.build/知校校园政策助手_HHMMSS`），产物复制到 `dist/` 而不是原地覆盖 |
| 不把密钥打进交付目录 | `dist/` 是准备发给别人的目录，密钥进去就等于泄露 | 构建脚本只提示，不自动复制 `.env` |

### 3.2 PyInstaller 参数要点

- `--onefile --console`：保留控制台。双击时能看到启动横幅与错误，比 `--windowed` 好排障
- `--add-data "frontend/dist;frontend/dist"`、`--add-data "demo;demo"`：Windows 用 `;` 分隔
- `--hidden-import` **由脚本扫目录生成**（`pkg_modules("app")`），不手写清单。
  手写清单一定会漂：`create_app()` 里的蓝图是函数内 import，漏一个就是"构建成功、双击报 ModuleNotFoundError"
- `--exclude-module` 排掉 numpy/pandas/matplotlib/PIL/tkinter，否则体积会翻倍

## 4. 怎么证明它能用

`tools/verify_exe.py` 不是"看退出码"，而是**在系统临时目录里真跑三次**：

| 场景 | 沙箱内容 | 断言 |
| --- | --- | --- |
| A 裸 exe | 只有 exe | 自建 13 张表、写 2 个账号、导入 18 份示例政策；`/api/v1/health`、`/`、登录、未授权 401 全部符合预期 |
| B 带库交付 | exe + `dist/data/` | 直接打开真实交付库（18 份政策 / 11 条任务）而不是空库 |
| C 当服务跑 | exe + `dist/data/`，`--port` 起在空闲端口 | **对着这个包**调 `/retrieval/search`，断言既不被拒答、又能看到 `via_neighbour=true` 的补全片段 |

> 场景 C 是 R2 补做时加的，起因很直白：A/B 只证明"启动成功、账号能登、库非空"，
> 而这三条断言在**改动前后的两个包上一模一样地通过**——旧包没有相邻片段补全，照样全绿。
> 要证明"发出去的这个包里有某项能力"，只能对着这个包把那个能力调一次。
> 这类"断言与改动无关"的自检，比没有自检更容易骗人。

为什要在临时目录里跑：数据库按设计落在 exe 同级 `data/`。在 `dist/` 里跑一次，
交付目录就会多出一份测试数据，"拷给老师的那份"就带着我的演示痕迹。
所以脚本跑完还会**逐项比对 `dist/` 前后是否一致**（文件集合与字节数），不一致直接判失败。

> 比对时**跳过 `app.db-shm` / `app.db-wal`**。只要进程以 WAL 方式打开过库，这两个附产物就会被
> 创建或改变大小，**哪怕全程只读**（自检要查交付库的 `count(*)`，必然打开）。把它们算进比对，
> 这条检查会变成随机失败：库本来带着 shm 时通过、删掉之后就失败。实测踩过一次——
> 手动删掉 `app.db-shm` 再跑，前后集合不一致，报"交付目录被污染"，而实际什么都没写。

实测结果：

```
[自检] 场景 A data/ → ['app.db-shm:32KB', 'app.db-wal:1814KB', 'app.db:4KB', 'uploads:8KB']
[自检] 场景 A：政策文件 18 份 · 建表 13 张 · 全部通过
[自检] 场景 B：政策文件 18 份 · 全部通过
[自检] 交付库 documents=20 chunks=122 tasks=11
[自检] 场景 C 当服务跑 · 端口 5099 · 沙箱 C:\...\Temp\zx_exe_feature_ix77636d
[自检] 场景 C /health → 18 份 / 122 片段
[自检] 场景 C 检索 → refused=False 候选 10 条 · 补全 2 条
[自检] 交付目录未被污染（前后逐项一致）
[自检] exe 三个场景均通过
```

### 4.1 三个只有真跑才会暴露的坑

1. **单文件 exe 是"启动器 + 子进程"两段式**。只 `kill()` 父进程会留下孤儿子进程，
   它占着 exe 映像与 SQLite 文件，沙箱删不掉。必须 `taskkill /F /T`。
2. **`taskkill` 在中文 Windows 上输出 GBK**。用 `subprocess.run(..., text=True)` 会按 UTF-8 解码，
   在 reader 线程里抛 `UnicodeDecodeError` —— 表现为"验证脚本崩了，但 exe 其实是好的"。
3. **WAL 模式让"看文件大小"变成假线索**。裸 exe 首次运行后 `app.db` 只有 4 KB，
   数据其实在 `app.db-wal`（816 KB）。判断"库有没有内容"必须开连接查 `count(*)`，不能看体积。

### 4.2 界面这一层，也要对着 exe 验一次

场景 C 调的是接口。接口返回 10 条候选，**不等于**用户打开页面能看见文件——
前端产物是构建时塞进 exe 的，如果 `frontend/dist` 比源码旧，页面照样是空的。
R2 的那次事故（列表页显示「文件（0）」）就属于这一层，而当时的 224 项测试 + 7 页巡检全绿。

所以交付前多做一步：把 `dist/` 拷进临时沙箱，用 exe 自己起服务，再对**这个 exe 的界面**跑一遍巡检。
已封装成一条命令（`tools/exe_ui_check.py`，内部就是"拷沙箱 → 挑空闲端口起 exe → 调 `browser_check`"）：

```bash
.venv\Scripts\python.exe tools\exe_ui_check.py
# 需要留存截图时：--keep-shots .workbuddy\shots-exe
```

实测（`dist` 当前这一版）：

```
[巡检] 登录页 ok · 角色卡片 2 · 底色 rgb(15, 17, 21)
[巡检] 工作台    ok · 文字   999 · 卡片  6 · 溢出 -10
[巡检] 智能问答   ok · 文字   682 · 溢出 -10
[巡检] 资格匹配   ok · 文字  1203 · 卡片  1 · 溢出 -10
[巡检] 计划与任务  ok · 文字  1179 · 卡片  2 · 溢出 -10
[巡检] 政策知识库  ok · 文字   883 · 卡片  1 · 溢出 -10
[巡检] 规则管理   ok · 文字   939 · 卡片  2 · 溢出 -10
[巡检] 备注
   - 知识库列表 10 行 / 标题「文件（18）」
[巡检] 全部通过
[界面] browser_check 退出码 0（0 = 全过）
```

> 为什么不做进 `tools/verify_exe.py`：巡检要 CDP 驱动系统 Edge，和"跑一次 HTTP"不是一类依赖。
> 单独一个脚本、由交付前执行一次，比把浏览器依赖塞进打包自检更划算。
> 关键是**这一条要写进清单**，否则"接口通了"很容易被当成"页面能看"。

配套还有一道构建期的闸：`tools/build_exe.py` 在打包前比较 `frontend/src/**` 与
`frontend/dist/index.html` 的修改时间，**src 更新则直接中止构建**（退出码 2）：

```
[构建] ⚠ 前端产物可能过期：src/ 最新改动比 dist/index.html 晚 <秒差> 秒
       先跑 cd frontend && npm run build，否则 exe 里是旧页面
       已中止。确认要用旧产物再打，请设 ZHIXIAO_ALLOW_STALE_DIST=1
```

理由同上：源码改了没重建，exe 里还是旧页面，而**所有接口断言都会通过**。
这条闸把"忘了 build"从"交付后才发现"提前到"打包时就拦下"。

## 5. 运行时参数

| 参数 | 作用 |
| --- | --- |
| （无参数） | 自举 + 起服务 + 自动打开浏览器 |
| `--no-browser` | 只起服务 |
| `--port 5001` | 换端口 |
| `--host 0.0.0.0` | 允许局域网访问（默认只绑 127.0.0.1） |
| `--reset` | 把现有数据库**改名备份**（不删除），再重建一份干净演示数据 |
| `--bootstrap` | 只做自举（建表 / 账号 / 示例政策） |
| `--selftest` | 起服务、打一遍 HTTP、打印结果并退出（供 `verify_exe.py` 用） |

## 6. 已知的边界（不粉饰）

| 项 | 实际情况 | 影响 |
| --- | --- | --- |
| 体积 103.0 MB | Python 运行时 + jieba 词典 + sqlalchemy 都在里面 | 微信/QQ 传文件没问题，邮件附件可能超限 |
| 首次启动 2–4 秒 | 单文件 exe 要先解压到临时目录 | 之后启动同样如此，属于 onefile 的固有代价 |
| 没有 `.env` 就是降级模式 | 只返回检索原文，不做归纳 | 界面顶部常驻一行说明。要用真实模型需把 `.env` 放到 exe 同级 |
| 杀软可能误报 | PyInstaller 单文件是"自我解压"行为，常被启发式规则盯上 | 加白名单即可；不用 onefile 可显著降低误报率（代价是变成一个文件夹） |
| 数据在 exe 同级 `data/` | 换一个目录运行就是另一套数据 | 想带走数据要连 `data/` 一起拷；只拷 exe 等于重装 |
| 只能 Windows | 未测 Linux/macOS 打包 | 课程交付环境为 Windows |
| 不签名 | 无代码签名证书 | 首次运行会有 SmartScreen 提示 |

这些条目同时登记在 `docs/60-交付/已知限制.md`（C-10 ~ C-12）。
