## 1. 这套系统现在能跑什么

必须先说清楚边界，避免复现者按"完整系统"的预期来验证：

| 能力 | 状态 | 验证方式 |
| --- | --- | --- |
| 后端启动、`/health` 返回真实状态 | ✅ 可用 | `curl /api/v1/health` |
| 登录、JWT、角色守卫 | ✅ 可用 | `curl -X POST /api/v1/auth/login` |
| 13 张表建表、SQLite 三 PRAGMA | ✅ 可用 | `tools/init_db.py` 输出 |
| 前端 7 个页面（登录/工作台/知识库/问答/匹配/计划/规则） | ✅ 可用（M5） | 打开 http://127.0.0.1:5173，学生与管理员各走一遍 |
| 政策上传（PDF/DOCX/TXT/MD） | ✅ 可用（M3） | 界面「政策知识库」或 `curl -F file=@...` |
| 解析：文本提取、魔数校验、扫描件识别 | ✅ 可用（M3） | 上传 5 份演示文件，看 `parse_status` |
| 结构化切分（章节 → 段落 → 句子） | ✅ 可用（M3） | `GET /documents/{id}/chunks` |
| BM25 建索引 + 检索 | ✅ 可用（M3 建、M4 开接口） | `POST /retrieval/search` 或 `tools/rebuild_index.py --probe "..."` |
| **政策问答（带编号引用、会拒答）** | ✅ 可用（M4） | 界面「AI 政策问答」或 `POST /qa/ask`（需配模型 Key） |
| **24 条 × 6 类评测集自动跑批** | ✅ 可用（M4） | `tools/run_eval.py` |
| **规则抽取 + 人工复核（契约四闸门）** | ✅ 可用（M5） | 界面「规则管理」或 `POST /documents/{id}/rules/extract` |
| **三态资格匹配（8 算子，不调模型）** | ✅ 可用（M5） | 界面「资格匹配」或 `POST /matches` |
| **计划草稿 → 确认 → 任务中心（状态机 + 溯源）** | ✅ 可用（M5） | 界面「计划与任务」或 `POST /plans/draft` |
| 工作流可视化（六节点状态面板） | ⬜ **未实现** | M6 |
| 答案反馈、任务统计、工作流轨迹 3 条接口 | ⬜ 未实现 | M6 |

> **特别注意（M4 起）**：问答之所以敢开放接口，是因为答案要过**三道闸**，而不是因为模型好用——
> ① 覆盖率闸门（确定性，不调模型，低于 `RAG_MIN_COVERAGE=0.35` 的片段不交给模型）；
> ② 模型自评 `sufficient`（模型说没依据就拒答，返回 `4001`）；
> ③ 引用越界剔除（确定性，答案里的每个 `[n]` 必须落在 `1..N` 内，一条有效引用都没有就走 `4003`）。
> 模型只看到 `[1]..[N]` 顺序编号，看不到 `chunk_id`，所以**编不出不存在的片段**。详见 `docs/90-AI协作留痕/06-M4问答可信.md`。
>
> **特别注意（M5 起）**：匹配之所以敢说"你符合/不符合"，是因为**它不调模型**——
> 8 种算子由 `app/matching.py:evaluate()` 确定性求值，同一画像同一规则永远同一结果；
> 且**只有已复核的规则参与匹配**，模型抽出的候选规则必须人点过"通过"才生效。
> 两条合起来意味着：系统里没有任何一句"我认为你符合条件"是模型说的。详见 `docs/90-AI协作留痕/07-M5闭环可演.md`。

## 2. 前置条件

| 依赖 | 版本要求 | 本机实测 | 检查命令 |
| --- | --- | --- | --- |
| Python | ≥ 3.11 | 3.13.14 | `python --version` |
| Node.js | ≥ 18 | 22.22.2 | `node --version` |
| npm | ≥ 9 | 11.19.0 | `npm --version` |
| Git | ≥ 2.30 | — | `git --version` |

不需要数据库服务，不需要 Docker。

**模型 Key 是可选的，但决定你能验到哪一步**（M4 起）：

| 你配了什么 | 能验证的能力 |
| --- | --- |
| 不配 `LLM_API_KEY` / `LLM_MODEL` | 上传、解析、切分、`/retrieval/search` 全部可用；`/qa/ask` 返回 `4006 DEGRADED_MODE`，`data.answer` 为空、`data.snippets` 给原文片段。**这不是故障**，是既定降级路径 |
| 配了 Key | 上面全部 + `/qa/ask` 返回带 `[n]` 编号引用的答案；库内没有的问题返回 `4001`；`tools/run_eval.py` 可跑评测集 |

> 注意顺序：**覆盖率闸门在降级判断之前**。所以没配 Key 时若问一个库里完全没有的问题，返回的是
> `4001`（证据不足）而不是 `4006`（降级）——因为"没有证据"这件事不需要模型也能判定。

配 Key 只需在 `.env` 写三行（`.env` 已被 `.gitignore` 忽略，**不要把 Key 写进 `.env.example` 或任何入库文件**，
`tests/test_security_scan.py` 会扫）：

```ini
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=sk-...          # 你自己的 Key
LLM_MODEL=deepseek-flash    # 用 GET {LLM_BASE_URL}/models 核对可用名称，别凭记忆填
```

## 3. 三条启动路径

### 3.1 一键脚本（推荐评审）

```bash
git clone https://github.com/liqing-258/campus-policy-planner.git
cd campus-policy-planner
scripts\setup.bat          # macOS/Linux：bash scripts/setup.sh
```

脚本按序执行 5 步，任一步失败即中止：

| 步骤 | 动作 | 失败时的常见原因 |
| --- | --- | --- |
| 1/5 | 建 `.venv` | `python` 不在 PATH |
| 2/5 | 装 `requirements.txt` | 网络不通（可加国内镜像） |
| 3/5 | 复制 `.env.example` → `.env` | 目标文件已存在则跳过 |
| 4/5 | `tools/init_db.py` 建表 | 磁盘权限不足 |
| 5/5 | `tools/seed_demo.py` 写演示账号 | 用户名冲突（加 `--reset`） |

然后两个终端分别启动：

```bash
scripts\start-backend.bat     # 后端 :5000
scripts\start-frontend.bat    # 前端 :5173
```

### 3.2 手动逐步（需要逐条核对时）

```bash
# ① 虚拟环境与依赖
python -m venv .venv
.venv\Scripts\activate                 # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

# ② 环境变量
copy .env.example .env                 # macOS/Linux: cp .env.example .env
python -c "import secrets;print(secrets.token_hex(32))"
# 把输出填进 .env 的 JWT_SECRET

# ③ 建表与演示数据
.venv\Scripts\python.exe tools\init_db.py
.venv\Scripts\python.exe tools\seed_demo.py

# ④ 自检（20 项）
.venv\Scripts\python.exe tools\selfcheck.py

# ④.5 生成 5 份虚构演示文件（M3 起需要）
.venv\Scripts\python.exe tools\make_demo_docs.py

# ④.6 传 5 份文件并核验解析结果（M3 起，可选但建议）
.venv\Scripts\python.exe tools\e2e_gate.py

# ④.7 跑 24 条评测集（M4 起，需先配好 LLM_*；约 40 秒，会真调模型）
.venv\Scripts\python.exe tools\run_eval.py

# ⑤ 启动
.venv\Scripts\python.exe server.py
```

**M5 起的额外一步**（只在已有旧库时需要）：`tasks` 表新增了 `note` 列，
`db.create_all()` 不会给已存在的表加列——

```bash
# 已有 data/app.db 且不想重建时手工补列（新环境从空库建表则跳过）
.venv\Scripts\python.exe -c "import sqlite3;c=sqlite3.connect('data/app.db');c.execute('ALTER TABLE tasks ADD COLUMN note VARCHAR(500)');c.commit();print('ok')"
```

> `source_rule_id`、`needs_human_confirmation`、`dependency_ids` 三列**v1.0 数据模型里就有**，
> M5 之前只是建了表从没写过值。所以旧库不用补这三列，需要补的只有 `note`。

**M5 的规则复核**（演示库要跑匹配，必须先有已复核规则）：

```bash
# 把演示库里的抽取结果整理成可演示状态：批准 10 条（含 2 条期望值修正）、拒绝 5 条（附理由）
.venv\Scripts\python.exe tools\review_demo_rules.py
```

另开终端：

```bash
cd frontend
npm install
npm run dev
```

### 3.3 分离端口（端口被占用时）

```bash
.venv\Scripts\python.exe server.py --port 5001
```

同时改 `frontend/vite.config.ts` 里 `proxy['/api'].target` 的端口，否则前端调不到后端。

三个字段的含义（M4 起细化，前两版只有 `degraded` / `disabled` 两种值）：

| 字段 | 可能值 | 怎么读 |
| --- | --- | --- |
| `llm_mode` | `llm` / `degraded` | `degraded` = 未配 Key 或只配了半套（有 key 无 model 也算），是**未配 Key 时的正确结果**，不是故障。前端据此顶部常驻黄色提示条 |
| `llm_model` | 模型名 / `null` | 直接回显 `LLM_MODEL`，用来一眼确认"我以为配了 flash，实际配的是什么" |
| `embedding_mode` | `bm25_only` / `vector` / `disabled` | M4 起如实报 `bm25_only`：**没有向量检索，不粉饰成 `hybrid`** |

> `version` 现在是 `0.4.0`（M2 时是 `0.2.0`）。这条值来自 `app/config.py` 的 `Settings.version`，
> 每次里程碑提升，避免出现"文档说 0.4、程序报 0.2"的对不上号。

### 4.7 文档入库（M3 核心链路）

用管理员令牌传 5 份演示文件，实测结果（`tools/e2e_gate.py` 的真实输出）：

| 文件 | HTTP | code | parse_status | 关键回执 |
| --- | --- | --- | --- | --- |
| 01 正常 PDF（4 页） | 201 | 0 | `indexed` | 切成 4 段，页码 1/2/3/4，202–264 字 |
| 02 正常 DOCX | 201 | 0 | `indexed` | 按 Heading 1 分节 |
| 03 扫描件 PDF | 201 | 0 | `empty` | `parse_hint`="共 1 页，仅提取到 0 个字符（平均每页 0.0 字），疑似扫描件。本系统不含 OCR，请上传带文本层的 PDF 或手工录入。" |
| 04 空文本 TXT | 201 | 0 | `empty` | `parse_hint`="仅提取到 0 个字符，低于有效阈值 50。" |
| 05 改名假文件 | 415 | 1005 | —（未落盘） | 扩展名 `.pdf` 但内容是 MZ 头，魔数校验在写盘前拦下 |

单条 `curl` 复现（第 1 条）：

```
$ curl -X POST http://127.0.0.1:5000/api/v1/documents \
    -H "Authorization: Bearer <TOKEN>" \
    -F "file=@demo/01-本科生奖学金评审办法（演示样例）.pdf" \
    -F "title=（演示样例）奖学金评审办法"
{"code":0,...,"data":{"id":"01M6X...","title":"（演示样例）奖学金评审办法",
 "parse_status":"indexed","chunk_count":4,"parse_error":null,"parse_hint":null,...}}
```

**为什么扫描件返回 201 而不是 4xx**：文件本身是合法的 PDF，系统也确实收下了（保留原件、可重新解析），
只是**没有可检索的文本**。这不是"请求错误"，是"内容不可用"，所以用 201 + `parse_status=empty` + 明确提示。
把这种情况报成 400 会让上传者以为文件坏了，而实际换一份带文本层的 PDF 就行——提示必须能指导行动。

### 4.8 索引与检索（M3 的"索引真的建成了"证据）

索引只在内存里，没有接口可看，所以必须用脚本证明它可用：

```
$ .venv\Scripts\python.exe tools\rebuild_index.py --probe "家庭经济困难认定需要什么材料"
[index] 片段数   10
[index] 词项数   255
[index] 平均词数 46.6
[index] 构建耗时 301.2 ms

[probe] 问题：家庭经济困难认定需要什么材料
  1. score=6.0058  coverage=0.8333 （演示样例）01-…pdf / 第4页 / 第四章 申请材料与附则
     命中词项：家庭、经济、困难、认定、材料
  2. score=6.8427  coverage=0.6667 （演示样例）01-…pdf / 第2页 / 第二章 申请条件
     命中词项：家庭、经济、困难、认定
  3. score=1.3542  coverage=0.1667 （演示样例）02-…docx / 无页码 / 三、材料要求
     命中词项：材料
```

**请重点看第 1、2 名的关系**：第 2 名分数更高（6.8427 > 6.0058），却排在第 1 名后面。
原因是它只覆盖了 4/6 个查询词，而第 1 名覆盖了 5/6——它撞上了更罕见的词（idf 高）所以分数虚高。
这就是排序用 `(coverage, score)` 而不是只看 `score` 的直接理由。

负向验证（知识库里没有的东西必须召不回来）：

```
$ .venv\Scripts\python.exe tools\rebuild_index.py --probe "食堂营业时间"
[probe] 问题：食堂营业时间
  （无命中——若知识库确实没有相关内容，这正是期望行为）

$ .venv\Scripts\python.exe tools\rebuild_index.py --probe "转专业流程"
1. score=2.396  coverage=0.5  …02-学生事务办理指南.docx / 无页码 / 二、办理流程
2. score=2.3005 coverage=0.5  …01-奖学金评审办法.pdf / 第2页 / 第二章 申请条件
3. score=1.2181 coverage=0.5  …01-奖学金评审办法.pdf / 第1页 / 第一章 总则
```

「转专业流程」召回 3 条全是 `coverage=0.5`。**V1.2 的本文曾在这里写"低于 0.6 会拒答"——
那句话是推断，实测后被推翻了**：M4 用 24 条数据把阈值定到 `0.35`，0.5 是**能过闸**的，
真正让它拒答的是模型自评 `sufficient=false`。订正记录见本节末尾。

> `build_ms=301.2` 里约九成是 jieba 首次加载词典，第二次构建通常在 10 ms 量级。
> 索引不落盘是刻意取舍：落盘会引入"索引与正文不一致"的坑，而重建成本很低。

#### 订正：阈值从 0.6 改到 0.35，以及"拒答到底靠谁"

M4 开发中用 24 条评测集扫了 5 个阈值（`tools/run_eval.py --sweep`），原始结果：

| `RAG_MIN_COVERAGE` | 总通过 | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0.00（关闸） | 22/24 (91.7%) | 4/4 | 4/4 | 3/4 | 4/4 | 4/4 | 3/4 |
| 0.15 | **24/24** | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| 0.25 | 23/24 (95.8%) | 4/4 | 4/4 | 3/4 | 4/4 | 4/4 | 4/4 |
| **0.35（采用）** | **24/24** | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| 0.50 | 22/24 (91.7%) | 4/4 | 4/4 | 3/4 | 4/4 | 3/4 | 4/4 |

两件事值得单独说：

1. **曲线不单调**（0.15 满分、0.25 掉一条、0.35 又满分），说明差异落在模型抖动范围内
   （`temperature=0.2` 也不是确定性的）。所以我**没有挑最高分的 0.15**——那等于把过拟合当成调优。
   选 0.35 的理由是它更保守、语义可解释（查询词覆盖到 1/3 以上）、且距 0.50（C、E 两类各掉一条）还留一档余量。
2. **B 类拒答在阈值 0 时也是 100%**。这条数据很关键：它说明**拒答主要靠模型，不靠覆盖率闸门**。
   闸门真正的作用是"过滤噪声候选 + 省一次模型调用"，所以它应该偏宽松，而不是被当成拒答主力。

这两条一起改了设计判断：把闸门当"粗筛"，拒答的最终裁决交给模型自评——这也解释了为什么
`RAG_MIN_COVERAGE` 从 M3 的 0.6 一路降到 0.35，看起来像"放松了标准"，实际是把职责放回了正确的地方。

`answer` 为 `null` 而不是空串——"没有生成答案"和"生成了一个空答案"是两件事，前端据此显示

#### 为什么 4001 / 4003 / 4006 都是 HTTP 200

这是本项目一条刻意的偏离（`接口清单.md` §7.1 有登记）。理由：

- 请求本身没问题（限流、鉴权、参数都合法），服务也确实**正常完成了判断**；
- 用 4xx 会让前端 `catch` 到一个"失败"，而"证据不足"是需要**好好展示**的业务结果（附候选、附建议）；
- 真正的基础设施错误（超时 4004、上游 4005、输出非法 4002）仍然走非 200，两者不混。

代价是：前端不能只判断 `resp.ok`，必须看 `code`。这一点在 `接口清单.md` §7.1 里写明了，
接前端时要按 `code ∈ {4001,4003,4006}` 走"业务态"分支。

#### 顺带修掉的一个真缺陷：重启后索引为空

M4 联调时发现：`/health` 报 `document_count=4, chunk_count=10`，`/qa/ask` 却答
「知识库为空：尚未上传任何已解析的政策文件」。原因是索引**只在内存里**，上传时才重建，进程一重启就空了。
更糟的是那句提示把人指向"去重新上传文件"这个错误方向。

已修：`app/indexing.py` 增加 `ensure_index_loaded()`，检索前发现索引为空就懒加载一次，
并用一个进程内标记保证"库确实是空的"时不会每次查询都扫表。回归测试见
`tests/test_indexing.py::test_index_is_lazily_loaded_after_process_restart`。

### 4.12 规则抽取（M5，真实调用模型）

复现方式（界面或命令行各一条，都真实调模型）：

```bash
# 命令行：换成自己的文档 ID 与管理员令牌
curl -X POST http://127.0.0.1:5000/api/v1/documents/<文档ID>/rules/extract ^
  -H "Content-Type: application/json" -H "Authorization: Bearer <ADMIN_TOKEN>" ^
  -d "{\"max_rules_per_chunk\":8}"
```

实测输出（2026-11-10，`deepseek-v4.1-flash`）：

```text
文档：01-本科生奖学金评审办法（演示样例）.pdf   片段 4
耗时 22.2 s   extracted=20  stored=20  dropped=0

文档：02-学生事务办理指南（演示样例）.pdf       片段 6
耗时  7.2 s   extracted=8   stored=8   dropped=0
```

两个真实观察：

| 观察 | 说明 |
| --- | --- |
| 4 片段比 6 片段慢 3 倍 | 不是片段数决定耗时，是**输出条数**（20 vs 8）。推理模型的 `reasoning_tokens` 与正文抢同一个 `max_tokens`，输出越长越慢 |
| 默认 2500 预算下，4 片段那份直接 `4002`（`reasoning_tokens=2500`、正文为空） | 抽取因此单独要预算 `max(llm_max_tokens, 6000)`。**不全局调大**：问答 2500 够用，全局调大等于每次问答都为长输出付费 |

抽取结果落库时**一律** `review_status=needs_review`。此时跑匹配会得到 `2008`：

```json
{ "code": 2008,
  "message": "该文件还没有已复核的可比对规则；请管理员先抽取并复核条件类规则",
  "data": { "document_id": "01J...", "approved_rules": 0, "total_rules": 20 } }
```

> 注意这是 **HTTP 200 + `code=2008`**。它不该出现在错误弹窗里——用户没做错任何事，
> 正确动作是"去复核规则"，前端应当渲染引导卡片而不是报错。这是 M5 新增的业务态码（见 `接口清单.md` §8.1）。

复核（`tools/review_demo_rules.py`）：

```
批准 10 条（其中 R-6 期望值由「是（经学校…认定）」改为 yes、R-7 由「无纪律处分记录」改为 none）
拒绝  5 条（R-1 适用范围不该让学生自述、R-8/R-9/R-10 属优秀学生奖学金条件、R-15 无可求值字段…）
失败  0 条
```

> 那两条期望值修正是 M5 最有价值的一次发现：模型抽的语义没错，
> 但 `equals` 拿「是（经学校家庭经济困难学生认定）」去比对用户填的 `yes` 永远不成立——
> **合规的学生会被判"不符合"**。这类错误只有人看得见，这正是复核环节存在的理由。

### 4.13 三态匹配（M5，不调模型）

`GET /tasks` 里每条都带 `source_rule_id`（非空）与 `note`——**溯源链在数据层有证据**，
不是只在前端拼了一句好话。

### 4.15 任务状态机（M5）

```
$ POST /tasks/<id>/status {"status":"doing"}  → 200  doing
$ POST /tasks/<id>/status {"status":"done"}   → 200  done，completed_at 写入
$ POST /tasks/<id>/status {"status":"doing"}  → 409  code=2005
   message: 当前状态 done 不允许转移到 doing（允许：todo）
$ POST /tasks/<id>/status {"status":"todo"}   → 200  todo，completed_at 清空
```

`done → doing` 被刻意禁止：允许它会让 `completed_at` 无法解释（先写了完成时间，再回 doing 时这个时间算什么）。

### 5.1 M3 阶段新增（解析/切分/索引相关）

| 现象 | 原因 | 处理 |

### 5.2 M4 阶段新增（模型接入 / 拒答 / 引用）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/qa/ask` 返回 `4002`，消息里带 `reasoning_tokens=…`、`正文为空` | 推理模型先花 `max_tokens` 预算"想"，想满了就没额度输出正文。**这是预算问题，不是模型认为没依据** | 调大 `LLM_MAX_TOKENS`（本项目实测要 2500；1200 时"需组合三处片段"的题会挂）。**别把 4002 当 4001 处理**，否则用户会被告知"没有依据"而真实原因是配置 |
| `HTTP 400 The supported API model names are …` | `LLM_MODEL` 填了不存在的名字（本项目就踩过：任务书给的 `deepseek-v4.1-flash` 在服务端不存在） | 先 `curl -H "Authorization: Bearer $KEY" {LLM_BASE_URL}/models` 核对，别凭记忆或凭文档填。本项目实际可用的是 `deepseek-flash` / `deepseek-v4-pro` |
| `/qa/ask` 报"知识库为空"，但 `/health` 显示 `document_count>0` | 索引在内存里，进程重启后为空（M4 已修：检索前懒加载一次） | 升级到 M4 代码即可；若仍复现，手动跑 `tools/rebuild_index.py` 看输出 |
| 追问"那成绩单要原件吗？"零命中，主问题却正常 | jieba 对同一个词在不同上下文切法不一致（「上一学年成绩单」切出`学年成绩`，「成绩单」切出`成绩单`），词项交集为空 | M4 已加字符 bigram 兜底。若仍零命中，用 `python -c "from app.indexing import tokenize;print(tokenize('…'))"` 对比两侧切分 |
| 答案看起来对，但引用编号指到了不相关的片段 | 模型给的是 `[1]..[N]` 顺序编号，不是 `chunk_id`；编号与候选的顺序由服务端决定 | 拿响应里的 `citations[i]` 看 `snippet` 是否真的支撑那句话。**不要只看编号对不对**——越界能机器拦，"指对了编号但内容不支持"只能人工核 |
| 前端处理 4001 时弹了"请求失败" | 业务态返回 HTTP 200 + `code=4001`，前端若只看 `resp.ok` 就会漏 | 按 `code ∈ {4001,4003,4006}` 走业务分支；详见 `接口清单.md` §7.1 |
| `tools/run_eval.py` 一条能跑一分多钟、偶尔抖动一条 | 每条都要真调模型（含推理 token），且 `temperature=0.2` 也不是确定性的 | 正常。判断"改坏了没有"看 24 条的整体通过数，不要盯单条；`--sweep` 扫阈值更耗时间，一次约 3–4 分钟 |

### 5.3 M5 阶段新增（规则抽取 / 匹配 / 计划 / 任务）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 抽取报 `4002`，`reasoning_tokens` 等于 `max_tokens`、正文为空 | 抽取是**长输出**任务（一次 8–30 条规则），推理模型的思考过程先吃掉同一个预算 | 抽取已单独申请 `max(llm_max_tokens, 6000)`。若仍复现，说明该文档片段太长、输出条数更多，把 `max_rules_per_chunk` 调小后分次抽 |
| 抽取返回 200 但 `dropped` 里有一堆规则 | 四个契约闸门在过滤：引用不是片段子串、算子不在白名单、`field_key` 不在画像白名单、`chunk_index` 越界 | **这是设计行为**。看 `dropped[].reason` 逐条判断是模型编造还是 Prompt 需要收窄；不要为了让数字好看把它们塞回去 |
| 匹配返回 `2008` | 该文档下没有 `approved` 的条件规则（抽取结果默认是 `needs_review`） | 去「规则管理」复核，或在演示库跑 `tools/review_demo_rules.py` |
| 匹配 500，日志里 `FOREIGN KEY constraint failed` | `MatchSession` 与 `MatchResultItem` 之间**没有 ORM relationship**，SQLAlchemy 的 flush 排序不保证父行先写 | 已在 `app/matching.py` 里 `db.session.add(session)` 后显式 `db.session.flush()`。**不要删那一行**——删掉后单条写入偶发不报错，批量时必挂，最难查 |
| 确认计划后任务建好了，但提示语（"为什么没有日期"）是空的 | 旧库缺 `tasks.note` 列，`db.create_all()` 不给已存在的表加列 | 见 §3.2 的 `ALTER TABLE tasks ADD COLUMN note VARCHAR(500)` |
| 创建任务返回 500，日志 `did not return a valid response … but it was a tuple` | `ok()` 本身返回 `(Response, 200)`，再写 `return ok(x), 201` 就套成了两层 tuple | 用 `ok(x, http_status=201)`。已在 `app/tasks.py` 修正 |
| 任务流转 `done → doing` 返回 409，以为坏了 | 这是**刻意禁止**：允许它会让 `completed_at` 无法解释 | 要重做先回 `todo`（允许），再 `doing` |
| 前端点上传没反应 | 同一个 `ref` 绑了两个 `<input>`，`$refs` 指向后一个（无 `@change`） | 只保留一个 input，用按钮触发 `fileInput?.click()` |
| 用 `urllib` 请求 `127.0.0.1:5000` 拿到 502 | 本机设了 `HTTP_PROXY`，`urllib` 把本地请求也发给代理 | 用 `httpx.Client(trust_env=False)`，或脚本里 `no_proxy=127.0.0.1,localhost` |
| 界面 6 个页面里只有登录页能进，其他被弹回工作台 | 路由守卫在首次导航就跑，而 `restore()` 要等 App 挂载；`localStorage` 里没有 `zxx_user` 时守卫读到 `user=null` | 已把用户信息一并持久化到 `localStorage.zxx_user`。清一下浏览器缓存重新登录即可 |
