## 1. 这套系统现在能跑什么

必须先说清楚边界，避免复现者按"完整系统"的预期来验证：

| 能力 | 状态 | 验证方式 |
| --- | --- | --- |
| 后端启动、`/health` 返回真实状态 | ✅ 可用 | `curl /api/v1/health` |
| 登录、JWT、角色守卫 | ✅ 可用 | `curl -X POST /api/v1/auth/login` |
| 13 张表建表、SQLite 三 PRAGMA | ✅ 可用 | `tools/init_db.py` 输出 |
| 前端登录页、工作台、降级提示条 | ✅ 可用 | 打开 http://127.0.0.1:5173 |
| 政策上传（PDF/DOCX/TXT/MD） | ✅ 可用（M3） | `curl -F file=@...` 或 `tools/e2e_gate.py` |
| 解析：文本提取、魔数校验、扫描件识别 | ✅ 可用（M3） | 上传 5 份演示文件，看 `parse_status` |
| 结构化切分（章节 → 段落 → 句子） | ✅ 可用（M3） | `GET /documents/{id}/chunks` |
| BM25 建索引 + 检索 | ✅ 可用（M3 建、M4 开接口） | `POST /retrieval/search` 或 `tools/rebuild_index.py --probe "..."` |
| **政策问答（带编号引用、会拒答）** | ✅ 可用（M4） | `POST /qa/ask`（需配模型 Key） |
| **24 条 × 6 类评测集自动跑批** | ✅ 可用（M4） | `tools/run_eval.py` |
| **政策知识库前端页面（问答界面）** | ⬜ **未实现** | 随 M5 界面一起做 |
| 匹配 / 计划 / 任务 | ⬜ 未实现 | M5–M6 |

> **特别注意（M4 起）**：问答之所以敢开放接口，是因为答案要过**三道闸**，而不是因为模型好用——
> ① 覆盖率闸门（确定性，不调模型，低于 `RAG_MIN_COVERAGE=0.35` 的片段不交给模型）；
> ② 模型自评 `sufficient`（模型说没依据就拒答，返回 `4001`）；
> ③ 引用越界剔除（确定性，答案里的每个 `[n]` 必须落在 `1..N` 内，一条有效引用都没有就走 `4003`）。
> 模型只看到 `[1]..[N]` 顺序编号，看不到 `chunk_id`，所以**编不出不存在的片段**。详见 `docs/90-AI协作留痕/06-M4问答可信.md`。

## 2. 前置条件

| 依赖 | 版本要求 | 本机实测 | 检查命令 |
| --- | --- | --- | --- |
| Python | ≥ 3.11 | 3.13.14 | `python --version` |
| Node.js | ≥ 18 | 22.22.2 | `node --version` |
| npm | ≥ 9 | 11.19.0 | `npm --version` |
| Git | ≥ 2.30 | — | `git --version` |

不需要数据库服务，不需要 Docker。

**模型 Key 是可选的，但决定你能验到哪一步**（M4 起）：

| 你配了什么 | 能验证的能力 |
| --- | --- |
| 不配 `LLM_API_KEY` / `LLM_MODEL` | 上传、解析、切分、`/retrieval/search` 全部可用；`/qa/ask` 返回 `4006 DEGRADED_MODE`，`data.answer` 为空、`data.snippets` 给原文片段。**这不是故障**，是既定降级路径 |
| 配了 Key | 上面全部 + `/qa/ask` 返回带 `[n]` 编号引用的答案；库内没有的问题返回 `4001`；`tools/run_eval.py` 可跑评测集 |

> 注意顺序：**覆盖率闸门在降级判断之前**。所以没配 Key 时若问一个库里完全没有的问题，返回的是
> `4001`（证据不足）而不是 `4006`（降级）——因为"没有证据"这件事不需要模型也能判定。

配 Key 只需在 `.env` 写三行（`.env` 已被 `.gitignore` 忽略，**不要把 Key 写进 `.env.example` 或任何入库文件**，
`tests/test_security_scan.py` 会扫）：

```ini
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=sk-...          # 你自己的 Key
LLM_MODEL=deepseek-flash    # 用 GET {LLM_BASE_URL}/models 核对可用名称，别凭记忆填
```

## 3. 三条启动路径

### 3.1 一键脚本（推荐评审）

```bash
git clone https://github.com/liqing-258/campus-policy-planner.git
cd campus-policy-planner
scripts\setup.bat          # macOS/Linux：bash scripts/setup.sh
```

脚本按序执行 5 步，任一步失败即中止：

| 步骤 | 动作 | 失败时的常见原因 |
| --- | --- | --- |
| 1/5 | 建 `.venv` | `python` 不在 PATH |
| 2/5 | 装 `requirements.txt` | 网络不通（可加国内镜像） |
| 3/5 | 复制 `.env.example` → `.env` | 目标文件已存在则跳过 |
| 4/5 | `tools/init_db.py` 建表 | 磁盘权限不足 |
| 5/5 | `tools/seed_demo.py` 写演示账号 | 用户名冲突（加 `--reset`） |

然后两个终端分别启动：

```bash
scripts\start-backend.bat     # 后端 :5000
scripts\start-frontend.bat    # 前端 :5173
```

### 3.2 手动逐步（需要逐条核对时）

```bash
# ① 虚拟环境与依赖
python -m venv .venv
.venv\Scripts\activate                 # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

# ② 环境变量
copy .env.example .env                 # macOS/Linux: cp .env.example .env
python -c "import secrets;print(secrets.token_hex(32))"
# 把输出填进 .env 的 JWT_SECRET

# ③ 建表与演示数据
.venv\Scripts\python.exe tools\init_db.py
.venv\Scripts\python.exe tools\seed_demo.py

# ④ 自检（20 项）
.venv\Scripts\python.exe tools\selfcheck.py

# ④.5 生成 5 份虚构演示文件（M3 起需要）
.venv\Scripts\python.exe tools\make_demo_docs.py

# ④.6 传 5 份文件并核验解析结果（M3 起，可选但建议）
.venv\Scripts\python.exe tools\e2e_gate.py

# ④.7 跑 24 条评测集（M4 起，需先配好 LLM_*；约 40 秒，会真调模型）
.venv\Scripts\python.exe tools\run_eval.py

# ⑤ 启动
.venv\Scripts\python.exe server.py
```

另开终端：

```bash
cd frontend
npm install
npm run dev
```

### 3.3 分离端口（端口被占用时）

```bash
.venv\Scripts\python.exe server.py --port 5001
```

同时改 `frontend/vite.config.ts` 里 `proxy['/api'].target` 的端口，否则前端调不到后端。

```

{"code":0,"message":"success","data":{"status":"ok","version":"0.4.0","env":"dev",
```

三个字段的含义（M4 起细化，前两版只有 `degraded` / `disabled` 两种值）：

| 字段 | 可能值 | 怎么读 |
| --- | --- | --- |
| `llm_mode` | `llm` / `degraded` | `degraded` = 未配 Key 或只配了半套（有 key 无 model 也算），是**未配 Key 时的正确结果**，不是故障。前端据此顶部常驻黄色提示条 |
| `llm_model` | 模型名 / `null` | 直接回显 `LLM_MODEL`，用来一眼确认"我以为配了 flash，实际配的是什么" |
| `embedding_mode` | `bm25_only` / `vector` / `disabled` | M4 起如实报 `bm25_only`：**没有向量检索，不粉饰成 `hybrid`** |

> `version` 现在是 `0.4.0`（M2 时是 `0.2.0`）。这条值来自 `app/config.py` 的 `Settings.version`，
> 每次里程碑提升，避免出现"文档说 0.4、程序报 0.2"的对不上号。

### 4.7 文档入库（M3 核心链路）

用管理员令牌传 5 份演示文件，实测结果（`tools/e2e_gate.py` 的真实输出）：

| 文件 | HTTP | code | parse_status | 关键回执 |
| --- | --- | --- | --- | --- |
| 01 正常 PDF（4 页） | 201 | 0 | `indexed` | 切成 4 段，页码 1/2/3/4，202–264 字 |
| 02 正常 DOCX | 201 | 0 | `indexed` | 按 Heading 1 分节 |
| 03 扫描件 PDF | 201 | 0 | `empty` | `parse_hint`="共 1 页，仅提取到 0 个字符（平均每页 0.0 字），疑似扫描件。本系统不含 OCR，请上传带文本层的 PDF 或手工录入。" |
| 04 空文本 TXT | 201 | 0 | `empty` | `parse_hint`="仅提取到 0 个字符，低于有效阈值 50。" |
| 05 改名假文件 | 415 | 1005 | —（未落盘） | 扩展名 `.pdf` 但内容是 MZ 头，魔数校验在写盘前拦下 |

单条 `curl` 复现（第 1 条）：

```
$ curl -X POST http://127.0.0.1:5000/api/v1/documents \
    -H "Authorization: Bearer <TOKEN>" \
    -F "file=@demo/01-本科生奖学金评审办法（演示样例）.pdf" \
    -F "title=（演示样例）奖学金评审办法"
{"code":0,...,"data":{"id":"01M6X...","title":"（演示样例）奖学金评审办法",
 "parse_status":"indexed","chunk_count":4,"parse_error":null,"parse_hint":null,...}}
```

**为什么扫描件返回 201 而不是 4xx**：文件本身是合法的 PDF，系统也确实收下了（保留原件、可重新解析），
只是**没有可检索的文本**。这不是"请求错误"，是"内容不可用"，所以用 201 + `parse_status=empty` + 明确提示。
把这种情况报成 400 会让上传者以为文件坏了，而实际换一份带文本层的 PDF 就行——提示必须能指导行动。

「转专业流程」召回 3 条全是 `coverage=0.5`。**V1.2 的本文曾在这里写"低于 0.6 会拒答"——
那句话是推断，实测后被推翻了**：M4 用 24 条数据把阈值定到 `0.35`，0.5 是**能过闸**的，
真正让它拒答的是模型自评 `sufficient=false`。订正记录见本节末尾。

> `build_ms=301.2` 里约九成是 jieba 首次加载词典，第二次构建通常在 10 ms 量级。
> 索引不落盘是刻意取舍：落盘会引入"索引与正文不一致"的坑，而重建成本很低。

#### 订正：阈值从 0.6 改到 0.35，以及"拒答到底靠谁"

M4 开发中用 24 条评测集扫了 5 个阈值（`tools/run_eval.py --sweep`），原始结果：

| `RAG_MIN_COVERAGE` | 总通过 | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0.00（关闸） | 22/24 (91.7%) | 4/4 | 4/4 | 3/4 | 4/4 | 4/4 | 3/4 |
| 0.15 | **24/24** | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| 0.25 | 23/24 (95.8%) | 4/4 | 4/4 | 3/4 | 4/4 | 4/4 | 4/4 |
| **0.35（采用）** | **24/24** | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |
| 0.50 | 22/24 (91.7%) | 4/4 | 4/4 | 3/4 | 4/4 | 3/4 | 4/4 |

两件事值得单独说：

1. **曲线不单调**（0.15 满分、0.25 掉一条、0.35 又满分），说明差异落在模型抖动范围内
   （`temperature=0.2` 也不是确定性的）。所以我**没有挑最高分的 0.15**——那等于把过拟合当成调优。
   选 0.35 的理由是它更保守、语义可解释（查询词覆盖到 1/3 以上）、且距 0.50（C、E 两类各掉一条）还留一档余量。
2. **B 类拒答在阈值 0 时也是 100%**。这条数据很关键：它说明**拒答主要靠模型，不靠覆盖率闸门**。
   闸门真正的作用是"过滤噪声候选 + 省一次模型调用"，所以它应该偏宽松，而不是被当成拒答主力。

这两条一起改了设计判断：把闸门当"粗筛"，拒答的最终裁决交给模型自评——这也解释了为什么
`RAG_MIN_COVERAGE` 从 M3 的 0.6 一路降到 0.35，看起来像"放松了标准"，实际是把职责放回了正确的地方。

`answer` 为 `null` 而不是空串——"没有生成答案"和"生成了一个空答案"是两件事，前端据此显示

#### 为什么 4001 / 4003 / 4006 都是 HTTP 200

这是本项目一条刻意的偏离（`接口清单.md` §7.1 有登记）。理由：

- 请求本身没问题（限流、鉴权、参数都合法），服务也确实**正常完成了判断**；
- 用 4xx 会让前端 `catch` 到一个"失败"，而"证据不足"是需要**好好展示**的业务结果（附候选、附建议）；
- 真正的基础设施错误（超时 4004、上游 4005、输出非法 4002）仍然走非 200，两者不混。

代价是：前端不能只判断 `resp.ok`，必须看 `code`。这一点在 `接口清单.md` §7.1 里写明了，
接前端时要按 `code ∈ {4001,4003,4006}` 走"业务态"分支。

#### 顺带修掉的一个真缺陷：重启后索引为空

M4 联调时发现：`/health` 报 `document_count=4, chunk_count=10`，`/qa/ask` 却答
「知识库为空：尚未上传任何已解析的政策文件」。原因是索引**只在内存里**，上传时才重建，进程一重启就空了。
更糟的是那句提示把人指向"去重新上传文件"这个错误方向。

已修：`app/indexing.py` 增加 `ensure_index_loaded()`，检索前发现索引为空就懒加载一次，
并用一个进程内标记保证"库确实是空的"时不会每次查询都扫表。回归测试见
`tests/test_indexing.py::test_index_is_lazily_loaded_after_process_restart`。

### 5.1 M3 阶段新增（解析/切分/索引相关）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 上传正常 PDF，`parse_status` 却是 `failed` | 极可能是解析器内部异常（M3 开发期真踩到过：参数改名后函数体没跟着改，抛 `NameError`，所有 PDF 全挂） | 先看 `parse_error`，M3 起错误信息已带异常类型与内容，如 `解析过程出现未预期错误（NameError: name 'page' is not defined）`。**不要只看"failed"就猜是文件问题** |
| 上传 `.pdf` 返回 415 / `code=1005` | 扩展名是 PDF 但文件头不是 `%PDF-`（改名的可执行文件等） | 这是设计行为。用 `head -c 4 文件 \| od -An -tx1` 确认真实格式 |

| DOCX 整篇只切出 1 个片段 | `min_section_chars` 太大，小章节被全并 | 已从 120 降到 40。若文档本身极短（<100 字），1 个片段是正确结果 |
| `tools/rebuild_index.py` 首次跑要 300 ms 以上 | jieba 首次加载词典（约 0.25 s），与索引规模无关 | 正常。第二次构建通常 <20 ms |

### 5.2 M4 阶段新增（模型接入 / 拒答 / 引用）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/qa/ask` 返回 `4002`，消息里带 `reasoning_tokens=…`、`正文为空` | 推理模型先花 `max_tokens` 预算"想"，想满了就没额度输出正文。**这是预算问题，不是模型认为没依据** | 调大 `LLM_MAX_TOKENS`（本项目实测要 2500；1200 时"需组合三处片段"的题会挂）。**别把 4002 当 4001 处理**，否则用户会被告知"没有依据"而真实原因是配置 |

## 8. 与文档不一致时的处理原则

如果本文与实际行为不符，**以代码为准，并立即修改本文**。
