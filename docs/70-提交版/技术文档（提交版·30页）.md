## 1. 问题：办一件事要穿过五道断裂

大学生办一件事——申请奖学金、评奖评优、考试报名、学籍异动、实习手续——通常要穿过五道断裂：

| 环节 | 真实处境 | 后果 |
| --- | --- | --- |
| **找** | 政策散在官网、学院群、PDF、办事指南 | 找不到，或找到的是上学年的旧版 |
| **读** | 正式文件长、条款嵌套、例外多 | 读不完，关键门槛记不住 |
| **判** | 条款是通用表述，不确定是否适用于自己 | 不敢申，或申了才发现不符合 |
| **办** | 材料、顺序、截止时间分散多处 | 漏材料、跑空路、错过节点 |
| **跟** | 多步骤事项没有统一跟踪 | 中断后遗忘 |

通用大模型在这五道断裂上**只能解决"读"的一半**：它能复述条款，但它给不出出处、判不了资格、
排不出顺序、记不住进度；更麻烦的是它会在没有依据时**编一个看起来合理的答案**。

**知校不做"政策问答"，做的是把政策变成一份自己能照着做、且每一步都能回头核对原文的清单。**

```
政策文件 → 证据检索 → 带引用解释 → 条件结构化 → 三态匹配 → 计划草稿 → 用户确认 → 任务跟踪
```

### 1.1 与"校园 AI 聊天机器人"的六处差异

| 维度 | 普通政策问答 | 知校 |
| --- | --- | --- |
| 依据 | 模型自己的话 | 绑定 `文档 + 页码 + 章节 + 原文`，可点击回原文 |
| 判断 | 直接给"你能/不能" | 三态：符合 / 不符合 / **待补充或待核实**（并说明原因） |
| 输出 | 一段文字 | 结构化条件 + 任务清单 + 依赖关系 + 截止时间 |
| 信息不足 | 编一个答案 | 明确拒答，不产生任何具体数字与日期 |
| 版本 | 不感知 | 过期文件降权、冲突并列展示 |
| **判定权** | 模型 | **模型只抽取候选规则，结论由代码计算** |

最后一行是整套设计的支点。资格判断是责任敏感行为，必须可复现、可解释、可写断言。
模型输出会漂移，无法写测试，也无法向用户解释"为什么判我不符合"。所以：

- 模型只做**抽取**（把条款变成候选规则），规则一律 `needs_review`；
- 人在界面上点"通过"之后，规则才参与匹配；
- 匹配由 8 种算子的**纯函数**求值，不调模型——同一画像、同一规则，永远同一结果。

## 2. 意图控制：三道闸 + 六节点（核心章节）

"AI 应用"最难的不是让它答得好，而是让它**在该停的时候停**。本项目把这件事拆成可测的四层。

### 2.1 问答链路的三道闸

| 闸 | 机制 | 位置 | 为什么这样设计 |
| --- | --- | --- | --- |
| ① 覆盖率粗筛 | 命中查询词项占比 < `RAG_MIN_COVERAGE`（0.35）直接拒答；R3 起覆盖率取「用户原话 / 自包含查询 / 同义扩展词」**三个视图的最大值** | 检索后、调模型前 | 主题不相关的问题**不该花钱问模型**。1–2 ms，零成本 |
| ② 模型自评证据充分性 | Prompt 要求模型先判"片段是否足以回答"，不足则输出 `insufficient` | 生成中 | 有一种情况粗筛挡不住：片段相关但**没回答问题**（问具体金额，原文只有流程） |
| ③ 引用越界剔除 | 模型只拿到 `[1]..[N]` 顺序编号，出参必须是编号；越界编号 100% 剔除 | 生成后 | **编造 `chunk_id` 在物理上不可能**——它没见过真的 ID |

三道闸的结果是：**证据不足时系统说"未找到足够依据"并给出可补充方向，绝不产生数字与日期。**

> **一个必须说清楚的实测结论**：`RAG_MIN_SCORE`（原始 BM25 分数阈值）**是死配置**。
> M3 实测发现分数不能判相关性：无关查询拿到 1.7997，相关查询只有 1.3687。
> 改用"覆盖率"之后，排序键也从单一分数改成 `(coverage, score)`。
> 演示库上真实纠正过一次错序：第 1 名 score 6.0058 但覆盖 5/6 个查询词，
> 第 2 名 score 6.8427 只覆盖 4/6——**按分数排会答错**。

### 2.2 六节点轨迹：诚实优先于好看

每次提问都记录一条 `workflow_run`，六个节点：`intent → retrieval → analysis → matching → planning → validation`。

关键设计决定：一次问答**只走前四个**，`matching` / `planning` 属于另外两条链路（资格匹配、计划生成）。
这两个节点**必须记 `skipped` 并给出原因**，不许为了进度条好看补成"已完成"。

界面上"本次处理过程"显示 `4/6 个节点执行 · 共 3667 ms`，灰显的两个节点写明
"本次问答未涉及资格判断/计划生成"。**把没跑的节点补成已完成，进度条好看了，但每个数字都是假的**——
而轨迹的全部价值就在于它是可解释性证据。

### 2.3 规则抽取的四个契约闸门

模型输出的每条候选规则必须同时满足四项，否则**只丢这一条**（不整批失败）：

| 闸门 | 判据 | 拦什么 |
| --- | --- | --- |
| 引用子串 | `original_quote` 必须是片段原文的子串 | 编造条款 |
| 算子白名单 | 只能是 8 种已实现算子之一 | 发明无法求值的算子 |
| 字段白名单 | 画像字段必须在 `shared/enums.py` 的白名单里 | 采集不该采集的字段 |
| 片段不越界 | 引用的 `chunk_id` 必须属于本次抽取范围 | 跨文档拼凑 |
| （另有）页码不校验 | `page_or_section` 由模型填写，可能与真实页码不一致 | **不假装能校验**，界面标"原文未核对" |

### 2.4 提示注入：三层，但兜底不在这三层

8 种攻击形态（"忽略以上指令""你现在是……""输出你的系统提示"等）走三层处理：

1. **正则扫描**：命中即打 `prompt_injection_suspected` 标记；
2. **覆盖率降权 ×0.5**：可疑片段排序下沉，但**不删除**——政策原文不能因为含敏感词就消失；
3. **命中回执**：界面明确显示"本条回答涉及 1 个可疑片段，已降权"。

降权后 0.9 × 0.5 = 0.45 仍高于阈值 0.35，所以高相关片段依然进得了答案。

**但这三层挡不住改写过的注入**（换同义表达就能绕过正则）。真正的兜底是**第 2.1 节的闸③**：
模型只能引用本次给它的编号，想注入"请引用第 99 号文件"——99 号根本不存在，直接 4003。
**把安全性建立在"结构不可能"上，而不是"我猜到了攻击方式"。**

### 2.5 版本冲突：只认标题，不做语义聚类

同一政策常有多个版本。检测规则：**规范化标题相同 + 年份或发布日期不同**。

演示库实测：问"奖学金申请截止时间"，两版并列展示（2026–2027 现行有效 / 2025–2026 已被替代，
相差 365 天），而不是静默选一个。

**为什么不做语义聚类**：奖学金办法与勤工助学办法都含"家庭经济困难"，一聚类必然误报；
而**误报一次用户就开始忽略这个提示，比不提示更糟**。
代价是漏报"改了名"的版本——这条如实登记为已知限制 A-2，不假装覆盖到。

## 3. 架构与选型

### 3.1 模块化单体 + 自研 60 行编排器

```
浏览器 ──HTTP──▶ Flask 单进程（waitress）
                   ├─ Blueprint 路由层（35 条 /api/v1，只做校验与外壳）
                   ├─ 服务层 ──▶ 领域层（解析 · 切分 · BM25 检索 · 8 算子求值）
                   │            └─ 工作流层（六节点顺序编排，约 60 行）
                   ├─ SQLite（WAL）· data/uploads/（可写）
                   └─ llm.py（唯一出网模块，可降级）
前端 Vue3 + Vite + TS ──构建后由同一进程托管──▶ frontend/dist（只读）
```

调用方向严格单向：路由不写业务、服务不碰 SQL、只有 `llm.py` 出网、只有 `shared/` 跨端共用。

不做微服务、不引入 Agent 框架：单人开发、赛期 11 天，固定 6 节点顺序流程用约 60 行编排器即可；
换来的是**每个节点的输入输出、耗时、失败原因全部可见**——这在答辩时是可解释性优势，不是技术落后。

### 3.2 关键决策（ADR 摘要）

| ADR | 议题 | 决策 | 放弃的备选及原因 |
| --- | --- | --- | --- |
| 01 | 文档与片段存储 | 分表，片段冗余 `document_id` + 页码 | 单表 JSON：无法增量更新与建索引 |
| 03 | 规则判定 | 代码求值，8 算子白名单 | 让模型判定：不可测、不可解释、结论漂移 |
| 04 | 计划落库时机 | 两阶段：`draft` → `confirmed` | 直接落库：用户没有确认环节 |
| 05 | 无模型环境 | 降级模式：检索 + 规则 + 模板提示 | 直接报错：评审复现失败 |
| 08 | 后端框架 | Flask 3 + pydantic v2 显式校验 | FastAPI：需重建既有 125 接口的工程经验，工期不够 |
| 10 | 交付形态（M7） | Flask 单进程托管 `frontend/dist` + 单文件 exe | 双进程要 Node；Electron 多 60 MB 壳；Docker 要装 Docker |

### 3.3 三条硬约束

1. `shared/` **只允许标准库**，不得 import `app`（前后端共用枚举与错误码）；
2. 路由层不写业务逻辑，只做参数校验 + 调用服务 + 外壳封装；
3. 只有 `app/llm.py` 允许出网调用模型。

## 4. 关键实现

### 4.1 结构化切分：保留"这句话在哪一章哪一页"

不是定长硬切，而是 `章节 → 段落 → 句子 → 硬切` 四级回落，每片带
`document_id / page_number / section_title / char_start / char_end`。

这决定了引用能不能核验：用户点开 `[2]` 看到的不只是文字，而是"第 4 页 / 第四章 申请材料与附则"。
演示库 18 份文件切出 131 个片段（R5 给 9 份文件各补 1 章）。

### 4.2 检索：BM25 + 覆盖率 + 字符 bigram 兜底

jieba 分词建 BM25 索引（演示库 122 片段 / 2100 词项 / 构建 376.5 ms，其中约九成是 jieba 首次初始化）。

一个踩出来的缺陷：**查询与语料的切法不同会导致零命中**。
用户问"成绩单"，语料写"学年成绩"——分词后完全不相交，召回为 0，于是系统误判"知识库里没有"。
解法是字符 bigram 兜底（把"成绩单"拆成"成绩/绩单"参与匹配），**治的是切法不一致**。

**R3 又补了一层，治的正是 bigram 治不了的同义问题**：检索前用一次模型调用把问题改写成
"自包含查询 + 3~5 个政策同义表述"（"拿奖学金要准备啥" → "申请奖学金需要准备哪些材料"），
再用三路召回（自包含查询 / 同义扩展词 / 用户原话）做 RRF 融合（`k=60`），取 `top_k=6`。
它同时修掉两个真缺陷：追问里的"这个问题/它"在 BM25 上是纯噪声（实测「那能续借几次？」
单路只命中 1 条、过闸 0 条 → 拒答；改写后命中 23 条、过闸 6 条 → 正确作答）；
学生口语与政策写法不接轨（"评审办法" vs "怎么申请"）。

**闸门分母也随之一并明确**：不能把两路词项取并集——扩展词是同义**替代**（OR），
不是追加要求（AND）。实测并集把某章节的覆盖率从 0.40 稀释到 0.30，掉到 0.35 以下，
等于给 24 条评测集定好的阈值换了个含义。因此覆盖率取**三视图最大值**，并由此得到一条
可断言的性质：**改写只做加法**——不改写能过闸的片段，改写后仍然过闸；不改写能召回的片段，
改写后仍在候选池内（原话单独占一路召回）。两条用例守着这条性质。

**R4 把「点名文件」从查询词变成检索范围**：前端「继续追问」拼出的句子带《文件名》，
而书名号里的年份（2026）在正文里根本不存在——正文只写「本办法」。它占着覆盖率分母却永远命中不了，
于是被点名的那份文件反被自己的年份压到 0.308（阈值 0.35）整份出闸门，
而旧版因为正文印着「（2025年版）」排到第一。降级路径下这就是**问 2026 版、答 2025 版**。
解法是确定性规则（不依赖模型，降级同样生效）：书名号换成核心名（只去掉年份/版本括号）再检索、
范围收窄到被点名的文件、**点名时覆盖率闸门不适用**（主题已由「该文件在库里」回答，
能不能答交给模型自评）。实测同一条追问：改前候选 2 条、首条是 2025 版；
改后 4 条全部来自 2026 版并按章节顺序。

**R5 把「继续追问」从标签造句换成从证据派生**。原来的三条建议是前端用意图标签拼的，
而标签是分类器的输出、不是语料承诺：问「课程考核怎么算平时分」得到
「学分与成绩的申请截止时间和办理流程是什么？」，这句话在任何一份政策里都没有答案。
实测 18 份文件 × 3 条 = 54 条，**9 条必拒答**；补完语料后仍有 2~3 条在批次间漂移，
说明问题不在语料，在"拿标签造句"。改成后端按「刚答的文件 + 它真实存在的章节」派生
（`next_questions`）：第一条借书名号锚定，闸门不适用；只有办法/规定类才问「不符合…会怎么处理」，
指南类改问它真实存在的章节；章节题只挑这轮没引用过的。**52 条建议端到端 52/52 可答**，真实点击巡检 **13/13**（首跑抓到两个只在界面层出现的问题：版本冲突那条建议问的是「以哪版为准」——语料里没有效力判断，改问「两版差别」才答得出；拒答后的 chip 里混着「换一种说法提问」这类提示语，点下去等于把提示语当问题发出去）。

边界：改写是**模型调用**，无 `LLM_API_KEY` 时整段跳过（`model_calls=0`），纯指代追问
（「那它要多久」）仍会拒答——**R4 之后带文件名的追问在降级下已可用，只有纯指代这一半仍缺席**；
向量检索仍未启用，语义空间没有建成。都登记在已知限制里。

### 4.3 引用校验：白名单 + 越界剔除 + 无有效引用则拒答

```
模型输出 → pydantic（extra="forbid"）→ 编号 ∈ [1, N] ？
   ├─ 否 → 剔除，记 citation_warnings
   └─ 是 → 保留
若剔除后一条不剩 → 拒答（4001），不输出"参考了某某文件"这种无源之谈
```

一个实测踩出来的细节：模型有时返回 `"citations": [true]`（把编号写成布尔值），
`field_validator` 里专门滤掉布尔型——`isinstance(True, int)` 在 Python 里是 `True`，
不显式拦就会被当成编号 1。

### 4.4 三态匹配：`unknown` 比 `not_met` 更重要

8 种算子：`>= > <= < == != in not_in`（另有 `manual_review` 独立分流）。

求值结果三态，**`unknown` 有四种原因**，每种都写清是哪一个：

| reason | 场景 | 界面文案 |
| --- | --- | --- |
| `missing_info` | 画像缺这个字段 | "未填写：专业排名百分比" |
| `ambiguous_rule` | 主观条款（"表现突出"） | "条款需人工判断，系统不下结论" |
| `no_value` | 规则缺期望值 | "该条规则未给出可比较的数值" |
| `manual_review` | 显式标记人工复核 | "请咨询学院" |

**把"不知道"和"不符合"混为一谈，是资格类系统最危险的错误**：
学生会因为一个"不符合"放弃本可以申请的机会。所以留空字段必须是 `unknown` 而不是 `not_met`。

### 4.5 计划两阶段：草稿不落库

`POST /plans/draft` 返回任务清单，但**任务表不写**（`tasks_persisted=false`；
plan 壳子按 `draft` 落一行，否则下一步的 `plan_id` 无从引用）。
用户点"确认并写入任务中心"（`POST /plans/{id}/confirm`）才落库，且**幂等**：
重复确认返回 `already_confirmed=true` 与同一个 `plan_id`。

理由：AI 生成的任务可能遗漏或过度解读。让用户先看、先改、再确认，
既尊重用户对个人事务的决定权，也避免系统"替用户承诺"。

### 4.6 一处刻意的留空：日期不猜年份

政策原文写"9 月 10 日前提交"，没给年份。系统**不猜**，`due_at` 留空并提示
"原文给了月日、缺的是年份"。**留空比猜错好**——猜错会导致用户错过真实截止日，
而留空至少让他知道自己要补一个信息。

### 4.7 数据模型：13 张表与三个状态机

| 分组 | 表 | 要点 |
| --- | --- | --- |
| 身份 | `users` | 两角色（student / admin），密码 bcrypt |
| 知识 | `documents`、`document_chunks` | 文档带 `effective_status`（有效/替代/失效）、学年、版本；片段带页码与字符区间 |
| 问答 | `conversations`、`messages`、`qa_feedback` | 反馈**覆盖式**：同一消息重复评价不新增行 |
| 规则 | `policy_rules` | `original_quote` 必须是原文子串；复核态 `pending/approved/rejected` |
| 匹配 | `match_sessions`、`match_result_items` | 会话 + 逐条结果（三态 + 理由 + 证据引用） |
| 执行 | `action_plans`、`tasks` | 任务带 `source_rule_id`/`due_source`/`needs_human_confirmation` 溯源列 |
| 追溯 | `workflow_runs`、`audit_logs` | 六节点轨迹与关键写操作 |

三个状态机都写在 `shared/enums.py` 的**转移白名单**里，非法转移返回 409：

- 计划：`draft → confirmed → archived`；
- 任务：`todo → doing → done`，且 `done` **只能撤回 `todo`**（不能直接回 `doing`）；
- 文档：`effective → superseded → expired`。

**`done → doing` 被拒不是"成功但没效果"**——它返回 409 与业务码 2005。这类"看起来成功、其实没做"
的接口最容易被用户误信，所以宁可显式报错。

### 4.8 界面：为什么"产品化"是一个技术决定而非美化

M7 把界面从"建设进度看板"改成产品界面：删掉里程碑进度卡、阶段说明卡、导航上的 `M3`–`M7` 角标、
页脚的版本/接口数/测试数、登录页的"当前进度"。

理由不是审美：**评审打开系统看到"当前进度 M6 已完成"，会合理怀疑这仍是课程作业而不是可用产品**；
而"能不能交给别人用"正是 M7 的门禁。同时界面要经得起渲染检查——**换了主题最容易出的是「元素在、尺寸对、就是看不见」**：
R10 把深色换成浅底时，18 处用「加白」表达抬升的地方在白底上等于没画，`vue-tsc` 完全查不出，
所以用无头浏览器逐页量**计算出来的亮度**（见 §6.4）。

保留而改写的是**六节点轨迹**：它不是建设日志，而是"这次回答走了哪几步、哪几步没跑、为什么"，
属于可解释性证据。**两者看起来都像状态条，但一个是开发进度，一个是产品能力。**

## 5. 交付形态：从"能演示"到"能交出去"

### 5.1 单进程：一个端口跑完整个系统

有 `frontend/dist` 时，Flask 直接托管静态产物：

```python
@app.get("/")            # → index.html
@app.get("/<path:filename>")
def static_or_spa(filename):
    if filename.startswith("api/"):
        abort(404)       # 关键：/api/* 的 404 必须仍是 JSON
    if (dist / filename).is_file():
        return send_from_directory(dist, filename)
    return send_from_directory(dist, "index.html")   # history 路由回落
```

第二条分支不是洁癖：若 `/api/*` 的 404 被兜底成 `index.html`，前端 `res.json()` 会抛"解析失败"，
把人引向"后端崩了"而不是"路径拼错了"。**一个本该 5 秒定位的错误会变成 5 分钟。**

### 5.2 单文件 exe：零环境依赖

`dist/知校校园政策助手.exe`，**103.0 MB**，内含 Python 运行时 + 前端产物 + 演示文档。
首次运行自动建库（13 张表）、建演示账号、导入 6 份虚构政策并建索引，浏览器自动打开。

**唯一一条能悄悄毁掉交付物的坑**：`--onefile` 每次启动把自身解压到 `%TEMP%\_MEIPASS`，**退出即删**。
数据库路径若按 `Path(__file__).parent.parent` 推导，打包后就落在那个临时目录：

- 开发时（源码运行）这个路径恰好等于项目根 → **一切正常，看不出问题**；
- 打包后 → 用户第一次用正常，关掉窗口再打开，上传的文件、确认的计划**全没了**。

解法是把两个概念拆开：

```python
resource_root()   # 只读：打包后 = sys._MEIPASS（前端产物、demo/）
writable_root()   # 可写：打包后 = exe 所在目录（.env、app.db、uploads/）
```

**验证方式也换了**：不在 `dist/` 里跑 exe（数据会落进 `dist/data/`，把测试痕迹一起发给评审），
整份拷到系统临时目录再跑，跑完比对 `dist/` 前后逐项字节一致。

### 5.3 交付目录

| 文件 | 作用 |
| --- | --- |
| `知校校园政策助手.exe` | 主程序 |
| `启动_知校.bat` / `启动_知校_不打开浏览器.bat` / `查看_访问地址.bat` | 三种启动方式 |
| `重置演示数据.bat` | **改名备份**后重建，不删除旧库 |
| `data/` | 数据库 + 上传件，唯一会被写的目录 |

bat 必须是 **GBK + CRLF**（中文 Windows 的 cmd 按 GBK 解释批处理，写 UTF-8 会乱码）。
`.env` **不复制进 `dist/`**——那是准备发给别人的目录，密钥进去等于泄露。

## 7. 已知局限（精选，完整 37 条见文档）

**不写"没有局限"是这套系统的一部分。** 以下 10 条是评审最可能追问的：

| 编号 | 局限 | 处置 |
| --- | --- | --- |
| A-1 | 规则抽取**会漏条**，漏了就会漏判（漏判表现为"这条要求没出现在结果里"，比误判更难发现） | 抽取一律 `needs_review`，人点过才生效；界面允许逐条回原文核对 |
| A-2 | 版本冲突**漏报"改名"**的版本 | 只认规范化标题，不语义聚类（误报比漏报更伤信任）；如实登记 |
| A-3 | 提示注入只做模式匹配，**改写过的注入挡不住** | 兜底靠引用白名单（编造编号物理不可能） |
| A-4 | `matching`/`planning` 在问答链路**恒为 `skipped`** | 这是设计：它们属于另外两条链路，不许补成已完成 |
| B-2 | 评测集只有 24 条，样本量偏小 | 数字不对外引用 |
| B-3 | 多轮上下文**限 3 轮**、单条截断 240 字 | 防 Prompt 膨胀，超出的不提 |
| B-5 | 计划任务之间**没有自动依赖** | 字段已预留（含成环检测），未做自动推断 |
| C-1 | 上传后**同步解析**，超大 PDF 会让请求变慢 | 4 页 PDF 约 0.3 s；未测大文件 |
| C-10 | exe **103.0 MB，每次启动解压 3–8 s** | 单文件形态的代价，换来"拷一个文件就能用" |
| C-11 | **没有代码签名**，首次运行被 SmartScreen 拦一下 | 个人证书成本 + 赛期不足；如实告知 |

另外三条整体限制：**不支持扫描件 OCR**（无文本层标"疑似扫描件"并提示，不静默失败）、**复杂表格解析不完整**（提示核对原文）、**不接教务系统**（条件由用户手填，系统无法自动核验）。

**R5/R6 修的是「降级说不清原因」**：横幅此前只写「未配置模型密钥」，于是「真的没配 / 配了没读到 / 变量名拼错」三种情况在界面上是同一句话，用户唯一能得出的结论是「系统坏了」。R6 起横幅写出**缺哪个变量、找过哪几条路径**（`/health` 的 `llm_config` 只回状态与路径，不回值）；exe 放在项目内时向上读项目根的 `.env`（上一级须有 `server.py` 才信任），`dist/` 不必再复制一份密钥——**复制是泄露，读取是借用**。

**R7 修的是「登录打不开先别怀疑代码」**：`127.0.0.1 拒绝连接`（`ERR_CONNECTION_REFUSED`）意味着端口上没人听，不是 404、不是白屏。`server.py` 是**前台**进程，不常驻、不开机自启——关掉启动窗口服务就停（见已知限制里的 **B-16**）。所以排查第一步是 `netstat -ano` 看 5000 有没有 `LISTENING`，而不是翻最近的改动：本轮用户先怀疑「前几次修改改坏了」，核查后那两轮只动了 7 个文档，启动脚本与 `server.py` 都是几天前的版本。另一个反直觉的结论——**「命令返回成功」不等于「服务还活着」**：`Start-Process` 会打印 `ok pid=...`，然后进程照样被回收。

**R8 修的是「界面上的字比答案多」**：九条反馈里有四条是"少显示"，四条里有三条最后做成了**折叠**而不是删除——政策原文、引用片段、节点耗时都是该事实的唯一一份，删掉之后"这句话凭什么"在界面上再没有入口。真正删掉的只有两类：说第二遍的话（判定理由旁边那行「你的值 / 政策要求」）和内部术语（规则编号 `R-3`）。正文里的 `[n]` 也一样：它在服务端仍是引用校验的输入（越界剔除、全对不上整条拒答），只是在渲染层剥掉。另一个结论是结构性的——**只要状态是"用户刚填的"，它就不属于组件**：匹配页画像曾放在组件 ref 里，跳到知识库看一眼文件再回来就全空；搬进 Pinia + `sessionStorage` 之后，还必须用**整页刷新**再验一次，因为 SPA 切页验的是内存，不是存储（见 33 条里的 **C-13**）。

**R9 修的是「为了做界面，不得不扩接口」**：这一轮四条需求看着全是皮的活——换主色、落地页与上滑登录小窗、待办自动滚播加气泡光标、管理员数据中心。前三条确实是前端，第四条不是：库里没有"学生画像"和"提问分析"的聚合口径，把统计写在前端等于把整张问答日志拉到浏览器里数。于是新增两个只读端点（`/admin/analytics/portraits`、`/admin/analytics/qa`）加注册链路（`/auth/captcha`、`/auth/register`），接口从 31 涨到 35。**这是本项目第一次因为界面需求而扩接口**，写在这里是因为评审会问"为什么一轮 UI 优化动了后端"，而答案不该只活在提交信息里。

**R10 修的是「换主题不是改色值」**：四条需求（加 logo、整体转亮色、切页加动效、落地页加粒子）听着都像美术活，实际翻车点全在"看不见"上。深色主题把"抬升"写成 `rgba(255,255,255,0.05)`（输入框底、分段控件底、行悬停），这 18 处搬到白底上**等于什么都没画**——元素在、尺寸对、`opacity` 是 1，只是看不见，截图里只像"风格变简约了"。第二处更隐蔽：**主色分工在浅底上正好反过来**，深色里亮的那个当文字（对比度 8.1:1），浅底上同一个色只剩 3.42:1，而铺底反而要比文字更深。对比度是**算**出来的（三版试算脚本 × 三种底，首轮 14 项 8 项不合格，校准后 21 项全部 ≥ 4.5），边框则刻意不套 3:1——那是"必要控件边界"的启发式，装饰性描边硬套只会逼出一圈黑框。验收也随之换了一层判据：不信"元素存在"，只信"画出来了"——logo 查内部图形节点数、浅底查计算亮度、粒子读 canvas 像素并在两帧间比对、过渡用 rAF 连采 430ms 判中间态（点完立刻读 `opacity` 永远是 1，与"动画没写"在数据上无法区分）。

这一轮另有三处只在真机验收里露头的判断：`scrollTop` 每帧只加 0.27 px 会被布局单位舍回去（每秒 60 次调用全"成功"、值恒为 0，看着像浏览器禁了脚本滚动，实际要把余量攒够整像素再写）；`background-clip: text` 在无头 Chromium 下整块掉字（`innerText` 正确、`rect` 236×113，绘制像素为 0，改实色加 `text-shadow` 才出来）；注册时「该学号已注册」必须排在验证码校验**之后**，否则这句话本身就成了免验证码的学号枚举接口——顺序错了功能照样能用，所以专门写了一条测试咬住它。
