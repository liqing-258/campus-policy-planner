## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api/v1` |
| 传输 | JSON（`application/json; charset=utf-8`）；上传为 `multipart/form-data` |
| 鉴权 | `Authorization: Bearer <jwt>`；仅 `/health`、`/auth/login` 免鉴权 |
| 时间 | ISO 8601 UTC 带 `Z`，如 `2026-11-18T09:00:00Z`；纯日期用 `YYYY-MM-DD` |
| 命名 | 请求与响应字段一律 **snake_case**；前端在 `services/` 层做驼峰转换（如需） |
| 空值 | 缺失语义用 `null`，**禁止用空字符串或 `0` 冒充** |
| 未知字段 | 请求体 `extra='forbid'`，出现未声明字段直接 1001 |
| 分页 | 见 §4；默认 20，上限 100 |
| 幂等 | 见 §5 |
| 请求追踪 | 每个响应带 `request_id`；服务端日志同 ID 串联 |

## 2. 统一响应外壳

### 2.1 成功

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "01JCV8Z3QK7M2XP4RB9TYH6N",
  "timestamp": "2026-11-07T09:12:33Z"
}
```

### 2.2 失败

```json
{
  "code": 1001,
  "message": "参数校验失败：title 不能为空",
  "data": null,
  "request_id": "01JCV8Z3QK7M2XP4RB9TYH6N",
  "timestamp": "2026-11-07T09:12:33Z"
}
```

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| code | int | 是 | 0 为成功，非 0 见 §3 |
| message | string | 是 | 可直接展示给用户的中文说明，**不含堆栈** |
| data | object \| array \| null | 是 | 失败时固定 `null` |
| request_id | string(26) | 是 | ULID，用于查日志 |
| timestamp | string | 是 | ISO 8601 |

> **沿用既有项目外壳**（`code/message/data/request_id/timestamp`），便于复用同一套前端请求封装与调试习惯。

## 3. 错误码

### 3.1 分配原则

| 段 | 含义 | HTTP 映射 |
| --- | --- | --- |
| 0 | 成功 | 200 |
| 1xxx | 参数与校验 | 400 / 413 / 415 / 422 |
| 2xxx | 资源与状态 | 404 / 409 |
| 3xxx | 权限 | 401 / 403 |
| **4xxx** | **AI 链路（本项目新增）** | 502 / 504，或 200 + 业务态 |
| 9xxx | 系统 | 500 / 503 |

### 3.2 详细码表

| code | HTTP | 常量名 | 说明 | 典型场景 |
| --- | --- | --- | --- | --- |
| 0 | 200 | `OK` | 成功 | — |
| 1001 | 400 | `INVALID_PARAM` | 参数非法 | 字段缺失、类型错、未知字段 |
| 1002 | 400 | `INVALID_PAGINATION` | 分页参数非法 | `page<1`、`page_size>100` |
| 1003 | 422 | `SCHEMA_INVALID` | 结构校验失败 | 请求体不满足 Schema |
| 1004 | 413 | `FILE_TOO_LARGE` | 文件超限 | > 20MB |
| 1005 | 415 | `FILE_TYPE_UNSUPPORTED` | 类型不支持 | 扩展名或魔数不符 |
| 2001 | 409 | `DOCUMENT_DUPLICATED` | 文档已存在（hash 命中） | 重复上传 |
| 2002 | 404 | `DOCUMENT_NOT_FOUND` | 文档不存在 | 无效 ID / 已删除 |
| 2003 | 404 | `RULE_NOT_FOUND` | 规则不存在 | |
| 2004 | 404 | `PLAN_NOT_FOUND` / `TASK_NOT_FOUND` | 计划/任务不存在 | |
| 2005 | 409 | `STATE_TRANSITION_INVALID` | 状态转移非法 | `done → doing`、重复确认 |
| 2006 | 409 | `DEPENDENCY_CYCLE` | 任务依赖成环 | 确认计划时拓扑排序失败 |
| 2007 | 409 | `PARSE_IN_PROGRESS` | 解析进行中 | 重复触发解析 |
| 3001 | 401 | `UNAUTHENTICATED` | 未登录或令牌过期 | 无 token |
| 3002 | 403 | `FORBIDDEN` | 无权限 | 学生调管理员接口、越权访问他人任务 |
| **4001** | **200** | `INSUFFICIENT_EVIDENCE` | 证据不足（业务态，非错误） | 检索分低于阈值 → 拒答 |
| **4002** | **502** | `LLM_OUTPUT_INVALID` | 模型输出结构非法（重试后仍失败） | 非 JSON、字段缺失 |
| **4003** | **200** | `CITATION_REJECTED` | 引用越界，已剔除（业务态） | 模型编造 chunk_id |
| **4004** | **504** | `LLM_TIMEOUT` | 模型超时 | 超 30s |
| **4005** | **502** | `LLM_UPSTREAM_ERROR` | 上游 5xx / 鉴权失败 | 401、500 |
| **4006** | **200** | `DEGRADED_MODE` | 已降级（业务态） | 无 Key / 仅 BM25 |
| 9001 | 500 | `INTERNAL_ERROR` | 未预期异常 | 未捕获错误 |
| 9002 | 503 | `DB_UNAVAILABLE` | 数据库不可用 | 连接失败 |

### 3.3 为何 4001/4003/4006 返回 HTTP 200

**拒答是产品功能，不是系统故障。** 若返回 4xx，前端会弹错误提示，用户以为"系统坏了"；而实际应渲染为一张正常的回答卡片，标题是"未找到足够依据"。因此这三类用 `code` 表达业务态，HTTP 保持 200。

前端判定规则：`code === 0` → 正常；`code ∈ {4001,4003,4006}` → 正常渲染但带标识；其它非 0 → 错误提示。

## 4. 分页、排序、筛选

### 4.1 请求参数

| 参数 | 类型 | 默认 | 约束 |
| --- | --- | --- | --- |
| page | int | 1 | ≥1 |
| page_size | int | 20 | 1–100 |
| sort | string | 接口自定 | 白名单字段，`-` 前缀表示倒序，如 `-created_at` |
| keyword | string | — | ≤64 字，模糊匹配标题 |

### 4.2 响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "meta": { "page": 1, "page_size": 20, "total": 137, "pages": 7 }
  },
  "request_id": "...",
  "timestamp": "..."
}
```

| 规则 | 说明 |
| --- | --- |
| 筛选先于分页 | 先按全部筛选条件过滤，再计算 `total` |
| `total` 语义 | 过滤后的总条数，不是全表条数 |
| `pages` | `ceil(total / page_size)`，`total=0` 时为 0 |
| 超界 | `page > pages` 返回空 `items`，不报错 |
| 排序白名单 | `sort` 只接受接口声明字段，非法值返回 1001（**防 SQL 注入**） |

## 5. 幂等

| 接口 | 幂等方式 | 重复提交行为 |
| --- | --- | --- |
| `POST /plans/{id}/confirm` | 状态条件更新 `WHERE status='draft'` | 影响行数 0 → 返回当前计划（200，`code=0`），不重复建任务 |
| `POST /tasks/{id}/status` | 校验目标状态是否为当前状态的合法转移 | 同上状态 → 返回 200 现状；非法 → 2005 |
| `POST /documents` | `file_hash` 唯一性检测 | 命中 → 2001 + `data` 返回已有文档 ID |
| `POST /documents/{id}/reparse` | `parse_status='parsing'` 校验 | → 2007 |

> 可选支持 `Idempotency-Key` 头（M6 视工期），MVP 先用上表的自然幂等。

## 6. 请求校验原则

1. **校验在入口一次做全**：路由层用 pydantic 模型 `parse_obj`，失败即 1001/1003，不透传到服务层。
2. **业务校验在服务层**：状态机、依赖环、归属权限，失败返回 2xxx/3xxx。
3. **模型输出校验独立**：`app/schemas.py` 中 `LLMAnswer` / `ExtractedRule` 用于校验模型返回值，与请求模型分开，避免混用。
4. **不做隐式兜底**：缺 `due_at` 就留 `null`，不填 `now()`；缺 `page_number` 就留 `null`，不填 0。
5. **错误信息带字段名**：`"参数校验失败：gpa 必须是数字"`，便于前端定位。

## 7. 鉴权与权限

| 规则 | 说明 |
| --- | --- |
| 令牌 | JWT，`HS256`，载荷 `{sub: user_id, role, exp}`；有效期 720 分钟 |
| 角色守卫 | `@require_role('admin')` 装饰器；`student` 访问 → 3002 |
| 资源归属 | 所有 `GET/PATCH/DELETE` 涉及用户资源的接口，服务层强制 `WHERE user_id = current_user.id`；越权 → 3002（**不用 404 掩盖**，便于测试定位） |
| 文档写操作 | 上传/删除/重建索引仅 `admin`；`student` 只读 |
| 计划与任务 | 仅本人可见可改 |

## 8. 请求追踪与日志

| 项 | 约定 |
| --- | --- |
| `request_id` | 入口生成 ULID，写入 `flask.g`，随响应返回，日志每条带 |
| 访问日志 | `method path status ms request_id user_id` |
| 禁止记录 | 文档正文、用户个人信息原文、API Key、完整 JWT |
| AI 调用日志 | 记录 `run_id`、节点、耗时、token 数、是否降级；**不记录 Prompt 全文**（Prompt 走 `docs/90-AI协作留痕`，不进运行日志） |
