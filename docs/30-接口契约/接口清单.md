## 2. 关键接口入参 / 出参

### 2.1 `GET /health`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ok",
    "version": "0.1.0",
    "db": "ok",
    "llm_mode": "degraded",
    "llm_model": null,
    "embedding_mode": "disabled",
    "chunk_count": 118
  },
  "request_id": "...",
  "timestamp": "..."
}
```

> `llm_mode ∈ {llm, degraded}`；`embedding_mode ∈ {vector, bm25_only, disabled}`。评审一条命令即可看到系统真实能力状态。

### 2.2 `POST /auth/login`

| 入参 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| username | string | 是 | 1–64 |
| password | string | 是 | 1–72 |

出参 `data`：`{ "token": "...", "expires_in": 43200, "user": { "id", "username", "display_name", "role" } }`

### 2.3 `POST /documents`

| 入参（form-data） | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| file | file | 是 | ≤20MB；扩展名 pdf/docx/txt/md；魔数校验 |
| title | string | 否 | 缺省取文件名去扩展名 |
| department | string | 否 | ≤100 |
| published_at | date | 否 | `YYYY-MM-DD` |
| academic_year | string | 否 | 形如 `2026-2027` |
| effective_status | string | 否 | 缺省 `unknown` |

出参 `data`：`{ "id", "title", "parse_status", "chunk_count" }`（上传后异步解析，前端轮询 `GET /documents/{id}`）

### 2.4 `POST /qa/ask`

| 入参 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| question | string | 是 | 2–500 字 |
| conversation_id | string \| null | 否 | 传则续接会话 |
| document_ids | array[string] | 否 | 限定检索范围 |
| top_k | int | 否 | 1–12，缺省 6 |
| include_trace | bool | 否 | 缺省 true |

出参见设计说明书 §6.3（含 `answer`、`citations`、`workflow`、`mode`、`suggestions`）。

**三条硬约束**（写入测试用例）：

1. `citations[].chunk_id` 必须属于本次检索结果，否则该条被剔除并记 `4003`；
2. 拒答时 `citations` 必须为空数组，`answer.direct_answer` 含"未找到足够依据"；
3. 降级时 `mode != "llm"`，前端必须显示降级标识。

### 2.5 `POST /matches`

| 入参 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| document_id | string | 是 | |
| profile | object | 是 | 键必须在 `field_key` 白名单内；`extra='forbid'` |

出参 `data`：`{ "session_id", "summary": {met,not_met,unknown,total}, "items": [...], "disclaimer" }`

`items[]` 字段：`rule_id`、`rule_code`、`description`、`status`、`unknown_reason`、`user_value`、`expected_value`、`rationale`、`evidence{chunk_id,page,quote}`。

### 2.6 `POST /plans/draft` → `POST /plans/{id}/confirm`

`draft` 入参：`{ "match_session_id": "...", "document_id": "..." }`，出参返回**未落库**的草稿（含临时 ID `T1..Tn`）。

`confirm` 入参：

```json
{
  "action_plan_id": "01JCV...P1",
  "tasks": [
    { "temp_id": "T1", "title": "下载并填写申请表", "priority": "P0", "due_at": null, "dependency_ids": [] },
    { "temp_id": "T2", "title": "到教务办开具成绩单", "priority": "P1", "due_at": "2026-09-25T09:00:00Z", "dependency_ids": ["T1"] }
  ]
}
```

校验：`tasks` 非空且 ≤50；`title` 1–100；`due_at` 若存在须晚于当前时间；`dependency_ids` 均存在于本次 `temp_id` 集合；依赖无环；`priority ∈ {P0,P1,P2,P3}`。

### 2.7 `POST /tasks/{id}/status`

| 入参 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| status | string | 是 | todo/doing/done/deferred/cancelled |

非法转移 → `2005`，`message` 形如：`当前状态 done 不允许转移到 doing（允许：todo）`。
